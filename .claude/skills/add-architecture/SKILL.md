# 구조 더하기 (모델 세션)

기준 문서는 [문서/개발.md 의 '구조 더하기'](../../../문서/개발.md#구조-더하기). 여기는 그 차례를 따라 할 때의 확인 목록이다.

## 시작 전

- 작업 트리 하나 · 가지 하나(`models/<구조>-<단계>`). 고치는 파일은 그 구조의 것(`구조/<이름>/` · `커널/생성<이름>.gl` · `시험/…<이름>…`)과
  [구조/등록.gl](../../../구조/등록.gl) 의 두 줄. 공유 코어(엔진/엔진.gl · 엔진K.gl · 가중치.gl · 서버몸.gl · 앱 · 커널생성.gl 의 공통 부분)를
  바꿔야 하면 멈추고 통합 작업에 청한다 — 무엇을 · 왜 · 어떤 시험으로.
- llama.cpp 의 같은 구조(src/models/<구조>.cpp · llama-arch.cpp)를 먼저 읽고, 블록 레시피를 [문서/블록조합.md](../../../문서/블록조합.md) 꼴로 적는다.

## 단계(단계마다 PR 하나)

1. **계약 · CPU 참조**(GPU 없이): 계약의 절, `계약/정수계약.py` 의 함수, `시험/참조<이름>.py`, fp64 수학 참조, `시험/계약자체.py` 의 시험.
2. **커널**: `커널/생성<이름>.gl` + 커널생성.gl 의 모드 · 포함 · 거부 몇 줄. 판마다 CPU 참조와 비트까지(`시험/<이름>판.py`).
   모듈 해시 줄 — `python -X utf8 시험/빠른점검.py --해시갱신`(바꾸지 않은 모듈의 해시는 그대로여야 한다), SASS 넘침 줄 — `시험/SASS_WSL.py`.
3. **엔진**: `구조/<이름>/엔진.gl` 에 `[<이름>구조들등록]` — `기본구조표("<이름>")` 에서 시작해 다른 칸만 바꾼다(칸의 뜻은
   [엔진/구조표.gl](../../../엔진/구조표.gl)). 보기: [구조/qwen35/엔진.gl](../../../구조/qwen35/엔진.gl). 처음에는 좁게 — `생성그래프` · `표판` ·
   `추측` · `슬롯복사` · `저장소` · `나누기` 는 거짓, `정밀만` 참, `벌칸까닭` 을 적는다.
4. **검증**: 층을 줄인 파일(`시험/작은MoE.py` 꼴)로 `엔진/시험_7B` 의 다섯 길과 CPU 참조 비트 → 실제 파일 하나로 `재기/모델검증.py` →
   `시험/구조회귀.py` 에 경우 하나. 엔진 · 앱의 확인: `서버 --모델확인 <gguf>` 가 그 구조를 받고 모듈 이름 · 생성기 인자를 낸다.
5. **문서**: `문서/바뀐것.d/<가지>.md` 조각, 단계 기록은 `구조/<이름>/기록.md`. 사용자 문서는 고치지 않는다(릴리스 때 통합).

## GPU

- GPU 를 쓰는 명령은 모두 `python -I -X utf8 시험/GPU줄.py 실행 --이름 "<가지> — <할 일>" -- <명령>`. 기다리는 동안 GPU 가 들지 않는 일을.
- 큰 파일 · 긴 실행은 층을 줄인 파일로. 바뀌지 않은 코드를 다시 돌리지 않는다.

## 끝

- 빠른 점검(`python -X utf8 시험/빠른점검.py --글 ../geul-lang-v2`)이 모두 통과, PR → CI(`check` · `linux`) 통과 → 스쿼시 병합.
