# 가중치에 둔 기억 색인: 첫 시험의 근거

초안 1 · 2026-11-13 · 우성현 (Sunghyeun Woo)

Zenodo 보관: [10.5281/zenodo.24184984](https://doi.org/10.5281/zenodo.24184984) (초안 1) · 모든 판 [10.5281/zenodo.24184983](https://doi.org/10.5281/zenodo.24184983)

영어 원문: [evidence.md](evidence.md) · 제안: [proposal.ko.md](proposal.ko.md)

이 글은 첫 시험이 무엇을 쟀는지, 그 수가 무엇을 뒷받침하고 무엇을 뒷받침하지 않는지를 적는다.

## 1. 주장

기억 색인을 읽지 않은 모델도, 색인을 알맞은 방식으로 어댑터에 학습시키면, 요청에 필요한 기억을 고를 수 있다. 기억을 언급하지 않는 요청에서도 그렇다. 작은 모델에서는 같은 모델이 색인을 문맥에서 읽는 것보다 잘 고른다.

이 주장은 기억 200개를 한 번 학습시킨 것, 4B 모델 하나, 지어낸 자료에 한정된다.

## 2. 과제

- **기억.** 프로젝트 넷을 가진 가상의 1인 개발자의 지어낸 기억 200개. 작업 규칙 · 프로젝트 사실 · 참고 · 사용자 정보가 50개씩이다. 기억마다 식별자, 한 줄짜리 색인 항목, 80 ~ 200 낱말의 파일이 있다.
- **기억 칸.** 모델은 답하기 전에 기억 칸에 식별자 200개 가운데 하나나 "없음"을 적는다. 채점은 칸 자리에서 이 201개에 대한 모델의 점수를 읽어서 한다. 글을 생성하지 않는다. 우연이면 0.5 % 다.
- **예.** 기억: "테스트와 모델은 SSD 에서만 돌린다. HDD 는 보관용이다." 요청: "느리고 큰 디스크에 있는 사본으로 벤치마크를 시작해 줘." 맞는 출력: 그 기억의 식별자.

## 3. 무엇을 견주었나

가중치에 학습시킨 것(Qwen3.5-4B 에 LoRA 랭크 16, 방식마다 씨앗 셋, 글의 수와 설정은 같다):

- **상황으로** — 그 기억이 필요해질 요청 → 식별자
- **설명으로** — 색인 항목과 그것을 바꿔 쓴 문장 → 식별자
- **질문으로** — 기억을 직접 묻는 질문 → 식별자

같은 요청으로 잰 견줄 상대:

- **색인을 문맥에** — 고치지 않은 4B 모델의 시스템 프롬프트에 200줄 색인을 넣고 같은 칸을 채우게 한다.
- **검색** — 요청과 기억 파일 · 색인 항목 · 같은 학습 상황 글 사이의 임베딩 유사도(Qwen3-Embedding-0.6B), 그리고 BM25.
- **본체 고정** — 모델은 건드리지 않고 작은 고르는 층만 학습한다.

학습 글(기억마다 종류별 20개, 그리고 기억이 필요 없는 요청 4,600개)은 공개 27B 모델이 기억의 제목 · 색인 항목 · 파일만 보고 썼다. 시험 요청은 다른 회사의 비공개 모델이 따로 썼다. 이 모델은 "이 기억이 필요해지는 때"를 적은 한 문장을 보고 썼고, 그 문장은 학습시킨 모델도 학습 글을 쓴 모델도 보지 못했다.

## 4. 주된 결과

기억의 글과 겹치는 특징적인 낱말이 없는 요청이다. 정답을 모르는 확인자가 색인을 보고 의도한 기억 하나만 고른 요청만 셌다(600개 가운데 411개). 구간은 기억 단위로 다시 뽑은 붓스트랩 95 % 구간이다.

| 방식 | 정답률 | 95 % 구간 |
|---|---|---|
| **색인을 가중치에, 상황으로 가르침** | **74.0 %** | 69.6 ~ 78.2 |
| 색인을 문맥에 (같은 4B 모델) | 43.3 % | 37.5 ~ 49.0 |
| 본체 고정, 고르는 층만 | 38.7 % | 33.0 ~ 44.5 |
| 기억 파일에 대한 검색 | 37.7 % | 32.1 ~ 43.5 |
| 학습 상황 글에 대한 검색 | 34.8 % | 29.9 ~ 39.6 |
| 색인 항목에 대한 검색 | 24.3 % | 18.9 ~ 30.1 |
| BM25 | 23.8 % | 19.7 ~ 28.1 |
| 색인을 가중치에, 설명으로 가르침 | 15.9 % | 12.8 ~ 19.3 |
| 색인을 가중치에, 질문으로 가르침 | 13.5 % | 10.5 ~ 16.7 |

600개 전체로 내도 순서가 같고(상황 / 문맥 / 설명이 68.2 % / 37.0 % / 13.8 %), 아래 판정이 모두 그대로다.

## 5. 미리 정한 기준에 따른 판정

| 물음 | 기준 | 값 | 판정 |
|---|---|---|---|
| 아이디어가 서는가 | 상황 ≥ 문맥의 0.9배, 그리고 ≥ 60 % | 74.0 대 43.3 | 선다 |
| 가르치는 방식이 가르는가 | (상황 − 설명)의 구간 아래 끝 ≥ 30 %p | +58.1 (53.3 ~ 62.9) | 가른다 |
| 같은 재료의 검색보다 나은가 | (상황 − 학습 상황 글 검색)의 구간이 0 위 | +39.2 (33.5 ~ 44.9) | 낫다 |
| 잘못 꺼내지 않는가 | 기억이 필요 없는 요청에서 문맥보다 5 %p 넘게 높지 않음 | 0.0 % 대 39.8 % | 괜찮다 |
| 다른 능력을 지켰는가 | 무관한 글의 손실 변화: +0.02 nat 이하면 지킴, +0.05 nat 초과면 깎임 | +0.067 nat | **깎였다** |

마지막 줄은 내가 정한 기준을 넘지 못한 것이다. 어댑터를 켜면 위키백과 글 189토막(영어와 한국어)의 토큰당 손실이 2.248 에서 2.315 nat 로, 약 3 % 올랐다.

## 6. 더 잰 것

등록한 시험 뒤에 더한 것이고 판정에 쓰지 않았다.

**요청의 종류 사이에서 옮겨 가는 정도.** 가르친 것이 나온다.

| 가르친 방식 | 설명 | 질문 | 기억과 낱말이 겹치는 요청 | 겹치지 않는 요청 |
|---|---|---|---|---|
| 설명으로 | 94.2 % | 57.4 % | 37.9 % | 15.9 % |
| 질문으로 | 79.5 % | 88.4 % | 37.0 % | 13.5 % |
| 상황으로 | 61.0 % | 57.8 % | 85.6 % | 74.0 % |
| (색인을 문맥에) | 93.0 % | 71.5 % | 62.7 % | 43.3 % |

상황으로 가르친 모델은 직접 물을 때 문맥 방식보다 약하다. 세 종류를 함께 가르치는 것은 재지 않았다.

**더 큰 모델이 같은 색인을 읽으면.** Qwen3.8-27B(4비트), 같은 프롬프트 · 같은 색인 · 같은 요청.

| | 학습시킨 4B | 읽는 27B | 읽는 4B |
|---|---|---|---|
| 기억과 겹치는 특징적인 낱말이 없는 요청 (411) | 74.0 % | 78.1 % | 43.3 % |
| 같은 요청, 600개 전체 | 68.2 % | 68.2 % | 37.0 % |
| 직접 묻는 질문 (400) | 57.8 % | 85.8 % | 71.5 % |
| 기억이 필요 없는 요청에서 기억을 꺼냄 (284) | 0.0 % | 27.1 % | 39.8 % |

묻지 않은 요청에서 학습시킨 4B 와 읽는 27B 의 차이는 구간이 0 을 품는다(411개에서 −4.1 %p, −9.6 ~ +1.3. 600개에서 0.0, −4.5 ~ +4.5). 411개는 색인을 읽는 확인자가 거른 것이라 읽는 쪽으로 기운다. 600개의 값이 덜 기운 값이다. 27B 모델은 학습 글을 쓴 모델이기도 하다. 다만 시험 요청은 본 적이 없다.

**더 작은 어댑터.** 랭크를 16 에서 4 로 낮추고 씨앗 셋으로 재면 정답률 74.9 %, 손실 변화 +0.034 nat(약 1.5 %)다. 정확도를 잃지 않고 값이 절반이 됐다. 0.02 기준 아래로 확실히 내려가지는 않았다. 이 설정들은 같은 시험 요청으로 견주었으므로, 새 요청으로 다시 재야 확정된다.

**무관한 긴 대화 뒤**(요청 앞에 낱말 1,100 ~ 1,330개): "없음"을 빼고 고르면 학습시킨 모델은 74.0 % 에서 71.7 % 가 됐다. "없음"도 고를 수 있게 하면 "없음"이라고 답하는 일이 늘었다(정답률 65.3 % → 53.6 %).

**끝까지.** 요청 100개에서, 고른 기억 파일을 문맥에 넣고 고치지 않은 4B 모델이 답을 썼다. 조건을 모르는 판정자가 답이 기억을 따랐다고 본 것은, 학습시킨 모델이 고른 기억을 넣었을 때 39개, 문맥 방식이 고른 기억일 때 28개, 정답 기억일 때 69개, 기억 없이 4개였다.

## 7. 이 수가 뒷받침하는 것

- 상황으로 학습시킨 색인은, 다른 글쓴이가 쓴 새 요청에서 묻지 않아도 떠오른다(74.0 %). 학습 글과 가장 덜 닮은 요청에서도 그렇다(유사도가 가장 낮은 구간에서 57.9 %. 문맥 방식은 31.6 %, 같은 학습 글에 대한 검색은 1.8 %).
- 가르치는 방향이 결과를 가른다. 같은 색인을 설명이나 질문으로 가르치면 물을 때 나오고 필요할 때는 나오지 않는다.
- 학습시킨 모델은 기억이 필요 없는 요청에서 꺼내지 않는다(씨앗 셋에서 852번 가운데 0번).
- 4B 모델에서, 학습시킨 색인은 묻지 않은 회상을 색인을 읽는 고치지 않은 27B 모델과 비슷한 수준으로 올린다.

## 8. 뒷받침하지 않는 것

- 이 방법이 색인을 읽는 큰 모델보다 낫다는 것. 낫지 않았고, 그것이 목적도 아니었다.
- 기억 수천 개에서, 또는 기억이 날마다 바뀔 때 된다는 것.
- 어댑터에 값이 없다는 것. 등록한 측정은 값의 한도를 넘었다.
- 따로 학습시킨 검색기보다 낫다는 것. 그 상대는 돌리지 않았다. 검색에 쓴 임베딩 모델은 작고(0.6B) 이 자료로 학습시키지 않았다.
- 실제 사용자의 기억, 다른 언어, 다른 모델 계열에 대한 것 전부.

## 9. 확인한 것

- 시험 요청마다 같은 기억의 학습 상황 글 가운데 가장 닮은 것과의 유사도: 가운데 값 0.63, 최고 0.85. 거의 같은 문장은 없었다.
- 묻지 않은 요청 50개를 무작위로 뽑아 직접 읽었다. 50개 모두 그 기억이 실제로 필요했다.
- 정답을 가린 확인자 둘이 "기억 하나만 필요하다"는 판정에서 100문항의 91 % 가 일치했다(카파 0.72).
- 모든 학습이 자기 학습 글을 100 % 맞혔다.
- 같은 모델을 두 번 채점하니 2,700문항 모두 같은 것을 골랐다.

## 10. 기록

- 가설과 기준은 2026-11-12 에, 어떤 실행보다 먼저 적었다. 계획 · 자료 · 스크립트의 해시는 2026-11-13 02:38 에, 본 측정 전에 로컬 파일에 적었다. 그 기록은 로컬에만 있었고 공개된 것이 아니다. 실행하며 바꾼 것은 계획에 시각과 함께 적었고, 저마다 해당 결과를 보기 전에 적었다.
- 계산 자원: 협력 연구 그룹이 제공한 H100 한 장(47 GB 구역)에서 약 5시간 40분.
- 자료 · 스크립트 · 문항별 채점은 초안 1 에 없다. 이 기록의 다음 판에 더한다.

## 11. AI 를 어떻게 썼나

AI 코딩 에이전트가 저자의 지시에 따라 스크립트를 쓰고, 측정을 돌리고, 이 글의 초안을 썼다. 실험 안에서 언어 모델이 맡은 구실은 이렇다. 공개 27B 모델이 학습 글을 썼다. 다른 회사의 비공개 모델이 기억과 시험 요청을 썼고, 시험 문항을 정답을 가린 채 확인하는 일과 생성된 답을 조건을 가린 채 판정하는 일을 맡았다. 시험 대상 모델은 공개 가중치 모델이다(Qwen3.5-4B, Qwen3.8-27B).
