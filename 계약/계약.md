# 계약 — 무엇을, 어디서만 잃는가

GeulPU 의 모든 계산은 정밀도를 소스에 적는다. GPU 가 고를 재량(반올림 방식 · 더하는 차례 · 근사 명령)을 남기지 않으니, 같은 계약이면
GPU 의 결과가 CPU 참조 구현([계약/정수계약.py](정수계약.py))과 비트까지 같고, 어느 길(한 번에 · 나눠서 · 하나씩 · 대화 ·
배치 · 메가커널)로 계산해도 같다. 손실은 아래에 적힌 곳에서만 생긴다.

## 0. PTX 계약 — 컴파일러의 약속

- 짧은실수 덧셈 · 뺄셈 · 곱셈은 반올림을 적어 낸다(`.rn`). 드라이버가 곱과 합을 FMA 로 합치지 못한다 — 합침은 소스가
  `곱해더하기` 로 적을 때만.
- 근사 명령(`ex2.approx` 등)을 쓰지 않는다. 지수 함수는 적어 둔 다항식(아래 적힌지수).
- **짧은실수 규칙 R — 비정규수 버림** (31단계 — [31단계](https://github.com/wwoosshh/GeulPU/blob/main/문서/31단계.md)). 아래의 짧은실수 연산(곱 · 덧셈 · 뺄셈 · 곱해더하기 · 나눗셈 ·
  제곱근 — "IEEE 반올림"이라 적은 곳 모두)은 이 규칙을 따른다.
  - 비정규수(크기가 0 보다 크고 2⁻¹²⁶ 보다 작은 수) 입력은 부호를 지킨 0 으로 읽는다.
  - 결과는 가수 24 비트로 반올림한다(지수 제한 없이 — 가까운 쪽, 같으면 짝수). 그 크기가 2⁻¹²⁶ 보다 작으면 부호를 지킨 0 으로 한다.
  - 곱해더하기는 곱을 반올림하지 않는다.

  모듈의 소스가 `(* 비정규수버림 *)` 으로 밝히고, PTX 백엔드가 짧은실수 연산마다 `.ftz` 를 붙인다. 소스가 밝힐 때만 붙이므로
  PTX 계약 P2 를 지킨다. 경계값까지 모두 이 규칙인 것을 확인한 길은 셋이다.
  - NVIDIA 의 Vulkan: 비정규수를 지키지 못한다.
  - Intel 의 Vulkan: 기본 모드와 버림 모드.
  - PTX `.ftz`

  그래서 CUDA 와 Vulkan 이 같은 비트를 낼 수 있다. 실제 모델의 출력은 바꾸기 전과 같다(31단계의 확인).
- 실수 → 정수 변환이 범위를 넘으면 모듈의 오류 칸에 표시한다(조용한 값이 없다). 시험은 오류 칸 0 을 본다.

## 1. 정수 블록 계약 — 선형 층(자리 둘)

가중치는 모델 파일의 Q8_0 · Q4_0 정수와 블록 척도(반실수) 그대로(k-양자화는 1.1). 활성값 x 는 32 칸 블록마다:

1. E = ⌊log₂ max_k |x_k|⌋, [−98, 100] 으로 자른다.
2. n_k = 가까운정수(x_k · 2^(13 − E)), |n| ≤ 2¹⁴ — 균형 256진 두 자리 D₀ ∈ [−128, 127], D₁ ∈ [−64, 64].
3. S_j = Σ_k D_j,k · q_k,n — 정수 텐서 코어(프롬프트) · dp4a(생성)의 **정확한** 정수 합(순서와 상관없다).
4. v_j = S_j · 2^(8j + E − 13) (정확), u = v₁ + v₀, y ← 곱해더하기(u, d_b,n, y) 를 블록 b 오름차순으로, 출력 = y + 치우침.

활성값의 눈금은 블록 최댓값의 2⁻¹⁴ — llama.cpp 가 활성값을 8 비트(2⁻⁷)로 다시 양자화하는 것보다 128배 촘촘하다. (자리 넷 —
2⁻²⁹ 눈금 — 도 계약으로 남아 있다.)

### 1.1 k-양자화 (26단계, [26단계](https://github.com/wwoosshh/GeulPU/blob/main/문서/26단계.md))

가중치는 파일의 정수와 척도 그대로. 활성값은 위와 같은 32 칸 블록과 자리 둘(n = 256·D₁ + D₀).

- **Q4_K · Q5_K** (슈퍼블록 256 = 32 칸 아래블록 여덟, 반실수 d · m, 아래블록마다 6비트 s_j · t_j — llama.cpp 의 get_scale_min_k4 와 같은 풀기,
  q ∈ [0, 15] · [0, 31]): a_j = d · s_j, b_j = m · t_j (둘 다 짧은실수로 정확). 활성값 블록 j(= 아래블록 j)마다 S_j = Σ_k n_k · q_k,
  T_j = Σ_k n_k (정확한 정수 — |S| < 2²⁴), u_j = S_j · 2^(E−13), w_j = T_j · 2^(E−13) (정확). j 오름차순으로 사슬 하나:
  **y ← 곱해더하기(u_j, a_j, y), y ← 곱해더하기(−w_j, b_j, y)**, 출력 = y + 치우침.
- **Q6_K** (슈퍼블록 256 = 16 칸 아래블록 열여섯, 반실수 d, 아래블록마다 부호 있는 8비트 s_k, q ∈ [0, 63]): a_k = d · s_k (정확). 아래블록
  k 마다 S_k = Σ n · (q − 32) (16 칸, 정확 — |S| ≤ 2²³), u = S_k · 2^(E−13), **y ← 곱해더하기(u, a_k, y)** 를 k 오름차순으로.
- **임베딩**(어휘가 k-양자화일 때): Q4_K · Q5_K 는 a_j · q − b_j (곱은 정확, 뺄셈에서 반올림 하나), Q6_K 는 a_k · (q − 32) (정확).
- 행렬마다 형식이 다를 수 있다(Q4_K_M 은 Q4_K 와 Q6_K 를 섞는다). Q8_0 · Q4_0 만의 모델은 위 1 ~ 4 의 식 그대로. CPU 참조는
  `계약/정수계약.py` 의 풀기K · 행렬곱K · 행렬곱K블라스 · 임베딩K.

커널 변형이 이 값에 이르는 방법은 비트가 같으면 자유다. 27단계부터:

- Q4_0 · Q4_K 의 타일 커널 변형은 u 를 **매직 넘버 누산(magic-number accumulation)**으로 얻는다. M = 1.5 · 2²³ · 2^(E−13) (비트는 블록의 정보에 이미 있다). 자리 1 의
  정수텐서곱 합 s₁ 로 C = 256·s₁ + 비트(M) (Q4_K 는 비트(M) − 8T)를 만들어 자리 0 의 정수텐서곱의 누산 시작값으로 준다. 결과의 비트를
  실수로 읽으면 M + S·2^(E−13) (Q4_K 는 M + (S − 8T)·2^(E−13)) — |S| ≤ 2²² (Q4_0) · |S − 8T| ≤ 2²² (Q4_K) 라 M 의 지수 구간 안에 있어
  정확하다 — 이고, M (Q4_K 는 M − 8T·2^(E−13))을 빼면 u 가 정확히 나온다. 칸마다의 정수→실수 · 척도 곱이 없어진다. Q8_0 · Q5_K · Q6_K 는
  합이 2²² 를 넘을 수 있어 이 길을 쓰지 않는다.
- Q6_K 의 타일 커널 변형은 16 칸 아래블록마다 m16n8k16 정수텐서곱 하나 — B = 4(q − 32), 척도 a/4: S′ = 4S, 곱해더하기(4u, a/4, y) =
  곱해더하기(u, a, y) 가 비트까지 같다.

어느 것도 출력의 비트 하나 바꾸지 않는다 — 27단계의 시험이 같은 CPU 참조와 맞대 본다.

### 1.2 빠른 계약 F1 — 선형층의 활성값 한 자리 (GeulPUv2 2단계, [문서/2단계.md](../문서/2단계.md))

빠른 모드의 모듈(`커널생성 … --빠른`)은 선형층(타일 커널 변형 · 줄 커널 변형 · 줄 타일 커널 변형 · 로짓 커널 변형, 그리고 그 입력을 내는 변환 · RMSNorm · SwiGLU ·
어텐션 병합의 에필로그)의 활성값을 **자리 하나**로 둔다. 어텐션(RoPE 의 q · KV 캐시 · 어텐션 안의 e)은 2 절 그대로 자리 둘이다.

1. E = ⌊log₂ max_k |x_k|⌋ 이고, **max · 2^(6 − E) < 127.5 이면 E ← E − 1** (실수의 비트로: 가수 23 비트 < 0x7F0000). 그다음 [−98, 100] 으로 자른다.
2. n_k = 가까운정수(x_k · 2^(5 − E)), |n| ≤ 127 — 자리 하나(D₀ = n). 블록 최댓값은 64 ~ 127 에 놓인다.
3. S = Σ_k n_k · q_k,n (정확한 정수 합 — 모든 형식에서 |S| < 2²²), u = S · 2^(E − 5) (정확), 그다음은 1 · 1.1 절의 식 · 차례 그대로
   (Q4_K · Q5_K 의 w = T · 2^(E − 5)).

- 정의역: 블록 최댓값 |x| < 2¹⁰¹ (그 위에서는 |n| 이 127 을 넘는다 — 자리 둘도 2¹⁰¹ 위에서 같은 성질이고, 실제 활성값은 닿지 않는다).
- 눈금은 블록 최댓값 / 127(llama.cpp 의 8 비트 활성값)의 (0.996, 1.992] 배 — 오차 분산으로는 약 2.15 배. 정밀 모드(자리 둘)의 눈금은 그 1/128 ~ 1/256.
- 결정성 · CPU 참조와의 비트 같음 · 길 불변은 그대로다(정수 합의 정확함과 정해진 차례). CPU 참조는 `정수계약.자리로 · 행렬곱블라스 · 행렬곱K ·
  행렬곱K블라스` 의 `자리수=1`.
- 커널 변형이 값에 닿는 방법: 한 자리에서는 모든 형식이 |S| < 2²² 라, 위의 매직 넘버 누산을 Q8_0 · Q5_K(Q4_K 와 같이 8 로 가운데 맞춤 — |S − 8T| ≤
  32·127·23) · Q6_K(반쪽마다 — |4S| ≤ 16·127·128)에도 쓴다. 출력의 비트는 그대로다(커널 변형 시험이 CPU 참조와 비교한다).

## 2. 정수 KV 계약 — 어텐션

c_attn 의 q · k · v 를 1 과 같은 문장(d 32 칸 블록, 자리 둘 + 지수 바이트)으로 바꿔 키 · 값을 캐시에 둔다. 질의 하나(위치 p)의
어텐션은 키 조각(위치 64 개)마다:

1. 점수 s_t = 0.125 × Σ_b (u_b,t × 2^(E_q,b − 13)) × 2^(E_k,t,b − 13) — u_b,t 는 자리 짝 넷의 정확한 정수 합(2¹⁶S₁₁ + 2⁸(S₁₀ + S₀₁) +
   S₀₀)을 짧은실수로 반올림 하나. 가린 키(t > p)는 −3 × 10³⁸.
2. m = max s_t, e_t = 적힌지수(s_t − m). **적힌지수**(x): n = 가까운정수(x · log₂e), r = x − n·C₁ − n·C₂(곱해더하기 둘),
   p = 1 + r + r²·(c₀ + r·(c₁ + … + r·c₅))(Cephes expf 계수, 곱해더하기 사슬), 결과 = p · 2ⁿ, x < −87.3 이면 0 — 모든 연산이 IEEE
   짧은실수라 CPU 가 같은 비트를 낸다.
3. l = 짧은실수(Σ_t 가까운정수(e_t · 2²³)) × 2⁻²³ — 정수로 정확히 더한 뒤 반올림 하나.
4. o_d: 값의 블록마다 e′_t = e_t × 2^(E_v − 13) 를 키 32 개 블록 j 마다 자리 둘로, u_j,d = 짧은실수(Σ_t n_e,t · n_v,t,d) (정확한 합,
   반올림 하나), o_d = u₀,d × 2^(E_e,0 − 13) + u₁,d × 2^(E_e,1 − 13) (반올림 하나).
5. 병합 — 3 절. 출력 O / L 은 c_proj 의 자리 둘로 바로.

정수 합은 순서와 상관없으니 프롬프트(텐서 코어 mma)와 생성(dp4a)이 같은 비트를 내는 것이 계약에서 바로 나온다.

### 2.1 빠른 KV 계약 F1A′ — 8비트 KV (GeulPUv2 ③b-2, [문서/긴문맥.md](../문서/긴문맥.md))

빠른 모드에서 'KV 캐시 8비트' 설정을 켜면 키 · 값을 8비트 정수와 fp32 스케일(scale)로 캐시에 두고, 어텐션이 그 정수를 그대로 곱한다.
q 와 e′ 의 16비트 형식(8비트 자리 둘), 최댓값 m · e_t · 합 l, 두 층 병합(3 절)은 2 절 그대로다.

1. 저장: 헤드 차원의 블록(값 32 개)마다 s = max|x| / 127(fp32 나눗셈, 반올림 하나). s > 0 이면 n 은 fp32 몫 x / s(반올림 하나)에 가장
   가까운 정수(같으면 짝수)이고 |n| ≤ 127, s = 0 이면 n = 0. 캐시에는 n(int8)과 s(fp32)를 둔다.
2. 점수: 블록 b 마다 u_b,t = fp32(Σ n_q · n_k) — q 의 16비트 형식 정수 n_q = 256·D₁ + D₀ 와 키의 n 을 곱한 32 개의 정확한 정수 합
   (|합| < 2²⁶)을 fp32 로 바꾼 값(반올림 하나). a_b,t = u_b,t × 2^(E_q,b − 13)(2의 거듭제곱 곱)으로 z ← a_0,t × s_k,t,0, 그다음 b = 1, 2, …
   차례로 z ← fma(a_b,t, s_k,t,b, z), s_t = z × c(c 는 헤드 크기 64 에서 0.125, 128 에서 4 절의 c). 마스킹된 키(t > p)는 −3 × 10³⁸.
3. 출력 o_d(d 는 값의 블록 b 안): e′_t = e_t × s_v,t,b(반올림 하나)를 키 32 개 블록 j 마다 2 절 4 처럼 16비트 형식(정수 n_e,t, 지수
   E_e,j)으로 바꾸고, u_j,d = fp32(Σ_t n_e,t · n_v,t,d)(정확한 정수 합 — |합| < 2²⁶, 반올림 하나), o_d = u₀,d × 2^(E_e,0 − 13) +
   u₁,d × 2^(E_e,1 − 13)(반올림 하나).

fp32 연산은 모두 규칙 R 을 따른다. 2 절과 다른 것은 키 · 값의 2의 거듭제곱 인수 2^(E − 13) 자리에 fp32 스케일 s 가 오는 것뿐이고 계산
순서는 같다. 키 · 값이 한 자리라 텐서 코어 행렬곱은 자리 쌍 넷에서 둘이 된다. 스케일이 2의 거듭제곱이고 값의 크기가 보통이면 ③b-1 의
에뮬레이션(역양자화한 값 n · s 를 16비트 형식으로)과 비트까지 같다. 다른 곳은 아주 작은 값뿐이다 — 0 인 블록은 s = 0 이라 기여가 정확히
0 이지만 16비트 형식은 지수 −98 의 값으로 남기고, 16비트 형식의 지수는 −98 아래로 내려가지 않는다. [시험/계약자체.py](../시험/계약자체.py)가
저장, 에뮬레이션과의 일치, 이 절의 문장을 행 하나씩 옮긴 계산을 확인한다.

### 2.2 빠른 어텐션 계약 F2 (GeulPUv2, [문서/빠른어텐션.md](../문서/빠른어텐션.md))

빠른 모드에서 KV 캐시 설정의 '8비트 · 빠른 어텐션'(커널생성 `--빠른 --F2` — 헤드 크기 128). 키는 2.1 그대로(int8 + 값 32 개마다 fp32
스케일)이고, 다른 것은 q 와 값의 스케일, 점수와 지수 함수의 단위, 가중합의 확률이다.

1. **q**: 16비트 형식(8비트 자리 둘)이고 지수 E_q 는 헤드(값 128 개)마다 하나 — E_q = ⌊log₂ max_d |q_d|⌋([−98, 100] 로 자르고, 최댓값이
   0 이면 −98), n_q,d = 가까운정수(q_d · 2^(13 − E_q)).
2. **값**: int8 과 헤드(값 128 개)마다의 fp32 스케일 — s_v = max_d |v_d| / 127(fp32 나눗셈, 반올림 하나), s_v > 0 이면 n 은 fp32 몫 v / s_v
   에 가장 가까운 정수(같으면 짝수), s_v = 0 이면 0. 캐시의 스케일 칸 [위치][4] 에는 같은 값 넷을 둔다(배치는 2.1 과 같다).
3. **점수**(log₂ 단위): 블록 b 마다 u_b,t = fp32(Σ n_q · n_k)(2.1 과 같은 정확한 정수 합에 반올림 하나), z ← u_0,t × s_k,t,0, 그다음
   b = 1, 2, 3 차례로 z ← fma(u_b,t, s_k,t,b, z), s_t = z × q_c. q_c = 2^(E_q − 13) × c′(정확), c′ = fp32(fp32(1/√128) × fp32(log₂e)) =
   0x3E0293EE. 마스킹된 키(t > p)는 −3 × 10³⁸.
4. **지수2**(x ≤ 0): x_c = max(x, −126), t = x_c + 1.5 · 2²³(가까운 정수로 반올림), r = x_c − (t − 1.5 · 2²³)(정확 — |r| ≤ ½), p 는
   곱해더하기 체인 (((((c₅ · r + c₄) · r + c₃) · r + c₂) · r + c₁) · r + 1) — c_k 는 (ln 2)^k / k! 의 fp32(c₁ … c₅ = 0x3F317218 ·
   0x3E75FDF0 · 0x3D635847 · 0x3C1D955B · 0x3AAEC3FF), 결과의 비트 = p 의 비트 + (t 의 비트 ≪ 23)(2³² 의 나머지 — 지수에 n 을 더한다).
5. **타일**(키 64): m = max_t s_t, e_t = 지수2(s_t − m)(마스킹된 키는 0), l 은 2 절 3 그대로(정수 합). e′_t = e_t × s_v,t(반올림 하나).
   행마다 타일의 e′ 최댓값으로 E = ⌊log₂ max_t e′_t⌋(자리 둘의 규칙 — [−98, 100], 0 이면 −98), n_t = 가까운정수(e′_t · 2^(13 − E)) ∈
   [0, 2¹⁴], U_d = fp32(Σ_t n_t · n_v,t,d)(타일의 키 64 개에 대한 정확한 정수 합에 반올림 하나), P = 2^(E − 13).
6. **병합**(3 절의 두 층 — 지수는 지수2): 그룹의 첫 타일이 (M, L, O) = (m, l, fma(U, P, +0)), 그다음 타일마다 M′ = max(M, m),
   가 = 지수2(M − M′), 나 = 지수2(m − M′), L ← fma(l, 나, L · 가), O ← fma(U, fp32(P · 나), O · 가), M ← M′. 그룹끼리는 3 절의 식에
   지수2. 출력은 O / L.

fp32 연산은 모두 규칙 R 을 따르고, 결정성 · CPU 참조와의 비트 같음 · 실행 경로 불변은 그대로다. 2.1 과 연산이 달라 출력 비트가 다르다.
값의 블록 넷이 e′ 의 자리 하나를 함께 쓰고(2.1 은 블록마다), 가중합의 정수 → fp32 변환이 키 64 개에 한 번이며(2.1 은 32 개마다),
지수 함수가 짧아 프롬프트 어텐션의 명령이 약 1/3 적다. CPU 참조는 [계약/정수계약.py](정수계약.py)의 `어텐션F2`(`F2 = True`).

## 3. 두 층 병합(two-level merge — 13단계)

키 타일(tile — 위치 64 개)을 그룹(group — 타일 16 개 = 위치 1024, 그룹 g 는 위치 [1024g, 1024g + 1024))으로 나눠:

1. 그룹 안에서 타일을 차례로 병합해 그룹 상태 (M_g, L_g, O_g) 를 만든다(그룹의 첫 타일이 처음 값).
2. 그룹들을 g = 0, 1, … 차례로 같은 식으로 병합한다(첫 그룹이 처음 값).

병합 식(두 층 모두): M′ = max(M, m), 가 = 적힌지수(M − M′), 나 = 적힌지수(m − M′), L ← 곱해더하기(l, 나, L·가), O ← 곱해더하기(o, 나, O·가).
그룹의 경계는 위치만으로 정해지므로 어느 길로 계산해도 같은 비트다. 위치 1024 까지는 그룹이 하나라 한 층 병합(9~12단계)과 같다.
그룹 상태만 전역 메모리에 두면 한 (행, 헤드)의 일을 블록들에 나눌 수 있다 — 긴 문맥의 짧은 청크가 빨라진 까닭. 정확도는 그대로다(fp64
대비 오차 중앙값 새 / 옛 1.0003 · 0.9994배).

## 4. Llama 계열 블록 (14단계 — Qwen2, [14단계](https://github.com/wwoosshh/GeulPU/blob/main/문서/14단계.md))

1. **RMSNorm** (행 하나, 너비 D): 스레드 t (0 … 255)의 부분합 p_t = Σ_{c ≡ t (mod 256)} x_c · x_c (c 오름차순, 곱 · 합마다 반올림), 128 부터 반씩 짝지어
   더해 S, r = 1 / 제곱근(S / D + eps) (IEEE 가까운 반올림), y_c = (x_c · r) · w_c. 다음 선형 층의 입력이면 바로 자리 둘로.
   eps 는 모듈의 상수이고 GGUF 의 `layer_norm_rms_epsilon` 과 같아야 한다 — Qwen2 는 짧은실수(10⁻⁶) = 0x358637BD(모듈 qwen2… — Qwen2.5 ·
   R1-Distill-Qwen-7B) 또는 짧은실수(10⁻⁵) = 0x3727C5AC(모듈 qwen2e5… — R1-Distill-Qwen-14B, 커널생성 qwen2e5큰), 그 밖은 받지 않는다(#16).
2. **RoPE** (NeoX — 반쪽 돌리기): 표 cos · sin [위치][32] 는 바르게 반올림한 짧은실수(θ_i = θ^(−2i/64) 를 fp64 로 바르게, 각 = 위치 · θ_i 는
   fp64 곱, cos · sin 은 짧은실수로 바르게 — 플랫폼의 수학 함수와 상관없다; 파이썬 표준 decimal 로 구한다). x′_i = 곱해더하기(x_i, cos, −(x_{i+32} · sin)),
   x′_{i+32} = 곱해더하기(x_{i+32}, cos, x_i · sin) — q · k 에, 치우침 뒤에. 그다음 q 는 자리 둘, k · v 는 정수 KV 캐시로.
3. **SwiGLU**: e = 적힌지수(0 − |g|), s = g ≥ 0 이면 g / (1 + e), 아니면 (g · e) / (1 + e), h = s · u (연산마다 IEEE 반올림). h 는 down 의 자리 둘로.
4. **GQA**: 질의 헤드 h 는 KV 헤드 ⌊h / (질의 헤드 수 / KV 헤드 수)⌋ 의 캐시를 읽는다 — 어텐션의 계약(2 · 3 절)은 그대로.
5. 치우침 없는 선형(o · gate · up · down · 로짓)은 치우침 0 을 더한다. 임베딩은 어휘의 q · d (정확), 위치 임베딩은 없다.
6. **헤드마다 Q · K 정규화** (37단계 — Qwen3, [37단계](https://github.com/wwoosshh/GeulPU/blob/main/문서/37단계.md)): q · k · v 선형(치우침이 없는 모델은 5 대로 0 을 더함) 뒤, RoPE 앞에
   q 의 헤드마다 · k 의 헤드마다(행 하나의 헤드 하나 = 원소 128 개 x_0 … x_127) 1 의 RMSNorm 을 D = 128 로 한다. 스레드 t < 128 에 원소가 하나씩이고
   간격 128 의 더하기는 +0 이라 그 식은 이렇다: p_t = x_t · x_t, 간격 h = 64, 32, …, 1 로 반씩 더해(p_t ← p_t + p_{t+h}) S, r = 1 / 제곱근(S / 128 + eps),
   y_t = (x_t · r) · w_t. 가중치 w 는 층마다 `attn_q_norm` · `attn_k_norm`(짧은실수 128 개 — 헤드끼리 같은 가중치), eps 는 모델의 값(생성기의
   상수와 같아야 한다). v 는 정규화하지 않는다. 그다음 RoPE(아래 헤드 크기 128 의 2)와 정수 KV 는 그대로.
7. **llama 구조** (39단계 — Llama 3.1 · 3.2 · Mistral v0.3, [39단계](https://github.com/wwoosshh/GeulPU/blob/main/문서/39단계.md)): 블록은 1 ~ 5 그대로(치우침 없음 — 0 을 더함), 헤드 크기는
   128(아래). 다른 것은 셋이다.
   1. **q · k 줄 되돌리기**: GGUF 변환기(llama.cpp 의 `convert_hf_to_gguf.py` 의 permute)는 헤드 하나(128 줄)의 원래 줄 h · 64 + j
      (h ∈ {0, 1}, j < 64)를 파일의 줄 2j + h 에 둔다. 가중치를 올릴 때 헤드마다 새 줄 j (< 64) 에 파일의 줄 2j, 새 줄 64 + j 에 파일의 줄
      2j + 1 을 놓는다(q 는 질의 헤드마다, k 는 KV 헤드마다 — 양자화된 줄을 그대로 옮긴다. 줄마다 따로 양자화되어 있어 값이 같다. 치우침이
      있으면 같이). 그 뒤의 RoPE 는 아래 헤드 크기 128 의 2(짝 (i, i + 64))를 그대로 쓰고, KV 캐시의 칸 차례는 원래(HF) 모델의 차례다.
   2. **RoPE 늘이기 인자**: GGUF 에 `rope_freqs.weight`(짧은실수 64 칸 f_i, 모두 양수)가 있으면 θ′_i = θ_i / f_i (fp64 나누기 하나 —
      바르게 반올림), 각 = 위치 · θ′_i (fp64 곱), cos · sin 은 짧은실수로 바르게(decimal). 없으면 θ′_i = θ_i. `rope.scaling.type` 이 있고
      none 이 아니면 받지 않는다.
   3. **eps**: RMSNorm 의 eps = 10⁻⁵ (모듈의 상수 짧은실수(10⁻⁵) = 0x3727C5AC — GGUF 의 값과 같아야 한다). 식은 1 그대로.
8. **YaRN 위치 늘이기** (GeulPUv2 ③a — Qwen2.5 7B 이상 · Qwen3, [문서/긴문맥.md](../문서/긴문맥.md)): 문맥(최대길이)이 GGUF 의 위치 수
   (`context_length` — Qwen2.5 32,768 · Qwen3 40,960)를 넘을 때만 켠다 — 배 s 는 문맥을 덮는 가장 작은 2 · 4(원래 길이 L = 32,768, 문맥 한도
   131,072). 구조 qwen2(너비 3,584 이상) · qwen3 일 때만(GGUF 에 `rope.scaling.type` 이 있고 none 이 아닌 파일은 구조와 상관없이 받지 않는다 — #17). 켜면 RoPE 표만 바뀐다(커널 그대로):
   1. **경계**: c(β) = hd · ln(L / (β · 2π)) / (2 · ln θ) 를 두 배 정밀도로 계산해 fp64 로 바르게 — 아래 = ⌊c(32)⌋, 위 = ⌈c(1)⌉ 를 [0, hd − 1] 로
      자른다(같으면 위 += 0.001). 정수에서 10⁻⁶ 안이면 멈춘다. (θ = 10⁶ · hd = 128 · L = 32,768 이면 아래 23 · 위 40 — 짝 24 … 39 가 섞인다.)
   2. **주파수**: r_i = (i − 아래) / (위 − 아래) (fp64 나누기)를 [0, 1] 로 자르고, g_i = r_i / s + (1 − r_i) (fp64 의 나누기 · 빼기 · 더하기 —
      이 차례), θ′_i = θ_i · g_i (fp64 곱 하나 — θ_i 는 헤드 크기 128 의 2). r_i 가 0 · 1 인 짝은 g_i = 1 · 1/s 로 정확하다.
   3. **크기**: m = 0.1 · ln s + 1 (ln s 는 fp64 로 바르게, 곱 · 더하기는 fp64 하나씩 — s 2 · 4 면 1.0693147180559945 · 1.138629436111989). 표 cos ·
      sin 은 짧은실수(m · cos(위치 · θ′_i)) · 짧은실수(m · sin(위치 · θ′_i)) — 각은 fp64 곱 하나, 정확한 곱 m · cos 의 바른 반올림 하나(q · k 가 모두 m
      배 — 어텐션 온도). 이것은 transformers 의 `_compute_yarn_parameters`(Qwen 의 config `rope_scaling: {type: yarn, factor, original_max_position_embeddings}`)
      · llama.cpp 의 rope_yarn 과 같은 식을 fp64 로 정한 것이다.
   4. 켠 서버는 프롬프트 캐시의 청크 이름에 `YaRN s×L` 을 넣는다(KV 의 바이트가 다르다). 위치 수 안의 문맥에서는 표 · KV 가 바이트까지 그대로다.

### 헤드 크기 128 (22단계 — Qwen2.5-7B, [22단계](https://github.com/wwoosshh/GeulPU/blob/main/문서/22단계.md))

헤드 크기 64 의 계약은 그대로다. 헤드 크기 128 에서 다른 것은 셋이다.

1. **점수의 눈금**: 점수 합은 32 칸 블록 넷을 b 오름차순으로 곱해더하기 사슬로 잇고(블록 0 이 처음 값 — 헤드 크기 64 의 둘과 같은 꼴), 그 뒤에
   s ← s × c 를 **곱 한 번(반올림 하나)**. c = 짧은실수(1/√128) = 0x3DB504F3 = 0.088388346135616302490234375 (가까운 반올림). 헤드 크기 64 의
   0.125 는 2 의 거듭제곱이라 어디서 곱해도 같지만, c 는 아니므로 자리를 정한다.
2. **RoPE**: 표 cos · sin 은 [위치][64], θ_i = θ^(−2i/128) (i = 0 … 63, fp64 로 바르게), 돌리는 짝은 (i, i + 64). 곱해더하기의 꼴은 헤드 크기 64 와 같다.
3. **출력 o_d** 는 값의 32 칸 블록 넷(d 0 … 127)마다 2 절 4 의 식. 적힌지수 · 합 l · 두 층 병합은 그대로다. 그룹 · 타일 상태는 (M, L, 여백 둘,
   O 128) = 원소 132 개.

## 5. 샘플링 (28단계 — 서버, [28단계](https://github.com/wwoosshh/GeulPU/blob/main/문서/28단계.md))

탐욕(온도 0)이 아닌 생성은 로짓 행 하나 z(엔진이 낸 짧은실수 V 개)에서 이 계약대로 다음 토큰을 고른다. 계산은 f64 로 적은 차례대로 하나씩
반올림하고, 곱해더하기는 쓰지 않는다. 고른 토큰은 (그 행의 로짓, 매개변수, 시드, 스텝)에만 달려 있다. 로짓이 배치 · 슬롯 · 넣는 길과
상관없으므로(1 ~ 4 절) 샘플링도 상관없다. 글(geul) 언어 버전은 [호스트/뽑기.gl](../엔진/뽑기.gl), 파이썬 버전은 [시험/뽑기.py](../시험/뽑기.py)다.

들어오는 것: 온도 T(f64 ≥ 0), top_k K(정수 ≥ 0, 0 = 끔), top_p P(0 < P ≤ 1), min_p Q(0 ≤ Q < 1), 시드 s(u64), 스텝 i(요청의 첫 생성 토큰이 0).

1. T = 0 또는 K = 1 이면 z 가 가장 큰 번호 중 가장 작은 것을 고른다(장치의 가장큰번호와 같다).
2. 번호를 (z 내림차순, 같으면 번호 오름차순 — −0 과 +0 은 같은 값)으로 늘어놓는다: j₁, j₂, ….
3. a_k = (f64(z_{j_k}) − f64(z_{j₁})) / T. 후보는 a_k ≥ −40 인 앞부분(n_F)이다. 이것이 밝힌 손실이다. 가장 큰 것의 e⁻⁴⁰ ≈ 4 × 10⁻¹⁸ 배
   아래의 확률은 0 으로 둔다.
4. n_K = K > 0 이면 min(K, n_F), 아니면 n_F.
5. w_k = 지수(a_k) (k ≤ n_K, w₁ = 1), c_k = c_{k−1} + w_k (c₀ = 0, 차례대로).
6. top-p: P < 1 이면 n_P = c_k ≥ P × c_{n_K} 인 가장 작은 k, 아니면 n_K.
7. min-p: n_Q = w_k ≥ Q 인 k(≤ n_K)의 수(Q = 0 이면 n_K).
8. n = min(n_P, n_Q) (≥ 1).
9. u = (분할섞기64(s, i) ≫ 11) × 2⁻⁵³, t = u × c_n. c_k > t 인 가장 작은 k(≤ n)의 j_k 를 고르고, 없으면(반올림) j_n 을 고른다.

- **분할섞기64(s, i)**: x = s + (i + 1) · 0x9E3779B97F4A7C15 (mod 2⁶⁴)로 시작해 차례로
  x ← (x ⊕ (x ≫ 30)) · 0xBF58476D1CE4E5B9, x ← (x ⊕ (x ≫ 27)) · 0x94D049BB133111EB, x ← x ⊕ (x ≫ 31) 을 한다(≫ 는 부호 없는 밀기).
  SplitMix64 를 s 로 시작했을 때의 (i + 1) 번째 값이다.
- **지수(a)**, a ∈ [−40, 0]:
  - k = ⌊a × 0x3FF71547652B82FE + 0.5⌋
  - r = (a − k × 0x3FE62E42FEE00000) − k × 0x3DEA39EF35793C76 (상수는 f64 의 비트 — 1/ln2 와 fdlibm 의 ln2 높은 · 낮은 쪽)
  - p ← 1/13!, p ← p × r + 1/n! (n = 12 … 0), 1/n! = f64(1) / f64(n!)
  - 값은 p × 2^k (2^k 는 비트로 만들어 곱한다 — 정확)

요청에 없을 때의 기본값은 llama-server 와 같다: T 0.8, K 40, P 0.95, Q 0.05. 시드를 주지 않으면 서버가 하나 샘플링해 응답(`geulpu.seed`)에 넣는다.
차례는 llama.cpp 와 다르다. llama.cpp 는 top-k · top-p · min-p 를 온도 1 의 확률로 자르고 온도를 마지막에 쓴다. 이 계약은 온도를 먼저 쓴다
(Hugging Face 와 같은 차례).

### 5.2 로그확률 (38단계 — 서버, [38단계](https://github.com/wwoosshh/GeulPU/blob/main/문서/38단계.md))

로그확률(`logprobs` · `top_logprobs` · echo 의 점수)은 로짓 행 하나 z(엔진이 낸 짧은실수 V 개)에서 이 계약대로 계산한다. 모든 계산은 f64 로
적은 차례대로 하나씩 반올림하고, 곱해더하기는 쓰지 않는다. 분포는 **모델의 것**(온도 1 · 거르기 없음)이다 — 5절 샘플링의 분포가 아니다.
글(geul) 언어 버전은 [호스트/로그확률.gl](../엔진/로그확률.gl), 파이썬 버전은 [계약/로그확률.py](로그확률.py)다. 로짓이 배치 · 슬롯 ·
넣는 길(생성 스텝 · 프롬프트 길)과 상관없으므로 로그확률도 상관없다 — 생성하며 받은 값과 같은 글을 점수 매긴(echo) 값이 비트까지 같다.

1. j₁ = z 가 가장 큰 번호 중 가장 작은 것, m = f64(z_{j₁}). a_j = f64(z_j) − m.
2. w_j = 지수(a_j)(5절의 지수) — a_j ≥ −40 인 것만, 아니면 0. 이것이 밝힌 손실이다(가장 큰 것의 e⁻⁴⁰ 배 아래는 합에서 빠진다).
3. 어휘를 16 구간으로 나눈다: B = ⌈V / 16⌉, 구간 r = [rB, min(V, (r + 1)B)). 구간마다 0.0 에서 시작해 번호 차례로
   S_r ← S_r + w_j, T_r ← T_r + w_j · a_j(곱은 반올림 하나). S = (…((S₀ + S₁) + S₂) + …) + S₁₅, T 도 같게(S₀ · T₀ 이 처음 값).
   구간은 계산을 워커 스레드로 나누려고 둔다 — 구간 안 · 구간 사이의 차례가 정해져 있어 스레드 수와 상관없이 같다.
4. L = 로그(S), **logprob_j = a_j − L**, 엔트로피 **H = L − T / S**.
5. 상위 k(≤ 20): 번호를 (z 내림차순, 같으면 번호 오름차순 — −0 과 +0 은 같은 값)으로 늘어놓은 앞 k 개와 그 logprob.

- **로그(x)** — fdlibm `e_log.c` 의 차례 그대로(S 는 1 이상 V 이하의 정규수):
  - x 의 비트에서 지수 k 와 가수를 떼어, 가수를 [√2/2, √2) 로 맞춘 xn(높은 단어 hx 에 0x95F64 를 더해 0x100000 자리로 가른다)과 f = xn − 1.
  - |f| < 2⁻²⁰(가수의 높은 단어로 판단)이면: f = 0 이면 k·ln2높 + k·ln2낮(k = 0 이면 0), 아니면 R = f·f·(0.5 − f·(1/3)) 로
    f − R(k = 0) 또는 k·ln2높 − ((R − k·ln2낮) − f).
  - 아니면 s = f / (2 + f), z = s·s, w = z·z, t1 = w·(Lg2 + w·(Lg4 + w·Lg6)), t2 = z·(Lg1 + w·(Lg3 + w·(Lg5 + w·Lg7))), R = t2 + t1.
    가수가 √2 둘레의 정한 범위면(fdlibm 의 i > 0) hfsq = 0.5·f·f 로 f − (hfsq − s·(hfsq + R)) 또는
    k·ln2높 − ((hfsq − (s·(hfsq + R) + k·ln2낮)) − f), 아니면 f − s·(f − R) 또는 k·ln2높 − ((s·(f − R) − k·ln2낮) − f).
  - 상수는 f64 의 비트: Lg1 0x3FE5555555555593, Lg2 0x3FD999999997FA04, Lg3 0x3FD2492494229359, Lg4 0x3FCC71C51D8E78AF,
    Lg5 0x3FC7466496CB03DE, Lg6 0x3FC39A09D078C69F, Lg7 0x3FC2F112DF3E5244, 1/3 = 0x3FD5555555555555, ln2높 · 낮은 5절과 같다.
  - 계약 자체 시험(빠른 점검)이 바르게 반올림한 ln 과 1 ulp 안인지 본다(6,021 값 — 최대 1 ulp).

응답: 채팅은 OpenAI 호환 `logprobs.content`(token · logprob · bytes · top_logprobs), 완성은 `logprobs`(tokens · token_logprobs ·
top_logprobs · text_offset — echo 면 프롬프트 토큰부터, `geulpu.echo_from` 앞은 null). `geulpu` 에 상위 k 의 번호 · 값(`top_ids` ·
`top_logprobs` — 완성의 사전 꼴은 같은 글의 토큰을 합친다), 엔트로피(`entropy` · `prompt_entropy`), 프롬프트 토큰(`prompt_tokens`), echo 행의
로짓 해시(`prompt_logit_hashes`). 실수는 유효 자리 17 로 써서 f64 가 그대로 되돌아온다.

- **로짓 해시**(`logit_hashes` · `prompt_logit_hashes`): 로짓 행(짧은실수 V 개)의 32비트 값 w 마다 h ← (h ^ w) × 1099511628211(mod 2⁶⁴),
  처음 h = 0xcbf29ce484222325(FNV-1a 64). 16진 16 자리.
- **지문 · 재현 파일**(연구 패널 — 계산의 계약이 아니라 기록의 꼴): 토큰 지문 = SHA-256(`geulpu-fp/1\nmodel <모델 파일 SHA-256>\nprompt
  <번호,…>\ntokens <번호,…>\n`), 로짓 지문 = SHA-256(`<토큰 지문>\n<스텝마다 로짓 해시,…>\n`) — 장치 · 백엔드는 넣지 않는다. 재현 파일
  (`geulpu-capsule/1`)은 요청(프롬프트 토큰 · 온도 · top-k · top-p · min-p · 시드(원문 정수) · `step_offset` · `max_tokens`), 결과(토큰 ·
  로그확률 · 엔트로피 · 상위 k · 로짓 해시), 모델(이름 · 파일 · 크기 · SHA-256), 만든 곳(`made_on` — 장치 · 백엔드는 만든 쪽이 적은 기록,
  계산 방식 `precision` · `kv8` · `fast_attention` 과 YaRN 배 `yarn`(#23 — 4.8 절, 0 이면 없음)은 확인이 고를 계약)을 담는다. [도구/repro_check.py](../도구/repro_check.py)가 GPU 없이 이 계약의 CPU 참조(1 ~ 5절)로 같은 토큰 · 로짓 해시 ·
  로그확률 · 지문이 나오는지 본다.
