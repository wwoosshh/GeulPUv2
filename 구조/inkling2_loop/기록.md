# 구조 inkling2_loop — 단계 기록

GGUF `general.architecture` = `inkling2_loop`(층 반복이 있는 Inkling 2 — Inkling-2-Mini)와 `inkling2`(반복 없음 — 같은 엔진이 시작 = 끝 = 층 수 ·
패스 1 로 받도록 짰다. 이 구조의 공개 파일이 없어 돌려 보지 않았다). 0.25.0 계획([문서/0.25.0.md](../../문서/0.25.0.md))의 25-4 단계, 사용자 2026-11-24 "진행해". 계약은 4.15, 판은
[커널/생성inkling2.gl](../../커널/생성inkling2.gl)(25-3), 블록 레시피는 [문서/블록조합.md](../../문서/블록조합.md) 의 'Inkling 2'.

말이 되지 않는다 — 비트 대조에만 쓴다.

## 엔진의 짜임

| 무엇 | 어떻게 |
|---|---|
| 층 실행 | 실행 a = 층 [0, 시작) → 층 [시작, 끝) 을 패스 수만큼 → 층 [끝, 층 수). Inkling-2-Mini 는 6 + 12 × 3 + 6 = 48 번 |
| 키 · 값 캐시 | 전체 어텐션 층의 실행(실제 파일 8 개)은 공통 KV 캐시 — 구조표의 캐시층수 를 실행 수로, 어텐션층인가 는 늘 거짓(층 번호로 찾는 공통의 길을 피한다). 슬라이딩 윈도 층의 실행(40 개)은 구조의 고리 버퍼(Gemma 4 와 같은 꼴 — 위치 p 는 p mod 고리) |
| 합성곱 상태 | [슬롯][실행][k · v · 어텐션 출력 · FFN 출력][앞 3 행][너비] |
| 블록 상태 | 스택 하나(칸 0 … 깊이 − 1 이 블록 상태, 칸 깊이에 그때의 x) — 블록섞기잉클링 이 이어진 칸을 그대로 읽는다. 패스가 끝나면 그 패스가 더한 상태와 출력을 은행 스택에 옮기고(다음 패스의 메시지 — 계약 4.15 의 10) 깊이를 반복 앞으로 되돌린다 |
| 행렬곱(고전 Q8_0) | 0 h_q 의 [q \| 상대 r \| 싱크 t(64 열로) \| 게이트 g] = 6,592 열, 1 attn_output(깊이 3,072), 6 · 7 슬라이딩 윈도 층의 k · v, 8 · 9 전체 어텐션 층의 [k \| 동적 탭] · [v \| 동적 탭], 4 로짓 |
| 행렬곱(16비트 블록 — 파일의 F32) | 10 라우터, 11 블록 섞기의 질의(32 열로), 2 반복 제어의 down(깊이 2 · 너비 = 4,608), 3 gain · forget |
| 로짓 | 소프트캡 30, 패딩한 어휘(200,058 … 201,023)는 −∞(로짓가리기잉클링 — 서버의 로그확률은 −40 아래를 건너뛴다) |
| τ | 전체 어텐션 층의 로그 스케일 표를 장치에서 한 번(타우표잉클링 — 호스트의 fp32 는 fma 를 계약대로 하지 못한다) |
| 모듈 | `inkling2큰 Q8_0 2304 24 8 1152 201024 --MoE Q8_0 --W16` → `inkling2Q8_2304x24x8x1152x201024_MoEQ8`(서버 --모델확인 이 내는 것) |

처음 판이 하지 않는 것: 생성 그래프 · 표 판(생성은 행마다 같은 계획), 추측 디코딩, 프롬프트 캐시(슬롯 캐시는 가진 토큰을 모두 이을 때만 —
구조표의 캐시통째), 슬롯 사이 복사, 문맥 저장소, 층 나누기(GPU 여럿), 빠른 계약, 8비트 KV, Vulkan.

## 남은 것

- k-양자화 파일(Q4_K_M 등): 엔진의 길이 없다. llama.cpp 의 변환은 전문가 down(K = 1,152 — 256 의 배수가 아니다)을 Q5_0 · Q8_0 으로 바꾸므로
  파일의 머리(텐서 형식)를 먼저 봐야 한다.
- 생성 그래프 · 표 판 · 추측 디코딩 · 프롬프트 캐시 · 슬롯 사이 복사.
- 서버 · 앱의 Inkling 길(채팅 · 도구 호출)은 25-5 에서.
