# 0.25.0 — Inkling-2-Mini (계획 2026-11-24)

사용자 2026-11-24: "지금 geulpu가 지원하는 모델이 시장의 모델분포에서 어느정도이고 … 기준을 최신화해서 지원하는 모델과 지원하지 않는
모델이 어떤지를 판단해봐" → 시장을 다시 측정한 뒤 "계획 세워". 선택한 모델은 Inkling-2-Mini 다(아래 '왜'). 버전은 [버전 규칙](버전규칙.md)대로
MINOR(새 구조 — 지금 받는 모델의 출력 비트는 그대로). 단계마다 PR 하나이고, 다음 단계로 갈지는 사용자가 정한다.

**목표**: Inkling-2-Mini 의 GGUF(Q8_0 · Q4_K_M)를 GeulPU 가 정밀 모드 · CUDA 로 실행한다 — 계약의 CPU 참조와 비트까지 같고, 품질 · 채팅 ·
도구 호출 · 토크나이저 · 채팅 템플릿을 확인한 뒤 모델 목록에 넣는다. 확인은 Pedro 의 원격 서버(H100)에서 한다(이 PC 의 Windows 에는
CUDA 로 쓸 수 있는 GPU 가 없다 — 아래 '측정 환경').

Inkling-2-Mini 를 먼저 하는 까닭:
- 새로 몰리는 모델이고 크기가 맞다 — 26B MoE 라 24 GB 카드(Q4_K_M 18.7 GB)와 원격 H100(47 GB — Q8_0 27.8 GB 가 그래픽 메모리에 다
  들어간다)에서 돈다. 12 GB 카드는 전문가를 RAM 에 둔다(지금의 MoE 실행 경로).
- Pedro 그룹(UPM GING)의 논문 조사가 논문을 읽고 정보를 뽑는 모델로 쓴다(그들의 H100 MIG 인스턴스 · vLLM).
- 같은 방식(가운데 층을 같은 가중치로 여러 번 실행하는 looped transformer)의 SenseNova-Loop-9B(11-17 — Qwen3.5-9B 의 구조에 층 반복과
  mHC)가 이미 나왔다. 엔진에 층 반복을 넣으면 다음 모델에 다시 쓴다.
- Qwen3.8-Flash-Next 는 다운로드 비중이 더 크지만 새 구조(희소 어텐션 인덱서 · 하이퍼커넥션 · n-gram 임베딩 · 전문가 512 개)와 2 ~ 3 비트
  형식을 함께 해야 하고, 원격 H100(47 GB + RAM 64 GiB 한도)에도 2 ~ 3 비트 파일만 들어간다 — 따로 계획한다.

## 계산 — 구성 요소와 GeulPU 에 이미 있는 것

llama.cpp 와 transformers 의 구현을 읽고 정리한 것이다(둘은 같은 식으로 보인다 — 다른 곳이 나오면 25-1 에서 적는다). '계약'은
[계약/계약.md](../계약/계약.md) 의 절이다.

| 구성 요소 | 계산 | GeulPU 에 있는 것 | 새로 할 것 |
|---|---|---|---|
| 입력 | 임베딩 → RMSNorm(`token_embd_norm`) | RMSNorm(계약 4 의 1) | 임베딩 뒤 정규화 |
| 블록 어텐션 잔차(block attention residual) | 6 층마다 잔차 스트림을 새로 시작하고 그 앞 상태를 블록 상태로 남긴다. 층의 입력 · FFN 의 입력 · 최종 출력은 [블록 상태들, 지금 상태]를 가중치 없는 RMSNorm 으로 맞춘 뒤 학습된 질의 벡터로 softmax(· / √2,304) 가중합한 값이다. 전체 어텐션 층은 q · k · v 입력의 질의가 따로 | RMSNorm, 작은 softmax(4 의 11 의 2) | 새 계약 · 커널, 행마다 블록 상태 버퍼 |
| 위치 | 상대 위치 편향: r = `attn_rel` · h(헤드마다 16 차원)를 L2 노름 클리핑(문턱 8)한 뒤 표 `attn_rel_bias`[16][1,024] 와 곱해 거리 0 ~ 1,023 의 편향을 점수에 더한다(그 밖의 거리는 0). 전체 어텐션 층은 q 와 r 에 τ = 1 + 0.1 · ln(max(1, (위치 + 1) / 8,192)) 를 곱한다 | log1p(4 의 10 의 4) | 새 계약, 어텐션 커널의 편향 항 · τ |
| 어텐션 싱크(attention sink) | 질의 · 헤드마다 싱크 로짓 t = `attn_sink_proj` · h — softmax 의 분모에 exp(t) 가 더해진다(값 벡터는 0) | 온라인 softmax(2 · 3 절) | 처음 상태에 싱크를 넣는 계약 · 커널 |
| q · k · v | q = `attn_q` · h 에 채널 스케일(`attn_q_clip`)을 곱하고 L2 노름 클리핑(문턱 22.63 = 16√2), k 도 같은 클리핑, v 는 가중치 없는 RMSNorm. 점수 스케일 1/√128 | L2 정규화(4 의 10 의 3), 가중치 1 의 v 정규화(4 의 12 의 2) | 클리핑 식(노름 + 10⁻⁶, min(1, 문턱 / 노름)) |
| short convolution | 커널 4 의 인과 합성곱을 k · v(전체 어텐션 층은 `attn_k_conv_proj` · `attn_v_conv_proj` 로 토큰 · KV 헤드마다의 탭(tap)을 더한다) · 어텐션 출력 · FFN 출력에. 잔차를 더해 √5(정적) · √9(동적)로 나눈다. 시퀀스마다 앞 3 토큰의 상태 | GDN 의 합성곱과 시퀀스 상태(4 의 10 의 2) | 정적 · 동적 탭, 잔차 · 스케일, 상태 네 가지 |
| 출력 게이트 | 어텐션 출력 × σ(`attn_gate` · h) | 4 의 9 | — |
| 슬라이딩 윈도 | 1,024 — 층 20 개 | Gemma 4 의 윈도 · 링 버퍼 KV(4 의 12 의 2) | 헤드 128 · 싱크 · 편향과 함께 |
| MoE | 라우터(F32) → σ → 선택 편향(`exp_probs_b`)을 더한 점수로 상위 8 → 선택한 전문가의 σ 를 합으로 나누고(하한 10⁻²⁰) × 8. 전문가의 활성 함수 SITU = 4 · tanh(g / 4) · σ(g) × 25 · tanh(u / 25) | σ 라우팅(4 의 13 의 8), 합친 gate_up · Q8_0 · Q5_0 의 down(Gemma 4 26B-A4B) | SITU, 하한 값 |
| 층 반복(loop) | 가운데 12 층을 3 번. 두 번째 패스부터는 층마다 앞 패스의 블록 상태와 출력에서 메시지(message) 넷(q · k · v · FFN)을 학습된 질의로 꺼내고(블록 어텐션 잔차와 같은 식), 입력 = (1 − tanh(f)) · x + tanh(g) · 메시지(f · g 는 [RMSNorm(x), RMSNorm(메시지)] 의 랭크 64 투영). 패스마다 KV 캐시와 합성곱 상태가 따로 — 층 실행 48 개 가운데 슬라이딩 윈도 40 · 전체 어텐션 8 | — | 엔진의 층 실행 순서, KV 캐시 층 48 개, 새 계약 |
| 출력 | 블록 어텐션 잔차 → `output_norm` → `output`(F32 누적) → 소프트캡 30 → 패딩한 어휘 966 개를 버린다 | 소프트캡(4 의 12 의 6) | 패딩한 어휘 버리기 |
| 토크나이저 | BPE, pre `inkling2` = GPT-4o 정규식 + ignore_merges, BOS 없음 | GPT-4o 정규식(엔진/사전처리표.gl 의 45), ignore_merges | 이름 한 줄 · BOS |
| 채팅 템플릿 | 역할 토큰 `<\|message_user\|>` · `<\|message_model\|>` · `<\|message_system\|>` · `<\|message_tool\|>`, 내용 토큰 `<\|content_text\|>` · `<\|content_thinking\|>`(생각 — 끄는 스위치가 없고 `reasoning_effort` 로 정도만 적는다), 도구 호출 `<\|message_model\|>이름<\|content_invoke_tool_json\|>{"name":…,"args":{…}}<\|end_message\|>`, 종료 토큰(EOS) `<\|content_model_end_sampling\|>`. 템플릿이 생성 프롬프트를 붙이지 않는다 — 모델이 역할 토큰부터 낸다. jinja 의 `generation` 블록(transformers 의 확장) · `tojson(sort_keys=…, separators=…)` · `dictsort(case_sensitive=…)` | jinja 해석기, 서버의 도구 호출 형식(Qwen · Llama 3 · Gemma 4 · GLM 등) | 도구 호출 형식 하나, 생각 내용 나누기, jinja 기능 확인 |

  번호와 커밋을 기록에 고정한다.

  확인한다.
