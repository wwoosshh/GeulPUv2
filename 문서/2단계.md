# 2단계 — 프롬프트 속도 1: 빠른 계약 F1(선형층의 활성값 한 자리) (계획 2026-10-19)

## 왜 · 무엇이 바뀌었나

- 사용자(2026-10-19): 이제 목표는 실사용 — 나와 주변인이 쓸 때의 속도 · 안정성 · 편안함이다. 이득이 분명하면 연구 때의 계약을 끝까지
  지킬 필요는 없다. 다만 계약 손실 · 기계적 손실을 막는 것은 엔진의 뿌리라, 그것을 버리는 것은 재설계다. llama.cpp · vLLM · SGLang 보다
  빠를 길이 있으면 시도한다. 각 단계의 계획은 독립 에이전트가 검증한다.
- 지금(GeulPU 39단계 기록): 7B 프롬프트는 llama.cpp 의 1.13 ~ 1.56 배 시간이다(2048 · 8192, 형식마다). 30단계의 커널별 측정(7B Q4_0)에서
  2048 토큰의 84 % 가 행렬곱이고, 행렬곱 넷은 int8 텐서 코어 최고치의 약 61 % 를 쓴다. 다만 활성값이 **자리 둘**(±2¹⁴)이라 바닥 자체가
  llama.cpp(8 비트 활성값)의 두 배다. 8192 토큰에서는 어텐션 + 접기가 31 % 다.
- 2026-10-13 에 같은 엔진에서 타일 커널 변형의 활성값을 자리 하나로 바꿔 쟀다: 7B Q4_0 프롬프트 512 · 2048 · 8192 가 1.38 · 1.35 · 1.26 배 빨랐다
  (하한 — 에필로그와 어텐션은 그대로). 33단계에서 그 변형(V1, `--자리하나`)을 Q8_0 · Q4_0 에 만들고 CPU 참조와 비트까지 맞췄다(판 시험 282
  경우 · 다섯 길 — 다른 칸 0). 다만 V1 의 눈금은 2^(E − 5)(E = ⌊log₂ 블록 최댓값⌋)라 최댓값이 32 ~ 64 에 놓여 llama.cpp 의 8 비트
  활성값(최댓값 → 127)보다 평균 약 2.9 배 거칠다.

## 결정 — 계약은 버리지 않고 정밀도만 한 단계 내린다

결정성(길 · 청크 · 함께 도는 요청과 상관없이 같은 비트)과 CPU 참조와의 비트 같음은 **정수 합의 정확함과 정해진 차례**에서 나오고, 같은
최적화에서 값이 거의 없다(33단계의 어림 · 2026-10-13 측정: 근사 지수로 바꿔도 거의 0). 값은 **정밀도**(자리 둘)에 있다. 그래서:

- **정밀 모드**(지금의 계약, 자리 둘) — 그대로 둔다. 모듈 18 개는 바이트까지 그대로. 연구 패널 · 교차검증의 기준.
- **빠른 모드 F1**(새 계약) — 선형층(타일 커널 변형 · 줄 커널 변형 · 줄 타일 커널 변형 · 로짓 판 · 접기의 출력)의 활성값을 **자리 하나**로. 어텐션(RoPE 의 q ·
  KV 캐시 · 어텐션 안의 e)은 이 단계에서 자리 둘 그대로(2b 의 일). F1 도 CPU 참조가 있는 계약이라 결정성 · 비트 재현 · 연구 패널은 모드
  안에서 그대로 선다.

### F1 의 활성값 규칙 (V1 에서 바꾸는 것 하나)

블록(32 칸)의 최댓값 m 에 대해 E = ⌊log₂ m⌋ (지금과 같음), **그리고 m · 2^(6 − E) < 127.5 이면 E ← E − 1**, 그다음 [−98, 100] 으로 자른다.
나머지는 V1 그대로: P = 5, n = 가까운정수(x · 2^(5 − E)), u = S · 2^(E − 5).

- |n| ≤ 127: E 를 줄인 경우 m · 2^(6 − E_원) ∈ [64, 127.5) → 가까운정수 ≤ 127. 줄이지 않은 경우(가수 ≥ 1.9921875) m · 2^(5 − E) ∈ [63.75, 64)
  → ≤ 64. int8 한 자리에 들어간다(V1 의 |n| ≤ 64 보다 넓다 — 판이 n 의 범위를 가정하는 곳을 확인해야 한다).
- 눈금 = llama.cpp(블록 최댓값 / 127)의 (0.996, 1.98] 배 — 로그 고른 가수에서 평균 약 1.43 배. 정확한 반올림(가까운 쪽 · 같으면 짝수)과
  나머지 계산(어텐션 자리 둘 · RMSNorm 등 짧은실수)은 llama.cpp 보다 촘촘하므로 전체 숨은 손실은 llama.cpp 와 같은 급으로 본다 — 아래 B 로 잰다.
- 가수 시험은 실수의 비트로 정확하다: 가수 23 비트가 0x7F0000 보다 작으면 줄인다(m · 2^(6 − E) < 127.5 ⟺ 1 + f < 1 + 127/128).
- 한 자리에서는 모든 형식에서 블록 합이 |S| < 2²² 이다(Q8_0 32·127·127 = 516,128 · Q5_K 32·127·31 · Q6_K 16·127·32). 지금 자리 둘에서 매직 넘버
  누산을 못 쓰던 Q8_0 · Q5_K · Q6_K 도 쓸 수 있다 — F1 의 에필로그를 줄일 여지(2c 후보, 이 단계의 필수는 아님).

## 독립 검토 (2026-10-19 01:10 — 판정: 고쳐서 진행)

새 에이전트가 계획 · 코드 · 기록을 직접 읽고 계산했다(파일은 고치지 않음). 요점과 그에 따른 결정:

1. **지수 규칙은 맞다** — 정규수 전수(지수 7 개 × 가수 2²³)에서 가수 시험 ⟺ 비교, 블록 최댓값 지수 −149 ~ 100 에서 |n| ≤ 127, 비정규수 · 0 을
   포함한 200 만 표본에서 GPU 식과 CPU 식의 E · n 이 같다. 차례는 "줄이고 자르기". 정의역은 |x| < 2¹⁰¹(그 위는 자리 둘과 같은 성질 — 계약에 적는다).
2. **k-양자화는 검사 한 줄이 아니다** — `생성K타일.gl`(활성값 복사 수의 내림 — 자리 하나면 판 여섯에서 0, 행의 자리 합, Q4_K 매직 넘버 사슬,
   Q6_K · Q5_K 의 S), `생성K.gl` 정수줄하나K(배치 · 복사 · 자리 합 · u · SwiGLU 에필로그), `생성줄타일.gl` 정수줄타일K(배치 · 복사 · 사슬)에 자리 둘이
   박혀 있었다. → 모두 자리 수를 따르게 고쳤다(자리 둘은 바이트까지 그대로 — 아래 A1).
3. **속도 여유가 작다** — 1.26 ~ 1.38 배는 Q4_0 만 잰 값이다. 에필로그 · B 풀기는 반으로 줄지 않아 Q4_K_M 은 llama.cpp 대비 여유 0 ~ 5 % 로 어림.
   → 결정: F1 의 실제 속도를 먼저 잰다. 2048 에서 llama.cpp 의 0.90 배보다 느리면(여유 10 % 아래) 2c 의 두 가지(한 자리의 매직 넘버 누산을
   Q8_0 · Q5_K · Q6_K 에, 행의 자리 합 T 를 활성값 바꿀 때 미리)를 이 단계로 당긴다.
4. **품질 B 는 그대로면 못 넘는다** — llama.cpp 의 숨은 손실은 거의 다 8 비트 활성값의 반올림이고, F1 의 오차 분산은 그 약 2.15 배(눈금이
   2 의 거듭제곱이라). 짧은실수 척도(최댓값 / 127)로 바꿔도 동률이다. → 결정(재기 전에 적음): 판정 B 를 **B′ 같은 급**으로 바꾼다 — 평균
   KL(정밀 ‖ F1) ≤ 2.5 × KL(정밀 ‖ llama.cpp) 이고 1위 토큰 일치율이 llama.cpp 의 것보다 0.5 %p 넘게 낮지 않다. 까닭: 이 크기(약 10⁻³)는
   Q4_K_M 의 가중치 양자화 손실(같은 꼴의 KL 이 그 수십 배)에 묻혀 쓰는 사람에게 보이지 않고, 사용자가 이득이 분명하면 계약을 늦춰도 된다고
   했다. B′ 와 C(분명한 속도 이득)를 함께 넘을 때만 F1 을 앱의 기본으로 한다. 아니면 F1 은 고를 수 있는 모드로만.
5. **측정의 공정성** — llama.cpp 도 표본의 가운데 값, `-fa` 0 · 1 × `-ub` 셋을 훑어 길이마다 가장 빠른 것, 바퀴마다 차례를 바꾸고, 모델은 고정
   경로(F:\geulpu-models). 생성 기준은 한쪽으로: F1 의 느려짐 ≤ 2 %. → `재기/견주기2.sh` · `재기/견주기요약.py`.
6. **그 밖** — A1 은 "정밀 모듈 16 개"(18 행 중 둘이 V1 — `_빠른` 행으로 바꾼다), A2 에 극단 값(지수 −98 · −97 · 100, 비정규수 · 0 블록)과 판
   모양 모두, 계약에 F1 절, 앱은 Vulkan · 공유32 장치에서 정밀 모드로, 모드를 바꾸면 서버를 다시 올려 캐시가 비고, 고른 모드의 모듈만 짓는다,

## 이 단계에 넣지 않는 것 (다음 반복의 후보 — 각각 따로 계획 · 검증)

- **2b 어텐션 빠른 길**: q · k(· e · v)를 자리 하나로 — 헤드 크기 128 어텐션 커널 변형(레지스터 255 · 넘침, 텐서 37 %)을 새로 짠다. 8192 의 31 %.

- **Vulkan · 공유32 의 F1**: CUDA 를 먼저. 친구 PC(AMD)용은 그 뒤.
