## 왜

긴 문맥 재기(문서/긴문맥재기.md)에서 생성 길이 문맥 10,240 토큰을 넘으면 틀린다는 것을 찾았다. 같은 토큰을 프롬프트 길과 생성 길(표 스텝)로
계산하면 10,200 까지는 로짓이 비트까지 같고 10,300 부터 어휘 전부가 다르며(12,000 부터 가장 큰 번호도), 31,000 에서 CUDA 700(메모리 접근
오류)으로 죽는다. 앱의 문맥 설정을 10,240 넘게 올리면 대화가 그 길이를 넘는 순간부터 생성 토큰이 오류 표시 없이 틀린다 — 계약 위반이고,
실사용의 세션(수만 토큰)에 닿는 결함이다. 속도보다 먼저 고친다.

## 까닭

커널/생성줄128.gl 의 `정수조각접기128`(헤드 크기 128 의 생성 어텐션 (나) — 두 층 접기)이 조각(키 64)마다의 M · L · 배율을 공유 판의 고정 칸에 둔다:
판[c] M · 판[160 + c] L · 판[320 + c] · 판[480 + c] 묶음 안 배율 · 판[640 + 묶음] 묶음 최댓값 · 판[656 + 묶음] · 판[672 + 묶음] 묶음끼리의 배율,
넓 판은 판[704 + 묶음] 묶음 L · 판[720 + 묶음 · 128 + d] 묶음 O. 그래서 조각 160 개(10,240 토큰) · 묶음 16 개까지만 칸이 겹치지 않는다. 그 너머는
칸이 서로 덮여 값이 틀리고, 넓 판은 18 번 묶음(위치 18,432)부터 공유 12 KB 를 넘는다.

- 이 생성기 함수 하나에서 나오는 판 모두가 같다: 정수조각접기 · 정수조각접기짧은 · 정수조각접기넓(시험용), 칸 판 정수조각접기 · 정수조각접기넓
  (`칸판` — 엔진의 정수조각접기칸 · 정수조각접기넓칸, 생성 그래프), 표 판 정수조각접기넓표(서버의 생성 · 추측 검증 스텝). 헤드 크기 128 의 모든 모듈
  (정밀 · 빠른 · 공유32 · qwen3 · llama — PTX 와 SPIR-V).
- 프롬프트 길의 접기(생성머리128.gl 의 정수묶음접기128)는 묶음 상태를 전역 묶음칸에서 읽고 배율 칸이 묶음 128 개(131,072 토큰)까지라 맞다.
  조각 어텐션(정수조각어텐션*)은 블록 하나가 (조각, KV 헤드) 하나라 길이 한도가 없다.
- 헤드 크기 64 의 생성 접기(커널/생성조각.gl 의 정수접기)는 이미 조각 256 개씩 무리로 돌며 앞 무리의 최댓값을 판[CM] 으로 잇는다 — 한도가 없다.
  GeulPU 의 긴 문맥 시험(합성 모델 · 위치 102,400)이 헤드 크기 64 라 헤드 크기 128 판의 한도가 드러나지 않았다. 머리128.py 의 긴 문맥 경우(8,300 행)는
  생성 커널 변형 넷과 생성 커널 변형(둘 다 이 접기)을 비교해 한도 안이었다.

## 고침

정수조각접기128 의 몸을 **무리(조각 128 개 = 묶음 여덟)마다 한 바퀴**로 돈다(헤드 크기 64 판과 같은 꼴):

1. 무리의 조각 M · L 을 판[c] · 판[160 + c] 에(c 는 무리 안 번호 0 … 127) — 동기화.
2. 묶음 안 배율(옛 · 새)과 묶음 최댓값 — 지금과 같은 식(묶음의 첫 조각부터 차례로 큰쪽, 무리는 묶음 경계에서 나뉘므로 묶음 안 계산은 그대로).
3. 묶음끼리의 배율: 무리 안 묶음 j 의 앞M = (첫 무리면 판[640] 에서 · 아니면 **이음M** 에서) 앞 묶음들의 최댓값을 차례로 큰쪽 — 묶음 g 의 앞M 은
   지금처럼 M₀ 부터 M_{g−1} 까지 차례로 큰쪽 한 값과 같은 차례의 같은 계산이다(이음M = 앞 무리 끝 묶음까지의 차례 큰쪽). 새큰2 · 가 · 나는 그대로,
   그리고 여기까지의 최댓값 판[688 + j] = 새큰2(첫 묶음은 M₀). 동기화 뒤 모든 스레드가 이음M = 판[688 + 묶음수 − 1].
4. 묶음 (L, O) — 지금과 같은 식(첫 조각이 처음 값, 이어 곱해더하기). 넓 판은 묶음마다 스레드 128 이 나란히 판[704 + j] · 판[720 + j · 128 + d]
   에 두고 동기화 뒤 스레드 0 … 127 이 차례로, 넓지 않은 판은 묶음마다 곧바로 — 누적 (L, O)는 레지스터로 다음 무리에 이어진다(첫 무리의 첫
   묶음이 처음 값).
5. 둘째 무리부터는 무리 맨 앞에서 동기화(앞 무리의 묶음 계산이 판을 다 읽은 뒤에 덮도록 — 헤드 크기 64 판 꼴).

- **같은 비트**: 모든 곱해더하기 · 적힌지수 · 큰쪽의 피연산자와 차례가 지금 판과 같다 — 조각 128 개까지는 무리 하나라 계산이 한 글자도 다르지
  않고, 그 너머도 예전 판이 칸만 겹치지 않았다면 냈을 값이다(계약의 두 층 접기 · 프롬프트 길과 같은 값).
- 판 칸: 넓지 않은 판 0 … 695(4 KB 의 1,024 안), 넓 판 0 … 1,743(12 KB 의 3,072 안). 길이의 한도는 최대길이뿐이다.
- 덧셈 비용: 둘째 무리부터 무리마다 동기화 하나가 맨 앞에 는다(검토 — 무리 하나, 곧 위치 8,191 까지는 장벽 수가 그대로).
