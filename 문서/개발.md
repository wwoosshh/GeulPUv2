# 개발

**[English](../docs/development.md)** · [README](../README.ko.md) · [기여 안내(영어)](../CONTRIBUTING.md) · [사용 안내](../사용안내.md) · [용어](용어.md)

소스에서 GeulPU 를 빌드하고 코드를 찾아가는 데 필요한 것입니다 — 앱을 쓰기만 한다면 [사용 안내](../사용안내.md)로 충분합니다. 변경을 제안하는 방법은 [CONTRIBUTING.md](../CONTRIBUTING.md)(영어)에 있습니다. 연구 기록(단계 문서 · 논문)은 [GeulPU 저장소](https://github.com/wwoosshh/GeulPU)에 있고, 아래의 'N단계' 링크는 그곳으로 갑니다.

| 앱 | 36 ~ 39단계 — `GeulPU.exe`(글로 쓴 관리자) + 웹 화면: 모델 찾기(Hugging Face 의 GGUF 전체를 정렬해 둘러보기) · 받기 · 더하기 · 확인, 채팅(모델 파일의 채팅 템플릿 — 0.12.0 부터 서버가 jinja 해석기로 그대로 실행, Qwen3 · MiniCPM5 의 생각 켬 · 끔, R1 은 화면이 R1 프롬프트를 짠다), 자기 진단 · 속도 · 교차검증, 결과 zip, 새 버전 알림. **연구 패널**(38단계 — 토큰마다 확률 · 분기 · 비교 · 점수 · 재현 파일, 로그확률은 계약 5.2) · 영어 화면. 릴리스 zip(1.5 MB)은 태그를 밀면 CI 가 소스에서 패키징한다(초안 — 공개는 사람이). Windows x64 만 — 쓰는 법은 [사용 안내의 설치](../사용안내.md#설치) |
| 층 나누기 | 25단계 — 한 GPU 에 들지 않는 모델을 층으로 나눠 여러 GPU 에(`--나누기 P` · `--장치 a,b,…` · `--예산 GB`). 이 PC 에는 GPU 가 한 장이라 한 장 안의 여러 CUDA 컨텍스트로 에뮬레이션했다: 나눠 돌린 경우 16 개가 나누지 않은 것과 바이트까지 같고, 7B 를 둘로 나눈 생성은 나누지 않은 것의 1.025 ~ 1.029 배(나눈 부분마다 컨텍스트 — 그 차이의 대부분은 한 GPU 에서 컨텍스트를 오가는 에뮬레이션의 값) · 1.002 ~ 1.003 배(컨텍스트 하나). 14B 를 둘로 나눈 것은 12 GB 한 장에 문맥 8192 로 들지 않아 그 경우를 재지 못했다 — 판정 25c 는 통과하지 못함([25단계](https://github.com/wwoosshh/GeulPU/blob/main/문서/25단계.md)) |
| 아직 없는 것 | 실제 여러 GPU 에서의 층 나누기(이 PC 에서는 에뮬레이션뿐), 계약의 손실을 7B 이상의 실제 엔진 출력으로 fp64 참값과 비교(실제로 잰 것은 0.5B — 7B · 14B 는 반올림 자리만 에뮬레이션한 fp64 계산으로 검토했다: llama.cpp 식의 1/3805 · 1/4467, [계약손실검토](https://github.com/wwoosshh/GeulPU/blob/main/문서/계약손실검토.md)), Q2_K · Q3_K · IQ4_XS 밖의 IQ 계열 · Q5_0(실제 72B 의 k-양자화 파일은 ffn_down 이 Q5_0 · Q8_0 이라 아직 돌지 않는다), 다른 MoE(Mixtral · Qwen3-30B-A3B), 애플 GPU 에서의 실행과 재현(NVIDIA 세 세대와 AMD RX 9060 XT 가 비트까지 같다 — [교차검증](../교차검증/), Intel 내장 그래픽은 Vulkan 으로 0.5B 가 같다 — [31단계](https://github.com/wwoosshh/GeulPU/blob/main/문서/31단계.md)), AMD 에서의 속도(RX 9060 XT 의 R1 생성이 RTX 4070 Ti 의 3 배 남짓 — 어텐션이 느리다), Qwen3.5 · Qwen3.6 MoE · Gemma 4 의 Vulkan, 헤드 크기 64 의 작은 llama(Llama-3.2-1B), Phi 등 다른 구조와 Gemma 4 의 E2B · E4B · 26B-A4B · 31B, 서버의 벌점(presence · frequency 는 0 만) · 인증 |

## 소스에서 빌드하기

1. **준비물**: Windows(또는 Linux x86-64 — 아래 4), NVIDIA 드라이버(Ampere 이상) 또는 Vulkan 드라이버. 앱 · 서버는 이것과 글 컴파일러로
   충분하다. 시험은 Python 3.12 + `pip install -r requirements.txt`(numpy).
2. **글 컴파일러와 백엔드**: 글(geul) 저장소를 이 저장소 옆 `../geul-lang-v2` 에 받아 고정 판([시험/글저장소커밋.txt](../시험/글저장소커밋.txt)
   — 글 1.4.0 의 태그 `2g-1.4.0` 커밋. CI · 꾸리기 · 교차검증 기준이 모두 이 커밋이다)으로 맞추고 자체 호스팅 컴파일러를 만든다. PTX · SPIR-V
   백엔드는 이 저장소의 [백엔드/](../백엔드/)에 있고 그 컴파일러로 빌드한다(백엔드가 포함하는 앞단 `self/하강.gl` 은 `GEUL_ROOT` 의 글 저장소에서 온다).
   ```
   git clone https://github.com/wwoosshh/geul-lang ../geul-lang-v2
   cd ../geul-lang-v2
   git checkout $(tr -d '\r\n ' < ../GeulPUv2/시험/글저장소커밋.txt)
   python build.py selfhost 컴파일러
   cd ../GeulPUv2
   mkdir -p 빌드/글
   GEUL_ROOT=../geul-lang-v2 ../geul-lang-v2/build/self_컴파일러.exe 백엔드/PTX/PTX.gl -o 빌드/글/ptx-backend.exe
   GEUL_ROOT=../geul-lang-v2 ../geul-lang-v2/build/self_컴파일러.exe 백엔드/SPIRV/SPIRV.gl -o 빌드/글/spirv-backend.exe
   ```
3. **앱 꾸리기**(릴리스와 같은 것): `앱\꾸리기.ps1 -GeulRoot ..\geul-lang-v2 [-GeulC ..\geul-lang-v2\build\self_컴파일러.exe] -NoZip` 이
   `빌드\앱\GeulPU-<판>\` 에 `GeulPU.exe` · `bin\`(server-cuda · server-vulkan · device-cuda · device-vulkan · diag-cuda · diag-vulkan ·
   kernel-gen · ptx-backend · spirv-backend) · `kernels\` · `web\` · `data\` 를 만들고, 서버 · 생성기 · 백엔드의 SHA-256 을 교차검증 기준과
   비교한다. 모델의 커널 모듈은 앱이 처음 그 모델을 올릴 때 이 GPU 에 맞춰 만든다(데이터 폴더의 `모듈\<판>\`).

   **서버만 띄우기**: 생성기와 서버를 빌드하고, 모델의 모양 · 형식에 맞는 모듈을 만들어 PTX 로 바꿔 서버 옆에 두고 띄운다(모듈이 없으면
   서버가 만들 명령을 알린다). 터미널 실행기는 `엔진/실행기.gl`(`빌드/글/실행기.exe 모델.gguf` — 같은 모듈).
   ```
   mkdir -p 빌드/글
   GEUL_ROOT=../geul-lang-v2 ../geul-lang-v2/build/self_컴파일러.exe 커널/커널생성.gl -o 빌드/글/커널생성.exe
   GEUL_ROOT=../geul-lang-v2 ../geul-lang-v2/build/self_컴파일러.exe 엔진/서버.gl -o 빌드/글/서버.exe
   빌드/글/커널생성.exe qwen2큰 K 3584 28 4 18944 152064 빌드/글/qwen2K_3584x28x4x18944x152064.gl     # Qwen2.5-7B 의 k-양자화 모듈
   빌드/글/ptx-backend.exe 빌드/글/qwen2K_3584x28x4x18944x152064.gl -o 빌드/글/qwen2K_3584x28x4x18944x152064.ptx
   빌드/글/서버.exe 모델.gguf --슬롯 4 --문맥 4096 --포트 8080
   ```
4. **리눅스**: 같은 소스를 글 컴파일러의 리눅스 대상으로 빌드한다(ELF — 가져오는 것은 `libc.so.6` · `libcuda.so.1` 뿐). WSL2 Ubuntu 24.04
   와 네이티브 Ubuntu 22.04(glibc 2.35 — H100 NVL 의 MIG 인스턴스)에서 시험했다. 명령과 겪은 일(NFS 홈의 git)은 [H100.md](H100.md).
   - 앱: `bash 앱/꾸리기.sh <글 저장소> [출력 폴더]` 가 윈도의 `앱\꾸리기.ps1` 과 같은 폴더(`GeulPU` · `bin/` 의 server-cuda ·
     device-cuda · diag-cuda · kernel-gen · ptx-backend · `kernels/` · `web/` · `data/` · `version.json`)와
     `GeulPU-<판>-linux-x64.tar.gz` 를 만든다. `./GeulPU --열지않음` 으로 띄우고 원격이면 SSH 포트 포워딩(`ssh -L 44544:127.0.0.1:44544 …`)으로
     화면을 연다. 자료 폴더는 `~/GeulPU`(`--자료` · `GEULPU_HOME`). 화면 없이 검사 하나: `./GeulPU --검사 쌍 [--빠름]`(재현성 · 쌍 —
     `--check r1|pair [--quick]`) — 결과 폴더와 zip 을 알리고, 모든 문제가 기준과 같으면 끝 코드 0(다름 1 · 끝나지 못함 2 · GPU 없음 3).
     모델 파일은 자료 폴더의 `모델/` 에 둔다(심볼릭 링크도 된다).
   - 체계와 닿는 자리는 [앱/윈도.gl](../앱/윈도.gl) 하나에 모았고, 리눅스 판은 같은 이름의 함수를 둔 [앱/리눅스/윈도.gl](../앱/리눅스/윈도.gl)
     (libc — fork · execv · pthread · mmap, SHA-256 은 글로)이다. 앱은 경로를 `\` 로 잇는다 — 리눅스 판은 경로를 받을 때 `/` 로 바꾼다.
     받기의 망(WinHTTP)은 [앱/받기망.gl](../앱/받기망.gl) 이고, 리눅스 판([앱/리눅스/받기망.gl](../앱/리눅스/받기망.gl))은 아직 받지 않는다
     — 모델은 따로 받아 '모델 추가'로 넣는다. 장치 확인의 CUDA 선언은 [엔진/장치C선언.gl](../엔진/장치C선언.gl)(리눅스 판은 libcuda.so.1).
   - 리눅스에 아직 없는 것: 앱 안의 내려받기 · Vulkan(AMD · Intel — #135) · 저장 장치가 HDD 인지 묻기(문맥 저장소의 '기본'은 켬) · 창 닫기 전의
     저장소 비우기. 관리자가 SIGTERM · SIGHUP · SIGINT 를 받으면 아직 도는 서버 · 도구에 SIGTERM 을 보내고 끝난다.

## 점검 — 커밋마다의 빠른 점검(CI)

[![빠른 점검](https://github.com/wwoosshh/GeulPUv2/actions/workflows/ci.yml/badge.svg)](https://github.com/wwoosshh/GeulPUv2/actions/workflows/ci.yml)

- **빠른 점검**(커밋마다, GPU · 모델 파일 없이 — GitHub Actions 의 Windows · Ubuntu 러너, 5 분 안팎, [시험/빠른점검.py](../시험/빠른점검.py)).
  글 컴파일러는 CPU 프로그램이라 커널 소스 → PTX · SPIR-V 까지는 GPU 없이 만든다: 글 저장소의 고정 판에서 글 컴파일러를 빌드하고,
  그것으로 백엔드 둘([백엔드/](../백엔드/)) · 생성기 · 엔진 프로그램 모두를 빌드하고, 모듈 스물둘(Qwen2 · Qwen3 · Llama 의 모양 · 형식 · 공유32 · 자리하나 · 빠른 계약)을 처음부터
  만들어 소스 · PTX · SPIR-V 를 [시험/모듈해시.txt](../시험/모듈해시.txt) 와 바이트까지 비교한다(커널이 뜻하지 않게 바뀌면 걸린다 — 일부러
  바꾼 커밋은 `--해시갱신`). NVIDIA ptxas(검사에만 — 엔진은 쓰지 않는다)로 SASS(sm_89)까지 만들어 커널마다 레지스터 · 넘침(spill)을
  적는다([시험/SASS넘침.txt](../시험/SASS넘침.txt)). 그 밖에 계약의 CPU 참조 자체 시험([시험/계약자체.py](../시험/계약자체.py)), 커널 변형 표가
  생성기 · 엔진에서 같은가, 실행기 · 서버 · 관리자의 가져오기 표(DLL), 파이썬 문법. 이 PC 에서도 같은 것을 돈다:
  `python -X utf8 시험/빠른점검.py --글 ../geul-lang-v2`.
- **GPU 시험**(손으로): 끝에서 끝의 비트 대조는 계약의 CPU 참조([시험/참조7B.py](../시험/참조7B.py)), 서버의 회귀 시험은
  [시험/서버28.py](../시험/서버28.py) · [시험/로그확률서버38.py](../시험/로그확률서버38.py). 연구 단계마다 돌린 공식 실행 스크립트는
  [GeulPU 의 공식실행/](https://github.com/wwoosshh/GeulPU/tree/main/공식실행)에 있다.
- **GPU 시험 · 재기에 드는 파일**(저장소에는 없다 — `모델/` · `빌드/` 는 git 이 무시한다):
  - 모델(GGUF): 시험과 재기는 GGUF 경로를 인자로 받는다. `재기/*.sh` 는 모델을 환경 변수 `GEULPU_MODELS` 의 폴더(기본 `F:/geulpu-models` —
    이 저장소를 만든 PC 의 것)에서, llama.cpp 를 `GEULPU_LLAMA_BENCH`(기본 그 아래의 `llama-b<판>`)에서 찾는다. 둘 다 ASCII 경로여야 한다
    (llama.cpp 도구가 한글 경로를 못 연다). `재기/MoE/전문가기록.py` 는 llama.cpp 의 DLL 폴더를 `GEULPU_LLAMA` 에서 찾는다.
  - 토크나이저: [시험/머리128.py](../시험/머리128.py) 의 층 0 채팅 질문은 시험에 주는 GGUF 안의 토크나이저를 쓴다 — 따로 받을 것이 없다.
  - wikitext-2: 품질 · 긴 문맥 재기(`시험/품질.py`, `재기/품질2b.sh` · `재기/추측3.py` 등)는 `빌드/wikitext-2/wiki.test.raw` 를 읽는다. llama.cpp 의
    퍼플렉시티 측정과 같은 파일이다 — llama.cpp 저장소의 `scripts/get-wikitext-2.sh` 가 받는 `wikitext-2-raw-v1.zip` 의
    `wikitext-2-raw/wiki.test.raw` 를 그 자리에 둔다(sha256 `173c87a53759e020…`).

## 여러 세션으로 개발하기

여러 작업(사람 · 에이전트 세션)이 같은 저장소와 GPU 하나를 함께 쓸 때 서로 부딪히지 않게 하는 규칙이다. 모델 구조마다의 엔진 코드는 구조
폴더(`구조/<이름>/`)에 있고, 엔진과 앱은 레지스트리(registry — [엔진/구조표.gl](../엔진/구조표.gl) · [구조/등록.gl](../구조/등록.gl))로 그것을
부른다 — 아래 '구조 더하기'.

| 역할 | 하는 일 | 고치는 파일 |
|---|---|---|
| 통합 | main 병합 · 릴리스 · 공유 코어(엔진 · 커널 생성기 · 앱의 공통 부분 · 레지스트리 · CI · 시험의 공통 부분) · 사용자 문서 | 모두 |
| 모델 | 구조 하나를 더하거나 고친다(계약의 절 · CPU 참조 · 커널 · 엔진 연결 · 시험) — 작업 트리 하나 · 가지 하나 | 그 구조의 파일과 등록 한 줄. 공유 코어를 바꿔야 하면 통합 작업에 작은 PR 로 청한다(무엇을 · 왜 · 어떤 시험으로) |
| 질의응답 · 대외 | 설명 · 측정의 해석 · 메일 · 글의 초안 | 코드를 고치지 않는다 |

- **GPU 는 줄을 선다**: GPU 를 쓰는 명령(시험_7B · 서버 · 앱의 시험 인스턴스 · llama.cpp · 커널 변형 시험 · 재기)은 모두
  `python -I -X utf8 시험/GPU줄.py 실행 --이름 "<가지> — <할 일>" -- <명령> [인자 …]` 로 돌린다 — 먼저 선 차례대로 한 번에 하나, 명령이
  띄운 프로세스도 명령과 함께 끝난다. 지금 누가 쥐었는지는 `시험/GPU줄.py 상태`(nvidia-smi 의 그래픽 메모리와 줄 밖의 프로세스도).
  기다리는 동안은 GPU 가 들지 않는 일(계약 · CPU 참조 · 문서)을 한다.
- **검증은 세 층**: ① 커밋마다(몇 분, GPU 없이) — 빠른 점검(CI: 모듈 해시 · 계약 자체 시험 · 빌드). ② 모델 PR 마다(GPU 짧게, 줄을
  서서) — 대표 파일 하나로 [재기/모델검증.py](../재기/모델검증.py), 이 PC 에 들지 않는 모델은 층을 줄인 파일([시험/작은MoE.py](../시험/작은MoE.py)
  처럼)로. ③ 릴리스 · 밤에만(GPU 길게) — Vulkan · 긴 문맥 · 품질 · 공유 메모리 32 KB · 교차검증.
- **모델 하나는 단계마다 PR 하나**: ① 계약 · CPU 참조(GPU 없이) → ② 커널 · 단위 시험(GPU 짧게) → ③ 엔진 · 앱 연결 → ④ 검증 →
  ⑤ 사용자 문서 · 릴리스(통합). 여러 모델이 서로 다른 단계에 있으면 GPU 를 오래 쓰는 ④ 만 겹치지 않게 줄을 서면 된다.
- **사용자 문서는 릴리스 때만**: PR 은 README · 사용안내 · user-guide · 지원 표를 고치지 않는다(통합 작업이 릴리스 때). 사용자에게
  보이는 변경은 조각 파일 하나 — `문서/바뀐것.d/<가지>.md`(꼴은 [`_꼴.md`](바뀐것.d/_꼴.md): 갈래 · 한국어 · `---` · 영어). 릴리스 가지에서
  `python -I -X utf8 시험/바뀐것합치기.py --쓰기` 가 [바뀐것.md](바뀐것.md) 의 '다음 판' 과 [CHANGELOG.md](../CHANGELOG.md) 의 'Unreleased' 에
  넣고 조각을 지운다. 빠른 점검이 조각의 꼴을 본다.
- **병합**: 가지 → PR → CI 통과 → 스쿼시 병합(지금과 같다). main 을 받아 올 때 줄을 더하는 표([시험/모듈해시.txt](../시험/모듈해시.txt) ·
  [시험/SASS넘침.txt](../시험/SASS넘침.txt))는 두 쪽의 줄이 모두 남는다(`.gitattributes` 의 `merge=union`) — 두 쪽이 같은 줄을 고쳤으면
  빠른 점검이 해시가 다르다고 알린다.

### 구조 더하기

GGUF 의 `general.architecture` 하나가 구조 하나다. 엔진의 공통 코드(엔진/엔진.gl · 엔진K.gl · 가중치.gl · 서버몸.gl)는 구조 이름을 보지 않고
지금 구조의 구조표(`현재구조` — 함수 칸 · 값 · 할 수 있는 것)만 부른다. 새 구조는 폴더 하나와 등록 두 줄로 들어온다.

1. **계약 · CPU 참조**(GPU 없이): 계약의 절([계약/계약.md](../계약/계약.md) §4 · [contract.md](../계약/contract.md)), 계약의 CPU 참조
   ([계약/정수계약.py](../계약/정수계약.py)의 함수와 `시험/참조<이름>.py`), fp64 수학 참조, [시험/계약자체.py](../시험/계약자체.py)의 시험.
2. **커널**: 그 구조의 판은 생성기 파일 하나(`커널/생성<이름>.gl`)에, [커널/커널생성.gl](../커널/커널생성.gl)에는 모드 · 포함 · 받지 않는 조합의
   거부 몇 줄. 판마다 CPU 참조와 비트까지(`시험/<이름>판.py`), 모듈 해시의 줄(`--해시갱신`)과 SASS 넘침의 줄(`시험/SASS_WSL.py`).
3. **엔진**: `구조/<이름>/엔진.gl`(가중치가 크면 `가중치.gl` 도)에 구조표 하나 — `기본구조표("<이름>")` 로 공통의 길에서 시작해 다른 칸만
   바꾼다. 칸의 목록과 뜻은 [엔진/구조표.gl](../엔진/구조표.gl) 이 기준이다:
   - 설정 · 모듈: `설정읽기`(메타데이터 → 모양 전역, 받지 않는 파일은 까닭을 알리고 끝냄) · `모듈구조` · `모듈꼬리` · `생성옵션` · `생성모드` ·
     `표시판`(그 구조의 모듈에만 있는 표시 커널).
   - 가중치: `층깔기` · `K층깔기` · `K깔기뒤` · `층올리기` · `K올리기뒤` · `올리기끝` · `K치우침` · `n2이름`.
   - 엔진: `모듈준비` · `K모듈준비뒤`(판 함수), `장치바이트` · `큰할당` · `버퍼잡기`(메모리), `층띄움들`(층들의 띄움 — 블록 레시피),
     `로짓뒤`(로짓 판 뒤 — 소프트캡 등) · `로짓뒤칸`(같은 일을 칸 하나에 — 층 렌즈의 행), 행렬곱(`행렬곱K` · `행렬곱N` · `행렬곱끝손질` · `K끝손질` · `가중인자` · `출력인자` · `K출력띄움` ·
     `K구간` · `K미리고를` · `재기층` · `down판` — 공통 번호 0 … 5, 그 밖은 구조가 정한다), KV(`어텐션층인가` · `캐시층번호` · `캐시층수` ·
     `qkv버폭` · `KV폭`(캐시 층 하나의 위치마다 원소 수) · `KV지수바이트`), 상태(`상태비우기` · `슬롯상태비우기` · `상태해시` · `일감끝`).
   - 할 수 있는 것: `생성그래프` · `표판` · `추측` · `슬롯복사` · `저장소` · `나누기` · `K끝손질판` · `캐시통째` · `되감기한도`(슬롯 캐시를
     되돌려 이어 쓸 토큰 수 — 버퍼잡기 에서 정해도 된다) · `공통어텐션`(공통 어텐션의 칸을 잡는가) · `렌즈됨` · `J렌즈됨`, 앱이 고르는 것 `정밀만` ·
     `벌칸까닭` · `KV8됨` · `F2B` · `공유32됨` · `협력됨` · `먼됨`, 서버가 알릴 `알림글`. 처음에는 좁게(생성 그래프 · 표 판 · 추측 · 슬롯
     사이 복사 · 문맥 저장소 · 층 나누기는 거짓, 정밀만, Vulkan 의 까닭) — 엔진은 공통의 대신 길(행마다 계산 · 행마다 표 걸음)로 돈다.
   - 등록: [구조/등록.gl](../구조/등록.gl) 에 `포함 "<이름>/엔진.gl"` 과 `<이름>구조들등록().` 두 줄(이 파일은 줄 단위로 합쳐진다).
     예: [구조/qwen35/엔진.gl](../구조/qwen35/엔진.gl)(Qwen3.5 · MoE — 거의 모든 칸), [구조/표준.gl](../구조/표준.gl)(qwen2 · qwen3 · llama — 공통의 길).
4. **검증**: 층을 줄인 파일([시험/작은MoE.py](../시험/작은MoE.py) 처럼)로 시험_7B 의 다섯 길과 CPU 참조의 비트(GPU 줄에 서서), 실제 파일은
   [재기/모델검증.py](../재기/모델검증.py) 하나. [시험/구조회귀.py](../시험/구조회귀.py) 에 경우를 하나 더한다 — 공유 코어를 고친 뒤 모든 구조의
   비트를 기준과 견주는 시험이다.
5. **앱**: 받는가 · 모듈 이름 · 커널 생성기 인자 · 할 수 있는 것은 엔진이 낸다(`서버 --모델확인` — [엔진/모델확인.gl](../엔진/모델확인.gl)) — 앱의
   코드를 고치지 않는다. 앱의 모델 목록(`앱/data/models.json`)의 항목과, 새 도구 호출 꼴 · 채팅 틀처럼 서버의 공통 부분이 바뀌면 그것은 통합
   작업에 작은 PR 로.
6. **문서**: 변경 기록 조각(`문서/바뀐것.d/<가지>.md`), 단계 기록은 `구조/<이름>/기록.md`. 사용자 문서 · 지원 표는 릴리스 때(통합).
