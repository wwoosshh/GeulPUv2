## 1. 기능 목록의 형식 — `geulpu-operations/1`

파일은 `앱/data/operations.json`(앱 꾸러미에 함께 들어가, 앱과 단계 C 의 CLI 가 실행 중에 읽는다). 맨 위는
`{"format": "geulpu-operations/1", "result_types": {…}, "operations": […]}`.

| 기능의 필드 | 뜻 |
|---|---|
| `id` | 화면 언어와 상관없는 이름 `묶음.동작`(예: `run.branch` · `debug.record.start`). 기록 · 이벤트 · CLI 가 이 이름을 쓴다 |
| `title` · `description` | `{ko, en}` |
| `status` | `exists`(지금 있음) 또는 `planned`(앞으로 — `stage` 필수, 예: `C` · `실험대 3`) |
| `http` | `{method, path}` — 그 기능이 부르는 경로(앱 API · 서버 API · 기록기로 전달). `planned` 이면 없어도 된다 |
| `params` | `[{name, type, required, default, description{ko, en}}]` — 서버 API 의 GeulPU 필드도 인자로 적는다 |
| `result` | 결과 형식의 이름(`result_types` 의 열쇠) |
| `job` | 오래 걸리는 일인가(참이면 일 번호를 돌려준다 — `/api/job/*`) |
| `records` | 실험 기록에 적는 것(`none` · `run` · `branch` · `score` · `lens` · `comparison` …) |
| `cli` | `{ko, en}` — 명령 이름(예: `{"ko": "실행 분기", "en": "run branch"}`). 단계 C 의 CLI 가 이것으로 만들어진다 |
| `gui` | `{view, note}` — 그 기능이 있는 화면(기능지도의 화면 열). 화면이 아직 없으면 `{"planned": "<단계>"}` |
| `internal` · `reason` | 사용자 기능이 아닌 것(예: `/api/ping` · `/api/hello`) — 까닭 필수. 동등성 점검에서 빠진다 |

`result_types` 는 결과 형식마다 `{gui_view, description{ko, en}}` — 모든 결과 형식에 그것을 보여 줄 화면이 있어야 한다.

**하나의 경로가 GET · POST 로 다른 일을 하면 기능 둘로 적는다**(예: 기록기 설정 읽기 · 쓰기). 앱은 요청 하나를 `앱/관리자.gl` 의
`관리나눠주기` 한곳에서 메서드와 경로로 나눠 처리하므로, B3 의 이벤트도 그 자리에서 낸다.

## 2. 첫 판의 범위

- **앱 API** — 기능지도 2 절의 경로 61 개(메서드마다 하나씩).
- **전달 경로(proxy) 둘** — 기능지도에 빠져 있던 것: `/v1/*`(와 `/tokenize` · `/detokenize` · `/tokenizer_info`)를 추론 서버로, `/llama/*` 를 사용자의
  llama-server 로(llama.cpp 재현의 기록기). 기능지도 3 절에 함께 적는다.
- **서버 API** — 생성(`/v1/chat/completions` · `/v1/completions` · `/v1/messages` · `/v1/responses`) · 점수(echo) · 분기(`step_offset`) · 렌즈(`layer_lens` ·
  `jacobian`) · 토큰화 · 모델 목록 · 건강 확인. 기능지도 3 절의 GeulPU 필드 15 개는 이 기능들의 인자로.
- **화면 밖 기능 다섯과 연구 패널 기록** — `planned`(단계 표시): GPU 없는 재현 확인(`도구/repro_check.py`), 같은 비트 확인(`도구/same_bits.py`),
  Jacobian lens 의 J 파일 맞추기(`도구/jlens_fit.py`), llama.cpp 실행의 설정 반사실, 연구 패널 기록의 앱 API. 요청 필드 `geulpu_tool_errors` 는
  생성 기능의 인자로(화면은 `planned`).
- **실험 기록** — `experiment.*`(만들기 · 목록 · 보기 · 점검)를 `planned`(단계 C)로. 형식은 B2.

## 3. 점검 도구 — `시험/기능목록점검.py`(GPU 없이)

1. 형식: 필드 · 형 · `id` 의 형식, `status` 와 `stage`, `cli` 의 두 언어.
2. 경로 대조: 앱의 글(geul) 코드가 처리하는 `/api/…` 경로(메서드와 함께)와 기능 목록의 경로가 같다 — 코드에만 있는 것 0, 목록에만 있는 것 0.
3. CLI: 내부용이 아닌 모든 기능에 CLI 이름(한국어 · 영어)이 있고, 같은 언어 안에서 겹치지 않는다.
4. 화면: 내부용이 아닌 모든 기능에 `gui` 가 있고, 모든 결과 형식에 `gui_view` 가 있다.
5. 웹 코드: `앱/web/*.js` 가 부르는 `/api/…` 경로가 모두 기능 목록에 있다(화면이 목록 밖의 경로를 부르지 않는다).
6. 인자: 경로를 처리하는 코드 블록이 직접 읽는 요청 키(몸의 JSON 키 · 질의)가 모두 그 기능의 `params` 에 있다.
7. `--자체시험`: 임시 사본에 잘못을 하나씩 넣어 모두 잡는지 본다 — 코드에만 있는 경로 · 목록에만 있는 경로 · CLI 이름 없음 · CLI 이름 겹침 ·
   화면 없는 결과 형식 · 웹 코드가 부르는 목록 밖 경로 · 코드가 읽는데 `params` 에 없는 키.

빠른 점검(`시험/빠른점검.py`)에 단계 하나로 넣는다. 전체 점검 경로(`커널/` · `백엔드/` · `시험/모듈점검.py` 등)는 건드리지 않아 CI 는 빠른 방식 그대로다.

## 4. B1 의 판정(구현 전에 적음)

1. **형식:** `앱/data/operations.json` 이 `geulpu-operations/1` 이고, 점검 도구의 형식 오류가 0 이다.
2. **범위:** 코드의 앱 API 경로 61 개가 메서드마다 모두 목록에 있고 목록의 경로가 모두 코드에 있다(빠짐 0 · 남음 0). 전달 경로 둘, 서버 API 의
   경로 10 개와 GeulPU 필드 15 개가 모두 기능의 경로 · 인자로 있다. 화면 밖 기능 다섯과 연구 패널 기록이 `planned` 로 있다.
3. **동등성 점검:** 3 절의 3 ~ 6 이 모두 통과한다.
4. **자체 시험:** 3 절 7 의 잘못 일곱을 모두 잡는다(7/7).
5. **CI:** 빠른 점검 안에서 GPU 없이 5 초 안에 끝나고, CI 는 빠른 방식 그대로다. 앱 코드와 모듈 해시는 바뀌지 않는다.

## 6. B2 — 실험 기록의 형식과 점검 (설계와 판정, 2026-11-08 확정)

[실험대.md](실험대.md) 2 · 3 절의 형식을 파일로 만든다. 바깥 연구자도 쓰므로 `experiments/` 의 파일 이름과 `experiment.json` 의 키는 영어다.

| 파일 | 무엇 |
|---|---|
| `experiments/README.md` · `README.ko.md` | 실험 기록이 무엇이고, 어떻게 더하고, 어떻게 확인하나 |
| `experiments/index.md` | 실험 목록(실험마다 한 줄) |
| `experiments/experiment.schema.json` | `experiment.json` 의 JSON Schema(`geulpu-experiment/1`). 점검 도구가 이 파일로 확인한다 — 형식의 기준은 이 파일 하나 |
| `experiments/_template/` | 새 실험의 템플릿 — `experiment.json` · `plan.md` · `results.md` |
| `도구/experiment_check.py` | 점검 — 표준 라이브러리만, GPU 없이(바깥 연구자도 돌린다) |

- **필수 필드:** `format` · `id`(폴더 이름) · `title` · `question` · `status` · `created` · `authors` · `geulpu.version` · `models`(모델마다 SHA-256 과
  출처) · `runs` · `criteria`(하나 이상) · `files`(포함 파일마다 경로 · SHA-256 · 바이트).
- **점검:** 스키마, `id` = 폴더 이름, `plan.md` 있음, `status` 가 `done` 이면 `results.md` 있음, `files` 의 해시 · 크기가 실제 파일과 같고 폴더 안의
  파일이 모두 `files` 나 세 문서(`experiment.json` · `plan.md` · `results.md`)에 있음, 폴더를 zip(deflate)으로 압축한 크기 5 MB 이하, `runs` 의
  기록 파일이 `files` 에 있음, `expected.json` 이 있으면 그 실행이 `runs` 에 있음, `index.md` 에 모든 실험 폴더(`_template` 빼고)가 있음.

**B2 의 판정(구현 전에 적음)**
1. 점검 도구가 `_template/` 을 통과시킨다.
2. 잘못 셋 — 포함 파일의 해시 틀림 · 압축 5 MB 넘음 · 필수 필드 빠짐 — 을 모두 잡는다(3/3).
3. CI 의 빠른 점검에서 GPU 없이 5 초 안에 돈다.
4. 앱 코드와 커널은 그대로다.

자체 시험에는 판정 밖의 잘못 셋도 넣는다 — 결과 문서 없음(`done`) · 판정 기준 없음 · `index.md` 에 없는 실험 폴더. 판정에 더하지 않고 결과에 적는다.

**B2 결과 (2026-11-08) — 판정 넷 모두 통과**

| 판정 | 결과 |
|---|---|
| 1. `_template/` 통과 | 통과 — `pass experiments/_template`, `index.md` 도 통과 |
| 2. 잘못 셋을 모두 잡음 | 3/3 — 포함 파일의 바이트 하나를 바꿈(SHA-256 다름) · 압축되지 않는 파일로 압축 크기 5.25 MB · `question` 빠짐 |

| 4. 앱 코드 · 커널 그대로 | 바꾼 것은 `experiments/` · `도구/experiment_check.py` · `.gitignore`(도구 허용 목록에 한 줄) · `시험/빠른점검.py`(단계 하나) · 문서 |

- **판정 밖:** 자체 시험은 잘못 21 가지를 모두 잡는다. 위에 적은 셋(결과 문서 없음 · 판정 기준 없음 · `index.md` 에 없는 폴더)에 더해 점검
  규칙마다 하나씩 — id 가 폴더 이름과 다름 · `plan.md` 없음 · 형식 · 상태 값 · 모델 해시의 모양 · 목록에 없는 파일 · 목록에만 있는 파일 · 크기
  틀림 · 폴더 밖 경로 · 세 문서를 목록에 넣음 · 기록 파일이 목록에 없음 · 실행 id 가 두 번 · 없는 실행에서 분기 · `expected.json` 의 없는 실행 ·
  `index.md` 가 없는 폴더를 링크. 대조군(올바른 실험)과 템플릿은 통과한다.
- **설계에 더한 것:** `--files <폴더>` 가 `experiment.json` 에 붙일 `files` 목록(SHA-256 · 크기)을 출력한다 — 손으로 해시를 적지 않도록.

  없는 JSON Schema 키워드를 쓰면 점검이 멈춘다 — 스키마가 점검하는 것보다 많이 약속하지 않도록.
- **용어:** 템플릿 폴더를 '틀'로 적은 곳(이 문서 · [실험대.md](실험대.md))을 '템플릿'으로 고쳤다([용어.md](용어.md)).

## 7. B3 — 기능 호출의 이벤트 (설계와 판정, 2026-11-08 확정)

명령 창과 화면이 "어디서 온 호출이든" 따라 바뀌도록([앱리디자인.md](앱리디자인.md) §3), 앱이 기능 호출마다 이벤트를 남기고 내보낸다.

- **이벤트를 남기는 호출:** 기능 목록에서 HTTP 방법이 POST 이고 `internal` 이 아닌 기능 — 계산하거나 기록을 바꾸는 기능이다(§3 의 정한 것 2:
  보기 동작은 찍지 않는다). GET(보기 · 상태 묻기)은 남기지 않는다 — 화면이 1 초마다 묻는 `/api/state` 도 여기 든다. 여러 기능이 함께 쓰는
  `/v1/completions` 는 본문으로 가른다: `geulpu.layer_lens` 가 있으면 `run.lens`, `geulpu.step_offset` 이 있으면 `run.branch`, `echo` 가
  참이고 `max_tokens` 가 0 이면 `run.score`, 그 밖은 `run.complete`.
- **이벤트 하나(JSON):** `seq`(앱이 켜진 뒤 1 부터) · `time`(유닉스 초) · `type`(`start` · `end`) · `call`(시작과 끝이 같은 호출 번호) · `op`(기능
  id) · `method` · `path`(쿼리 문자열 없이) · `source`. `end` 에는 `status`(화면 쪽에 보낸 HTTP 상태 — 보내기 전에 끊겼으면 0)와 `ms`(걸린
  밀리초), 응답이 끝나기 전에 화면 쪽이 끊었으면 `client_closed: true`. 요청 본문과 쿼리 문자열은 넣지 않는다 — 인자는 단계 C 에서 기능 목록의 인자
  정의로 더한다.
- **출처:** 요청 머리 `X-GeulPU-Source` — `gui`(웹 코드가 앱으로 보내는 요청마다 붙인다. 다른 사이트로 가는 요청에는 붙이지 않는다) ·
  `python`(파이썬 API). 머리가 없거나 다른 값이면 `unknown`. `cli` 와 AI 세션 이름은 단계 C 에서 더한다.
- **끝의 때:** 바로 답하는 호출은 답을 쓴 직후. 추론 서버로 전달하는 호출(`/v1/*`)은 서버의 응답이 끝났을 때(스트리밍이면 마지막 바이트를 보낸 뒤).
- **내보내기:** `GET /api/events?after=<seq>&wait=<ms>` → `{"events": [...], "last": <가장 새 seq>, "oldest": <남아 있는 가장 오랜 seq>}`.
  `after` 뒤의 이벤트가 있으면 바로, 없으면 `wait`(최대 30000) 동안 기다렸다가 답한다(긴 폴링 — 앱의 HTTP 층에 SSE 가 없다). 앱은 최근 1024 개만
  메모리에 둔다 — 디스크에 쓰지 않고, 앱을 다시 켜면 `seq` 가 1 부터다. `oldest` 가 `after + 1` 보다 크면 그 사이를 놓친 것이다. 기다리는 연결은
  HTTP 스레드를 막지 않는다(그 연결의 답만 미룬다).
- **기능 목록:** `system.events` 를 `exists`(GET `/api/events`, 인자 `after` · `wait`)로 바꾼다. 앱은 켜질 때 `data/operations.json` 을 읽어
  이벤트를 남길 기능의 표를 만든다 — 경로와 기능 id 를 코드에 다시 적지 않는다(`/v1/completions` 를 가르는 네 id 만 코드에 있다).
- **하지 않는 것:** 일(job)의 진행 · 끝 이벤트, 기록 저장 이벤트, 이벤트를 파일로 남기기, SSE, 이벤트에 인자 넣기 — 단계 C 와 E 에서 필요한 만큼.

**B3 의 판정(구현 전에 적음)**
1. 시험 인스턴스에서 POST 기능을 출처 셋(`gui` · `python` · 머리 없음)으로 부르면, 호출마다 `start` 와 `end` 가 하나씩 `seq` 차례로, 같은
   `call` 로 나오고 `op` · `source` · `status` 가 맞다. GET 호출은 이벤트를 남기지 않는다.
2. 작은 모델로 `/v1/completions` 를 네 모양(이어쓰기 · 점수 · 분기 · 렌즈)으로, `/v1/chat/completions` 를 스트리밍으로 부르면 `op` 가 차례로
   `run.complete` · `run.score` · `run.branch` · `run.lens` · `run.chat` 이고, 각 `end` 는 응답의 마지막 바이트가 화면 쪽에 온 뒤에 나온다.
3. 긴 폴링: 이벤트가 없으면 `wait` 뒤(±100 ms)에 빈 목록을 돌려주고, 기다리는 중에 호출이 오면 그 이벤트를 100 ms 안에 돌려준다. 기다리는
   동안 다른 요청은 평소처럼 답한다.
4. 기존 API 응답은 바이트까지 그대로다: 바꾸기 전 앱과 바꾼 앱에 같은 자료 폴더로 같은 요청(답이 시각에 매이지 않는 GET · POST 몇)을 보내 응답이
   같다.
5. 기능 목록 점검과 빠른 점검이 통과한다.

판정 2 는 GPU 를 쓴다 — GPU 줄로, 가장 작은 모델 하나를 한 번 불러서.

- **시험:** 시험 인스턴스(포트 44639 · 임시 자료 폴더)로, GPU 는 GPU 줄로 썼다(판정 2 — 모델 한 번, 9 초).
