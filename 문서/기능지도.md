# 기능 지도 — 앱 리디자인 단계 A (조사, 2026-11-08)

[앱리디자인.md](앱리디자인.md) 의 단계 A. GeulPU 의 기능이 화면 · 앱 API · 서버 API · 명령과 스크립트 가운데 어디서 닿는지를 한 표로 모으고,
연구 과제(사용자 시나리오)를 정한다. 단계 B(기능 목록)의 범위가 이 표다.

- **판정(앱리디자인.md 4 절에 미리 적음): "앱 API 61 개 · 서버 필드 · 스크립트가 모두 표에 있다" — 통과.** 앱 API 61 개(2 절), 서버 경로 10 개와
  GeulPU 필드 15 개(3 절), 명령과 스크립트 13 개(4 절).
- **모은 법:** main `a8118f4` 에서 기계적으로 뽑았다 — 앱 · 엔진의 글(geul) 코드에 적힌 `/api/…` 경로, 웹 코드(`앱/web/app.js` · `eval.js`)에서
  그 경로와 서버 필드를 부르는 함수, 파이썬 API(`도구/pypi/geulpu/api.py`), 도구와 재현 키트의 스크립트, 서버(`엔진/서버몸.gl`)가 읽는 요청 필드.
  "하는 일"은 경로를 처리하는 코드의 주석과 웹 코드의 함수에서 읽었다. 뽑은 `/api/…` 63 개 가운데 둘은 경로가 아니라 뺐다 — `/api/models` 는
  Hugging Face 의 주소(huggingface.co/api/models), `/api/llama` 는 주석 속 그룹 이름이다.
