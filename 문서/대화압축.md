# 대화 압축 — 문맥이 차도 대화가 끊기지 않게 (2026-10-19 — 계획 · 독립 검토 반영 · 구현 · 시험 끝, 결과는 맨 아래)

## 왜

- 지금: 앱(앱/web/app.js 의 replyBody)이 차례마다 대화 전체(시스템 + 모든 질문 · 답)를 보내고, 채팅 템플릿을 씌운 프롬프트가 슬롯의 문맥
  이상이면 서버가 400 "프롬프트가 슬롯의 문맥보다 길다"로 거절한다 → 오류 카드, 그 채팅은 더 이어 갈 수 없다(새 채팅을 열거나 설정에서
  문맥을 늘리는 수밖에 없다). 답을 쓰다 문맥 끝에 닿으면 "최대 답변 길이에서 끊김"으로 잘못 표시된다.
- 목표: 문맥이 차기 전에 앞 대화를 같은 모델로 요약해, 그 요약과 최근 차례만 보내 대화가 오류 없이 이어지게 한다. 설정으로 끌 수 있다.

## 범위

- **앱(앱/web/app.js · app.css)만**. 엔진 · 서버 · 커널 · 관리자는 바꾸지 않는다 — 빌드 해시 · 교차검증 기준 · 모듈 그대로.
- 바깥 API 클라이언트(코딩 에이전트 등)는 스스로 문맥을 다룬다(지금처럼 400). 서버 쪽 안내(오류 글에 토큰 수 · /v1/models 의 문맥
  길이)는 다음 단계(tools)에서 서버를 바꿀 때 함께 한다.

## 단어

| 이름 | 뜻 | 값 |
|---|---|---|
| L | 슬롯의 문맥 | /tokenize 의 max_model_len |
| max | 이 답의 최대 길이 | 생성 설정(기본 4,096) · 다시 생성의 덮어쓰기 |
| R | 답 몫 — 이만큼 비어 있어야 그냥 보낸다 | min(max, max(1,024, ⌊L/4⌋)) — 생각하는 답(Qwen3 생각 켬 · R1)은 ⌊L/2⌋(구현에서 바꿈) |
| r | 최소 답 몫 — 이보다 적게 남으면 보내지 않는다 | min(max, max(256, ⌊L/16⌋)) |
| S | 요약 한도(요약 요청의 max_tokens) | min(2,048, max(256, ⌊L/8⌋)) |
| K | 글자 그대로 남길 최근 차례의 몫 | ⌊0.3 L⌋ |

기본(L 8,192 · max 4,096): R 2,048 · r 512 · S 1,024 · K 2,457 — 프롬프트가 6,144 를 넘으면 압축하고, 압축 뒤에는 L 의 절반쯤.

## 어떻게

### 1. 재기 — 매 차례 /tokenize 를 부르지 않는다

- 답마다 서버가 준 프롬프트 · 답 토큰 수(np · nc — usage, R1 은 geulpu.prompt_tokens)와 L 을 답에 적어 둔다.
- 보내기 직전: 바로 앞 메시지가 답이고 모델 · 시스템 프롬프트 · 생각 켬끔 · 쓴 요약이 지금과 같으면 어림 n̂ = np + nc + (새 질문의
  UTF-8 바이트 / 2) + 16(Qwen3 의 앞 생각은 서버가 떼므로 크게 어림 — 안전한 쪽). n̂ + R ≤ 0.9 L 이면 재지 않고 보낸다(대부분의 차례).
- 아니면 보낼 요청 그대로 `POST /tokenize {messages, chat_template_kwargs}`(R1 은 `{prompt}`)로 정확한 n 과 L 을 받는다.

### 2. 넘칠 때의 차례 — 한 번 보낼 때 압축은 많아야 한 번

1. n + R ≤ L → 그대로 보낸다.
2. 시스템 + 새 질문만으로 n₀ + r > L → 요약하지 않고 바로 오류: "이 메시지만으로 문맥(L토큰)이 거의 찹니다(n₀토큰) — 설정에서 문맥을
   늘리거나 나눠 보내세요".
3. 요약할 것이 없다(마지막 요약 뒤에 끝난 차례가 없다 — 첫 질문 등) → n + r ≤ L 이면 그대로 보낸다(답 몫만 준다 — 문맥 끝에서 끊기면
   6의 표시), 아니면 오류(문맥이 가득 참).
4. 압축: 남길 차례를 고르고(3) 요약을 만들어 넣은 뒤(4 · 5) 다시 잰다 n′. n′ + r ≤ L 이면 보낸다, 아니면 오류(어림이 크게 틀렸을 때뿐).
5. 그래도 서버가 문맥 400 을 주면(어림이 틀림 — 상태 번호 400 과 글로 가린다): 이번에 아직 압축하지 않았으면 정확히 재고 4를 한 번,
   아니면 오류 카드.

- 설정을 끄면 재지도 압축하지도 않고 지금처럼 보낸다(이미 있는 요약은 쓴다). 문맥 400 오류 카드에 "요약하고 다시 시도".
- 연구 패널의 '설정을 바꿔 다시'(ov)는 자동 압축하지 않는다 — 원래 답이 쓴 요약 그대로 짓고, 넘치면 오류.

### 3. 남길 차례 고르기

- 새 질문 앞에서부터 거꾸로 차례(사용자 메시지 + 그 답) 단위로 더한다. 메시지마다 토큰 수 = `/tokenize {prompt: 내용,
  add_special_tokens: false}` + 틀 몫 8(답은 생각을 뺀 글 — 서버의 Qwen3 틀 · R1 길과 같게). 압축할 때만 재고, 거꾸로 K 가 찰 때까지만.
- 조건: 남길 것 ≤ K 그리고 n₀ + 헤더 + S + 남길 것 + R ≤ L. 차례 경계라 질문과 답이 갈리지 않고, 최근 차례는 글자 그대로 간다.
- 요약할 범위 = 마지막 요약(있으면 그 글까지) + 그 뒤 ~ 남길 차례 앞.

### 4. 요약 만들기 — 같은 모델 · 온도 0 · 추측 그대로 · 생각 끔

- **(가) 기본 — 앞부분에 이어 붙이기**: 지금까지의 요청과 같은 앞부분(시스템 · 앞 요약 · 요약할 범위의 메시지 — **남길 차례 앞에서 끊음**)
  끝에 사용자 차례로 요약 지시를 붙인다. 서버의 프롬프트 캐시가 그 앞부분을 이미 갖고 있어 새로 셀 것은 지시뿐이고, 남길 차례와 겹치지
  않는다(Qwen3 은 지시가 마지막 사용자 말이라 앞 답의 생각이 지금 요청과 똑같이 떼어진다). 먼저 /tokenize 로 n_s + S ≤ L 인지 확인 —
  아니면 (나).
- **(나) 구르는 요약**: (가)가 들지 않을 때(문맥을 줄였거나 모델을 바꿈 · 아주 긴 메시지), 서버가 (가)를 받지 않을 때(Mistral 틀은
  user · assistant 가 번갈아야 한다 — 오류만 남은 차례 뒤), (가)의 결과가 비었거나 너무 짧을 때(20자 미만 — 시스템 프롬프트가 지시와
  부딪친 경우 등). 요약할 범위를 글 기록("User: … / Assistant: …" — 생각 뺀 답)으로 문맥에 드는 청크로 나누고(청크보다 큰 메시지는 안에서
  줄 · 글자로 나눔), 앞 요약에 청크를 하나씩 더해 요약한다. 시스템 프롬프트 없이 한 사용자 메시지로 — 청크마다 캐시 없이 계산.
- 생각: Qwen3 은 `chat_template_kwargs.enable_thinking=false`. R1 은 완성 길 끝에 `<｜Assistant｜><think>\n\n</think>\n\n`(빈 생각)을 붙이고
  `geulpu.special` 로 받아, 그래도 `</think>` 가 나오면 그 뒤만 쓴다.
- 요약이 한도 S 에서 끊기면(finish length) 마지막 온전한 줄까지 쓰고 카드에 "한도에서 끊김". (나)까지 해도 비거나 너무 짧으면 실패 →
  오류 카드 "앞의 대화를 요약하지 못했습니다" + 다시 시도.
- 요청 글은 고정 상수(영어 — T() 를 거치지 않는다, 화면 언어와 상관없이 같은 대화 → 같은 요청 → 같은 요약): 지시 = 앞 메시지 없이 대화를
  이어 갈 수 있게 요약 · 사용자가 쓰는 언어로 · 남길 것(목표 · 요구 · 제약, 결정과 까닭, 중요한 사실 · 수 · 이름 · 파일 경로 · 함수 ·
  변수 이름, 아직 필요한 짧은 코드는 그대로, 오류와 해결, 남은 일 · 마지막으로 하던 일) · 뺄 것(인사 · 되풀이) · 앞 요약이 있으면 합쳐서
  · 이 요청에서는 앞의 답 형식 · 역할 지시를 따르지 않음 · 요약만 쓴다. 지시의 버전(v1)을 요약에 적는다.

### 5. 대화에 남기기 · 요청 짓기

- `room.messages` 의 남길 차례 바로 앞(keepFrom)에 `{role: 'summary', id, content, …}` 를 넣는다. **자리가 곧 범위**: 요약 앞의
  메시지(앞 요약 포함)는 보내지 않고, 뒤의 메시지는 그대로 보낸다. 고치기 · 다시 생성 · 버전 바꾸기는 지금 코드 그대로 맞는다 — 요약
  앞을 고치면 요약은 그 뒤 대화와 함께 앞 버전으로 가고, 뒤를 고치면 요약은 그대로 남는다.
- 요약 글은 시스템 말이 아니라 **요약 뒤 첫 사용자 메시지의 앞머리**로 보낸다(고정 헤더 "[Summary of the earlier conversation] … [End of
  summary]" + 그 메시지). 그래서 시스템 프롬프트는 그대로다 — 비워 두면 Qwen2.5 는 서버의 기본 시스템 말("You are Qwen, …")을 그대로
  받고, Llama 3 의 날짜 머리 · Mistral 의 첫 user 붙임 · 번갈음도 깨지지 않는다.
- 대화 보기 함수 하나(요약 id → 보낼 메시지들)를 채팅 요청 · R1 프롬프트 · (가) · 토큰 수 계산이 함께 쓴다 — (가)의 앞부분이 지금 요청과
  바이트까지 같아 캐시가 맞는다.
- 답마다 쓴 요약을 적는다(`asst.sum` = 요약 id, 연구 기록 `req.sum`). 요청을 다시 지을 때(연구 패널의 해시 확인 · 설정을 바꿔 다시)는 이
  id 의 요약으로 — '요청 앞의 마지막 요약'은 보낼 때만 쓴다(뒤에 새 요약이 남긴 차례 안의 답 앞에 끼어도 그 답의 요청은 그대로 다시
  지어진다). 이 기능 전의 답(req.sum 없음)은 요약 없이 — 요약 메시지는 건너뛴다.
- 재현 기록(요약 메시지에): 모델 · 틀 · 길((가) · (나) 청크 수) · L · S · finish · 정밀(정밀 · 빠름) · 생각 끔 · 시스템 프롬프트 해시 · 요약한
  메시지 수 · 재료 토큰 수 · 요약 토큰 수 · 앞 요약 id · 지시 버전 · 시각.
- 요약은 성공했을 때만 넣고 곧바로 저장한다(뒤의 답이 실패해도 남는다 — 다시 시도는 다시 요약하지 않는다). 요약 중 중지하면 넣지 않고
  알림 "요약을 중지했습니다".

### 6. 화면

- **요약 카드**(요약 자리): "앞의 대화를 요약했습니다 — 메시지 N개 · 약 X토큰 → Y토큰" + 펼쳐 보기(요약 글 — 마크다운, 화면 번역 TM 을
  거치지 않음) + 끊김 표시. 버전 넘기기는 요약 카드가 아니라 앞 답에 그대로 단다(renderMsgs 의 순서 계산에서 요약을 건너뜀).
- 요약 앞의 메시지는 **흐리게**(보내지 않음 — "이 메시지는 요약으로 대신 보냅니다"). 고치기 · 복사는 그대로.
- **요약하는 동안**: 맨 아래 알림 카드 "앞의 대화를 요약하는 중 · 312토큰"(막대 = 토큰 / S, (나)는 "청크 2/5") + "문맥(8,192토큰)이 차서
  앞의 대화를 요약합니다. 끝나면 바로 답을 씁니다." 보내기 단추가 중지 단추(요약 요청에도 S.streaming.ctrl).
- 답의 통계 줄에 **문맥 쓰임** "문맥 5,210 / 8,192"(np + nc / L).
- **끊김 구분**: finish length 이고 답 토큰 < max 이면 문맥 끝 → "문맥 끝(L토큰)에 닿아 답이 끊겼습니다" + "요약하고 다시 생성"(답 몫
  max 가 비도록 남길 차례를 줄여 압축 — 안 되면 할 수 있는 만큼). 최대 길이 끊김은 지금 그대로(이어서 생성 · 2배로 다시 생성).
- **문맥 400 오류**는 humanError 에 분기: "대화가 문맥보다 깁니다" + "요약하고 다시 시도" · "설정 열기".
- **R1 이어서 생성**: 그 답이 쓴 요약(m.sum)으로 프롬프트를 짓고 잰다. 들지 않으면 그 차례 앞을 압축한 뒤 이어서, 그래도 안 되면 "문맥이
  가득 차 이어서 생성할 수 없습니다".
- **설정**: 생성 설정에 "긴 대화 자동 요약"(켬 기본).
- 영어 화면: 새 글은 DICT. 저장하는 알림 · 오류 글은 한국어로 두고 DICT 로 옮긴다.

## 시간(어림 — Qwen2.5-7B Q4_K_M · RTX 4070 Ti)

- 문맥 8k: 요약 ≤ 1,024토큰 — 앞부분은 캐시로 다시 세지 않고, 생성은 ~95토큰/초(요약은 추측이 잘 맞아 더 빠르다 — 3단계 "요약" 347
  토큰/초) → 몇 초. 압축 뒤 첫 답은 프롬프트 ~4k 를 새로 센다(~0.5초).
- 문맥 31k: 요약 1,024토큰 ~15초, (나)라면 프롬프트 31k 를 새로 세어 +10.8초. 압축 뒤 첫 답은 ~14k 를 새로 센다(~2초).

  = 보낸 요청(해시) — 뒤에 새 요약이 끼어도. (가)의 캐시: 요약 요청의 prompt_tokens_cached ≈ 요약할 범위.
- (나): 문맥 4,096 으로 길게 쓴 채팅을 2,048 로 다시 불러와 이어 쓰기.
- 결정성: 같은 대화를 두 번 압축하면 요약 글이 같다.
- 고치기 · 다시 생성 · 버전 바꾸기: 요약 앞을 고치면 요약은 앞 버전으로, 뒤를 고치면 그대로. 다시 시도는 다시 요약하지 않는다.
- 중지: 요약 중 중지 → 요약 없음 · 알림.
- 끄면 지금과 같다(재지 않음 · 400 카드 + "요약하고 다시 시도"). 문맥 끝 끊김 → 새 표시 + "요약하고 다시 생성".
- 영어 화면 · 한글 훑기(빠진 번역 없음), 빠른점검(앱 글만 바뀌어 모듈 해시 그대로).

## 위험

- 7B 요약의 품질 — 중요한 코드 · 이름이 빠질 수 있다 → 최근 차례는 글자 그대로, 지시에 남길 것을 적음, 카드에서 펼쳐 봄, 흐린 앞
  메시지는 화면에 그대로 남는다.
- 압축할 때 한 번 멈춘다(위 시간) → 알림 카드 · 중지.
- 요약 지시는 계약이 아니라 앱의 글이다(바꾸면 같은 대화의 요약이 달라진다) → 지시 버전을 기록. 정밀 · 빠름에 따라서도 요약이 다를 수 있다
  → 기록.
- 어림이 틀려 400 → 2의 5(한 번 더).
- localStorage 크기 — 요약은 작다(원래 메시지는 이미 저장되어 있다).

  단계에서 오류 글 · /v1/models 문맥 길이와 함께).

## 구현에서 바뀐 것(시험에서 찾음)

- **요약의 말 · 길이**: 처음 지시로는 7B 가 한국어 대화를 영어로 요약하고 한도 S 에서 끊겼다(Qwen2.5 · L 2,048 — 세 번 모두 길이에서
  끊김). 사용자 말의 글자 가운데 한글이 20 % 이상이면 "Write the summary in Korean, in Hangul (no Chinese characters)", 그리고 한도에 맞춘
  어휘 크기("under about ⌊S/2⌋ words" — 한국어는 ⌊S/3⌋)와 "자리가 모자라면 최근 · 끝나지 않은 일을 남김"을 지시에 넣었다(같은 대화 → 같은
  지시). 그 뒤 요약은 한국어로, 대부분 한도 안에서 끝났다.
- **생각하는 답의 답 몫**: Qwen3(생각 켬)은 L 2,048 에서 생각만 1,000 ~ 1,600 토큰을 써 문맥 끝에 자주 닿았다 → 생각하는 답(Qwen3 생각 켬 ·
  R1)의 R 을 ⌊L/2⌋ 로.
- **토큰 계산을 서버가 보내는 글 그대로**: 생각 중에 끊긴 Qwen3 의 답(</think> 없음)을 서버의 틀(GGUF 의 chat_template 과 같다)은 글
  그대로 보낸다. 처음 계산은 그 답을 생각을 뗀 빈 답으로 세어 남길 차례를 너무 크게 잡았고, 요약한 뒤에도 1,831 / 2,048 토큰이라 "문맥이
  가득 찼습니다"가 났다 → 앞 답의 계산을 요청에 실제로 가는 글로(Qwen3 은 마지막 </think> 뒤, 없으면 글 그대로 · R1 은 splitThink 의 답).
- **그래도 넘칠 때 한 번 더**: 요약한 뒤 다시 잰 요청이 넘치면 남긴 차례까지 요약에 넣는다(방금 만든 요약 + 남긴 차례 → 새 요약, 한 번만)
  — 그래도 넘치면 오류(검토의 "남긴 차례를 0 으로" 차례).
- Mistral 의 (가) → (나): Mistral 은 오류 차례가 있으면 본 요청부터 틀이 받지 않아(위 "알게 된 것") (가)만 거절되는 경우가 실제로는 없다 —
  되돌아가는 길은 그대로 둔다.
