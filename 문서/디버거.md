# 디버거 — 로컬 모델을 만들고 쓰는 사람의 디버거 엔진 (계획 · 1단계 · 엔진 갱신 2026-10-20)

## 왜

- **목표(사용자, 2026-10-20)**: 로컬 AI 를 만들고 쓰는 연구자를 돕는 디버거 엔진 — PyTorch 등에서 GGUF 를 만들고, GeulPU 에서 돌리며 모델을
  시험하는 공간. 문맥 저장소의 다음 1(기록 · 재생 · 분기)을 이 목표의 1판으로 짠다.
- **GeulPU 만의 바탕**: 디버거는 "같은 실행을 다시 볼 수 있음" 위에서만 선다. GeulPU 는 같은 입력이면 채우는 길(슬롯 · 다른 슬롯 · 문맥
  저장소) · 일괄 · CUDA ↔ Vulkan(정밀 모드)이 달라도 같은 비트이고, 뽑기도 씨앗 · 걸음 번호로 정해진다.
- **다른 곳에서는 생성한 셈과 분석하는 셈이 다르다**: 같은 모델 · 같은 토큰열인데 llama.cpp 와 GeulPU 의 다음 토큰 1 위가 20 곳 중 1 ~ 2
  곳 달랐다(③a — 문서/긴문맥.md). llama.cpp 는 앞부분 캐시만으로 에피소드의 37 ~ 82 % 가 갈라진다는 보고가 있다(arXiv 2609.04748 —
  2026-10-16 확인). 에이전트 재생 도구(agentrr · AgentReplay · Rewind)는 기록한 글을 다시 틀 뿐 다시 셈하지 않는다(2026-10-19 확인).
- **이미 있는 것**: 연구 패널(답 하나 — 관찰 · 개입(갈래) · 비교 · 점수 · 재현 캡슐 · 내보내기), 서버 API(`geulpu.logit_hash` ·
  `prompt_tokens` · `step_offset`(갈래의 난수) · `echo` / `echo_from`(같은 토큰의 로그확률 — 생성과 비트까지 같음) · `logprobs` 20 · `record`),
  문맥 저장소(되풀이되는 앞부분을 다시 셈하지 않음 — 재생이 빠르다), GPU 없는 확인(도구/캡슐확인.py — 계약의 CPU 참조).
- **빠진 것**: "답 하나"를 넘어 **실행**(요청 여럿 — 에이전트 세션 · 시험 묶음) 단위의 기록 · 재생 · 갈래 · 견주기, 그것을 남기고 옮기는
  파일, 스크립트로 부르는 길. 연구 패널의 기록은 지금 브라우저 안에만 있다.

| 사람 | 하는 일 | 1판이 주는 것 |
|---|---|---|
| 모델을 만드는 사람(미세조정 · 양자화 · 병합 → GGUF) | 내 모델이 기준 모델과 어디서 · 얼마나 다르게 답하나, 양자화가 무엇을 바꿨나 | 같은 시험 묶음을 두 모델로 돌려 요청마다 처음 갈라진 걸음, 같은 답을 두 모델로 점수 매긴 로그확률 차 |
| 로컬 에이전트를 만들고 쓰는 사람 | 에이전트가 왜 그 도구를 불렀나 · 왜 틀렸나 | 세션을 비트까지 다시 돌리고, 아슬아슬한 걸음 · 도구 호출 직전에서 멈춰 보고, 다른 토큰 · 다른 도구 결과로 갈라 보기 |
| 행동을 연구하는 사람 | 드물게 나온 행동의 재현, 반사실 실험 | 씨앗과 걸음 번호로 같은 뽑기까지 재현, 한 곳만 바꾼 갈래(차이는 오직 그것에서) |

## 1판 범위 — 실행 단위의 기록 · 재생 · 갈래 · 견주기

1. **실행 파일**(JSONL): 머리 — 모델 sha256 · 파일 이름 · 계약(정밀 · 빠른) · GeulPU 판 · 서버 빌드 해시 · 모듈 해시 · 문맥 · 슬롯 · YaRN ·
   장치, 그리고 요청마다 한 줄 — 받은 요청 · 프롬프트 토큰(채팅 틀 뒤) · 씨앗 · 뽑기 설정 · 나온 토큰 · 걸음마다 로짓 해시 · 끝 까닭 · 시간 ·
   캐시가 깨진 자리. 로그확률 · 상위 k · 엔트로피는 담지 않고 필요할 때 다시 셈한다(메아리 점수 — 생성과 비트까지 같다).
2. **기록**: (가) 앱의 /v1 을 지나는 요청을 실행 하나로 적는다 — 디버거의 '기록 시작 · 멈춤'(기본 끔). 에이전트 · lm-evaluation-harness ·
   스크립트 무엇이든. (나) 시험 묶음(JSONL — 채팅 요청 여럿, 씨앗을 정함)을 돌려 실행 하나로.
3. **재생**: 실행을 지금 불러온 모델로 다시 돌려 요청 · 걸음마다 해시를 견준다 — 모두 같음, 또는 처음 다른 곳. 모델 · 판 · 계약이 다르면
   돌리기 전에 머리에서 알린다. 문맥 저장소가 되풀이되는 앞부분을 빠르게 한다.
4. **들여다보기 · 멈춤점**: 실행 안의 요청 하나를 연구 패널의 관찰로(걸음마다 확률 · 순위 · 여유 · 상위 10). 실행 전체에서 멈춤점을 찾는다 —
   여유 < δ(아슬아슬), 확률 < p(뜻밖의 뽑기), 도구 호출의 시작.
5. **갈래**: 요청 r 의 걸음 k 에서 다른 토큰을 골라 같은 씨앗 · 걸음 난수로 잇거나, 요청을 고쳐(도구 결과 · 시스템 프롬프트 · 사용자 말)
   다시 생성해 원래와 견준다. 갈래는 실행 파일에 가지로 남는다.
6. **견주기**: 실행 A 와 B(같은 요청열 — 다른 모델 파일 · 양자화 · 설정 · GeulPU 판) — 요청마다 같은가 · 처음 갈라진 걸음, A 의 답을 B 로
   점수(같은 토큰의 로그확률 차 — 걸음마다), 묶음 요약(갈라진 요청 수 · 갈라진 걸음의 분포 · 로그확률 차의 합).
7. **옮기기**: 실행 파일을 내보내 다른 GeulPU(같은 판 · 같은 모델 sha256)에서 재생 — 비트까지 같다. 작은 실행은 GPU 없이 계약의 CPU
   참조로(도구/캡슐확인.py 를 실행으로 넓힌다).
8. **스크립트 길**: 앱 API(실행 목록 · 기록 시작/멈춤 · 시험 묶음 · 재생 · 갈래 · 견주기 — `/api/debug/…`)와 표준 라이브러리만 쓰는 파이썬
   도구(도구/디버거.py) — 연구자의 노트북 · CI 에서 부른다.
9. **화면**: 앱의 '디버거' — 실행 목록, 실행(요청 표: 상태 · 갈라짐 · 멈춤점), 요청(연구 패널의 관찰 · 개입 그대로), 견주기(A · B 나란히).
   영어 사전 함께.

**1판에서 하지 않는 것**: 엔진의 새 기능(필요한 API 는 이미 있다 — 다만 1단계에서 찾은 엔진의 비효율 셋은 엔진에서 고쳤다(사용자
2026-10-20 — 아래 '엔진 갱신')), 기울기(기여도 · SAE · 회로 — PyTorch 의 몫),
층 안의 값(로짓 렌즈 · 활성값 — 2판), F16/BF16 GGUF · 새 구조 · 대량 처리량(3판), 이름 붙인 상태 · 붙였다 떼는 검토(에이전트 여럿 —
따로).

## 그다음 — "PyTorch → GGUF → GeulPU 에서 시험"

- **2판 — PyTorch 다리**: (가) 변환 · 양자화 검사 — HF 모델(PyTorch)과 GeulPU 에 같은 토큰열을 넣어 로그확률을 견준다(위치마다 KL · 첫째
  일치 · 크게 갈라진 자리 — "내 GGUF 가 원래 모델대로 도나"). (나) 층마다의 로짓 렌즈 · 잔차 흐름 내보내기(numpy · safetensors — SAELens
  등으로 넘김) — 계약에 '읽어 내기' 칸, 엔진 변경.
- **3판 — 만든 그대로의 모델**: F16/BF16 GGUF(변환 직후의 파일), 구조 늘리기(Gemma 처럼 공개 SAE 가 많은 것), 시험 묶음의 처리량.
- 차례(사용자 2026-10-20): 디버거 1판 → ③b(8 비트 KV) → 그다음은 그때 정한다.

## 맞음 · 판정(미리 정함)

1. **기록 → 재생**: Qwen Code 로 앱에서 기록한 실제 세션(작업 셋)과 시험 묶음(요청 50 — 온도 0 과 온도 0.7 · 씨앗)을 다시 돌리면 모든
   요청 · 걸음의 토큰 · 로짓 해시가 같다(빠른 모드 CUDA). 정밀 모드는 CUDA 에서 기록하고 Vulkan 에서 재생해도 같다.
2. **옮기기**: 실행 파일을 새 자료 폴더의 다른 앱(다른 기계의 흉내 — 같은 판 · 같은 모델)으로 옮겨 재생해 같다. 머리가 다르면(모델 sha256 ·
   계약 · 판) 재생 전에 알린다.
3. **갈래**: 아슬아슬한 걸음에서 대안 토큰으로 갈래 — 앞 걸음은 원래와 비트까지 같고, 같은 갈래를 다시 돌려도 같은 비트.
4. **견주기**: 같은 시험 묶음을 Qwen2.5-7B Q4_K_M · Q8_0 · Qwen2.5-Coder-7B Q8_0 로 — 요청마다 처음 갈라진 걸음과 같은 답의 로그확률 차,
   견주기를 다시 해도 같은 보고.
5. **기록 비용**: 기록을 켜도 요청 시간이 1 % 넘게 늘지 않는다.
6. **CI**: GPU 없이 실행 파일 형식 · 견주기 셈을 파이썬 참조와(도구/디버거.py 의 시험).

## 위험

- 범위가 커지기 쉽다 — 1판은 엔진에 새 기능을 넣지 않는 선에서 끝낸다(찾은 비효율은 엔진에서 고친다 — 아래).
- 기록은 대화 내용을 담는다 — 자료 폴더에만, 기본 끔, 지우기 단추.
- 재생은 같은 GeulPU 판 · 같은 모델 · 같은 계약에서만 비트가 같다 — 커널이 바뀐 판이면 다를 수 있어 머리에서 먼저 알리고, 옛 판 꾸러미로
  재생하게 안내한다.
- 연구자의 수요는 아직 확인하지 않았다 — 1판 뒤 짧은 데모로 반응을 본다(밖에 올리는 것은 사용자 허락 뒤).

## 1단계 결과 (2026-10-20)

**만든 것**

- **실행 기록**(`앱/디버거.gl`): 기록 중이면 /v1 의 생성 요청에 `geulpu: {logit_hash, prompt_tokens}` 를 넣어 보내고(이미 있는 geulpu
  객체에는 그 안에 덧붙인다 — 맨 위 객체를 훑어 메시지 글 안의 같은 글자에는 걸리지 않는다), 응답이 끝나면 실행 파일

  서버를 올리는 때가 많다(Qwen Code 실행 도구가 그랬다). 머리에는 앱 판 · 커밋 · 모델 · 서버 설정과 빌드(`build`: 그 층의 서버 실행 파일
  sha256 · 불러온 모듈과 그 sha256)가, 요청 줄마다 그 요청을 셈한 서버(`server`: 모델 sha256 · 층 · 계산 방식 · 문맥 · YaRN 배)가 있다. 흘림이면 geulpu 가 든 끝 사건을 `response` 로, include_usage 의 사용량 조각은

## 엔진 갱신 (2026-10-20)

사용자: "엔진 자체가 비효율적인 문제가 있으면 엔진의 업데이트로" — 1단계에서 찾은 셋을 엔진에서 고쳤다.

1. **JSON 수 풀기 — 제곱 → 한 번 훑기**(`엔진/제이슨.gl`): 수마다 글(geul) 표준 라이브러리의 `문자열_자르기` 로 수의 글을 떼었는데, 이
   함수는 원본의 처음부터 끝(0)을 찾아 훑는다(끝을 넘어 읽지 않게 하는 안전장치 — 부를 때마다 앞의 글 전체). 수가 많은 JSON 은 제곱으로
   느렸다. 범위를 이미 아는 자리라 그 바이트만 복사한다. 서버도 같은 풀기로 요청을 읽는다 — 토큰 18,414 개를 배열로 보낸
   /v1/completions(103 KB, 캐시가 다 맞음)가 **742 ms → 17 ~ 30 ms**(서버의 첫 토큰은 13 ms 그대로). 토큰 배열 프롬프트 · 점수
   매기기(echo) · 디버거 2단계의 갈래가 이 길을 쓴다.
2. **문맥 저장소 색인 읽기**(`엔진/저장소.gl`): 색인 줄마다 같은 함수 — 줄 수의 제곱이었다. 같은 방법으로.
3. **로짓 해시를 다음 GPU 걸음 뒤로**(`엔진/서버몸.gl` — 38f 의 로그확률 겹치기와 같은 꼴): 생성걸음이 해시를 묻는 일감의 행을 그
   슬롯의 해시대기 칸(표최대 행 · 로짓버퍼처럼 고정 메모리 — 슬롯마다 처음 쓸 때 한 번 만든다)에 바로 내리고(베끼기 없음), 해시는 다음
   생성걸음이 그래프를 띄운 뒤와 끝내기가 차례대로 셈한다. 해시의 정의(FNV-1a 64 — 32 비트 낱말)는 그대로다. 처음에는 칸을 일반
   메모리로 잡아 행을 내리는 것이 느렸다(짧은 답에서 탐욕 요청마다 +11.7 ms · 뽑기 +4.9 ms — 흘림 끔으로 요청의 칸을 하나씩 바꿔 잼).

값은 그대로다 — 푼 수 · 행 · 해시의 차례가 같다. 확인: 옛 서버로 기록한 위의 실행 여섯을 새 서버로 재생해 모두 같음(미뤄 셈한 해시가 옛
서버의 것과 걸음마다 같다), 교차검증(R1 32 문제 — CUDA 32/32, Vulkan 빠른 확인 — 협력 행렬 16x16x32 · 기본 모듈 모두 기준과 같음),
빠른 점검 통과(모듈 해시 그대로 — 커널 · 생성기는 바뀌지 않았다). 서버 실행 파일의
해시만 바뀌어 교차검증 기준(교차검증/expected.json)의 server_r1 · server_r1_vulkan 을 새로 적었다.

글(geul) 표준 라이브러리의 `문자열_자르기` 는 그대로 두었다(처음부터 훑는 것이 안전장치다). 범위를 아는 곳에 쓸 '범위를 받는 복사'를
언어에 둘지는 언어 쪽 일로 남긴다.
