# llama.cpp 실행의 비트 재현 — 1단계: 생성 걸음(CUDA)

이 문서는 단계의 계획과 판정 기준을 결과보다 먼저 적는다. 결과가 나오면 상태 칸만 고친다.

## 목적

엔진을 바꾸지 않은 llama.cpp 의 실행 하나를 GeulPU 의 GPU 커널로 비트까지 다시 계산한다. 1단계는 생성 걸음(토큰 하나)의 커널을
글(geul) 언어로 만들어 RTX 4070 Ti(CUDA)에서 돌린다.

- 앞선 일: CPU 참조 구현(Python, GeulPU 밖 — `E:\geulpu-work\xreplay`)이 같은 실행을 프롬프트 토큰만으로 처음부터 비트까지 다시
  계산했다(2026-11-05, 프롬프트 2,548토큰 + 생성 2걸음, 값 4,972,032개 불일치 0). 이 단계의 커널은 그 참조의 연산 순서를 그대로 옮긴다.
- 대상(고정): llama.cpp b12008 공식 Windows CUDA 13 빌드 · RTX 4070 Ti(sm_89, SM 60) · Qwen3.5-9B Q4_K_M ·
  `llama-server -np 1 -fa on --no-cache-prompt --cache-ram 0 -c 8192 -ngl 99`, 온도 0.

## 원리

- llama.cpp 의 CUDA 커널은 `-use_fast_math` 로 빌드됐다: 짧은실수 연산은 비정규수를 버리고(.ftz), 나눗셈 · 역수 · 제곱근 역수 · 지수 ·
  로그 · 사인 · 코사인은 GPU 의 근사 명령(MUFU)이다. 컴파일러가 곱셈과 덧셈을 FMA 로 합친 자리는 SASS 에서 읽었다.
- 재현 커널은 같은 PTX 근사 명령을 쓰고, FMA 의 자리를 `곱해더하기` 로 정확히 둔다(GeulPU 의 PTX 뒷단은 `mul.rn` · `add.rn` 을
  내므로 ptxas 가 합치지 않는다). 더하는 차례(워프 butterfly · 블록 합 · 병렬 블록의 합치기)도 llama.cpp 그대로다.
- 가중치는 GGUF 파일의 블록 그대로 장치에 둔다(llama.cpp 의 MMVQ 가 읽는 바이트와 같다).
- GeulPU 의 정밀도 계약 · 기존 모듈 · 출력 비트는 바꾸지 않는다. 재현 모듈은 따로 만든다.

## 1단계에 더하는 것

| 자리 | 무엇 |
|---|---|
| `백엔드/PTX/PTX.gl` | 근사 명령 내장 여섯: `근사역수`(rcp.approx) · `근사제곱근역수`(rsqrt.approx) · `근사로그2`(lg2.approx) · `근사사인` · `근사코사인`(sin · cos.approx), 곱하기 없는 `근사2지수`(ex2.approx), 그리고 0 쪽으로 반올림하는 덧셈 `영쪽더하기`(add.rz — llama.cpp 의 softplus 가 부르는 log1pf 의 한 줄). 기존 모듈의 PTX 는 바뀌지 않는다 |
| `커널/생성라마.gl` · `커널/커널생성.gl` | 재현 모듈의 생성기와 모드 `라마재현`(별칭 `llama-replay`) |
| `엔진/라마재현.gl` | 재현 호스트: GGUF 의 가중치 블록을 올리고, 기록된 상태에서 생성 걸음을 이어 가며 로짓을 파일로 낸다 |
| `시험/라마재현판.py` · `시험/라마재현.py` | 커널마다 기록(llama.cpp 의 노드 값)과 비트 대조, 끝에서 끝의 로짓 대조 |
| `시험/모듈해시.txt` · `시험/모듈점검.py` | 재현 모듈의 행 — CUDA 만(SPIR-V 뒷단은 근사 명령을 모른다 — 3단계)이라 SPIR-V 칸은 "-" |

생성 걸음의 커널(llama.cpp 의 이름): q8_1 양자화(`quantize_q8_1`) · 행렬-벡터 곱(`mul_mat_vec_q`, Q4_K · Q5_K · Q6_K · Q8_0) ·
RMSNorm(`rms_norm_f32`, 블록 1024 · 128 · 32) · 원소별 연산(SiLU · sigmoid · softplus · 곱 · 덧셈) · 합성곱(`ssm_conv`) ·
gated delta net 한 걸음(`gated_delta_net_cuda`) · RoPE(`rope_multi`, IMRoPE) · KV 캐시 쓰기(f16) ·
flash attention vec(병렬 블록 7 + 합치기) · 토큰 임베딩(CPU 의 `get_rows` 와 같은 값 — 곱이 정확해 장치에서 계산해도 같다).
