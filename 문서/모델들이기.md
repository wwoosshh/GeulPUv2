# 모델 들이기 (0.12.0 12-G3)

0.12.0 의 일반화([0.12.0.md](0.12.0.md)의 계획 바꿈) 셋째 단계. 새 GGUF 파일을 앱의 모델 목록에 넣기 전의 확인 — 12-1 · 12-2 에서 작업
폴더마다 스크립트를 따로 짜서 차례로 돌린 것 — 을 명령 하나(`재기/모델들이기.py`)로 묶는다.

## 왜

- 12-2 에서 모델 아홉을 넣을 때 비트(시험_7B · 긴 문맥 · 추측), CPU 참조, 품질(재기/품질2b.sh 에 모델 줄 더하기), 채팅 글 대조, 토큰 대조,
  꾸린 앱의 채팅 · 도구 호출 · Vulkan 을 저마다의 일회용 스크립트로 돌렸다. 모델마다 모양 인자 · 모듈 이름 · 모드를 손으로 적으니 틀릴 수
  있고, 앱이 실제로 쓰는 모듈과 어긋날 수 있다(앱의 정밀 CUDA 모듈은 1.0.0 1-7 부터 `--먼`, 8비트 KV · 빠른 어텐션은 KV8됨 모델에만).
- 12-3(Qwen3.5) 뒤로 받는 모델이 늘수록 같은 확인을 되풀이한다. 사람은 '못 미침' 과 목록에 들어갈 설명만 보면 되게 한다.

## 사용

```
python -X utf8 재기/모델들이기.py <모델.gguf> --작업 <폴더> --앱 <꾸린 앱 폴더> --토큰라마 <llama.cpp 폴더> --품질라마 <llama.cpp b11719 폴더>
    [--위키 <wiki.test.raw>] [--저장소 <Hugging Face 저장소>] [--단계 머리,비트,…] [--포트 44651] [--앱자료 <폴더>]
```

- 앱: `앱\꾸리기.ps1 -GeulRoot <글(geul) 저장소> -Out <폴더> -NoZip -AllowHashChange` 로 꾸린 폴더(`GeulPU.exe` 가 있는 곳). 도구가 임시
  자료 폴더 · 다른 포트로 켜고 끈다 — 사용자의 앱 · 자료는 건드리지 않는다.
- `--토큰라마`: llama.cpp 최신 공식 판의 폴더(llama-tokenize). `--품질라마`: 품질의 잣대 b11719(2b단계부터 같은 판 — 재기/품질2b.sh 와 같다).
- `--위키`: wikitext-2 의 wiki.test.raw(기본 `빌드/wikitext-2/`). WSL 의 Ubuntu-24.04 에 jinja2(채팅 템플릿의 참조).
- 모델 파일과 llama.cpp 폴더는 ASCII 경로(llama.cpp 도구가 한글 경로를 열지 못한다), 모델과 작업 폴더는 SSD 에. 품질 단계는 작업 폴더의
  디스크에 50 GB(로짓)가 비어 있어야 한다.
- 모델 파일은 받지 않는다(받기는 늘 사용자의 허락 뒤에). GPU 메모리를 다른 일이 1.5 GB 넘게 쓰고 있으면 GPU 단계를 건너뛴다.
- `--단계` 로 일부만: 예 `--단계 머리,틀,토큰,목록`(GPU 없이 몇십 초).

## 단계와 판정

| 단계 | 하는 일 | 통과 |
|---|---|---|
| 머리 | GGUF 의 메타데이터와 꾸린 앱의 모델 확인(`/api/state` 의 shape) | 앱이 받는다 · 도구가 읽은 모양(형식 · 너비 · 헤드 · FFN · 어휘)이 앱의 것과 같다. 아니면 여기서 멈춘다 |
| 비트 | 앱이 이 모델에 쓰는 CUDA 모듈마다 시험_7B 다섯 길. 모델 파일이 6 GB 이하면 앱의 기본 빠른 모듈과 정밀로 시험_긴문맥(문맥 32,768 · `--far 0,0`) · 시험_추측 | 모두 같음 · 다른 경우 0 · 다른 칸 0 · 오류칸 0 |
| 참조 | CPU 참조(시험/참조7B.py)가 시험_7B 의 모든 행 로짓과 같은가 — 넷까지 함께, 다른 단계와 나란히(6 GB 넘는 모델은 앱의 기본만) | 다른 칸 0 |
| 품질 | llama.cpp(f16 KV) 대비 다음 토큰 KL · 1위 일치(시험/품질.py — 2,048 토큰 글 넷 + 8,192 창 하나, 6 GB 넘는 모델은 덩이 128 행) | 앱의 기본 모드가 판정 B′(글마다 평균 KL 이 llama.cpp 의 2.5 배 이하 · 1위 일치가 0.5 %p 넘게 낮지 않음). 다른 모드는 참고 |
| 틀 | 서버의 채팅 템플릿(GPU 없이 — 엔진/시험_채팅틀)을 jinja2 와(시험/채팅틀대조.py — 채팅 · 도구 경우, 생각 켬 · 끔) | 글자까지 같다 |
| 토큰 | 토크나이저(GPU 없이 — 엔진/시험_토큰)를 llama-tokenize 와: 까다로운 글 열(숫자 · 공백 · 줄바꿈 · CJK · 이모지) · 문서 다섯 | 토큰 번호가 같다 |
| 쓰임 | 꾸린 앱에서 불러오기 → 서버의 `/tokenize` 를 jinja2 참조와(시험/도구틀.py), 채팅 둘(한국어 · 영어), 템플릿에 도구가 있으면 도구 호출(시험/도구호출.py) | 앱이 고른 모드가 판정한 모드 · 같은 토큰 · 답이 있다 · 호출이 맞다 |
| 벌칸 | 같은 앱의 GPU 층을 Vulkan(늘 정밀)으로 바꿔 채팅 둘 | 답이 있다 |
| 목록 | `앱/data/models.json` 항목과 영어 화면의 번역 줄(`앱/web/app.js` 의 DICT)의 초안 | — (사람이 모델 설명 · 저장소 · 라이선스의 조건을 채운다) |

**앱과 같은 규칙**(앱/모델보기.gl · 일.gl):
- 모듈 이름 `{구조}{Q8|Q4|K|KI}_{너비}x{헤드}x{KV 헤드}x{FFN}x{어휘}` — 구조는 qwen3 · llamae6(llama, eps 10⁻⁶) · llama · qwen2e5(eps 10⁻⁵) ·
  qwen2. 정밀 CUDA 모듈은 `--먼`, 빠름은 `--빠른`, 8비트 KV 는 `--빠른 --KV8`(이름 끝 `_KV8`), 빠른 어텐션은 `--빠른 --KV8 --F2`(qwen3 은
  `--F2B` — 이름 끝 `_F2_KV8` · `_F2B_KV8`).
- 앱의 기본 모드: 빠름(F1 — 16비트 KV). k-양자화 파일이고 질의 폭이 너비와 같으면(헤드 크기 128 — 앱의 KV8됨) 8비트 KV + 빠른 어텐션.
  Q8_0 · Q4_0 파일 · 정밀 · Vulkan 은 16비트 KV.

## 결과

- `<작업>/결과.md`(표) · `결과.json` · `목록초안.json` · `기록.txt`, 시험마다의 기록은 `<작업>/r/`. 끝 줄 `모델 들이기: 모두 통과`(종료 0) 또는
  `모델 들이기: 못 미침 N`(종료 1) — 건너뛴 단계가 있으면 그 수도.
- **못 미침을 어떻게**: 비트 · 참조 · 틀 · 토큰 · 앱이 받기의 못 미침은 엔진을 고친다(목록에 넣지 않는다). 품질의 못 미침은 사용자의 결정 —
  12-2 의 Q8_0 작은 모델 넷처럼 기준 미달로 적고 넣거나, 넣지 않는다. 도구 호출의 못 미침이 모델의 몫이면(서버의 `/tokenize` 가 공식
  템플릿과 토큰까지 같은데 모델이 호출을 틀리게 쓴다 — Qwen2.5-1.5B · 3B 의 `{{…}}`) 목록의 설명에 적는다.
- 목록 초안: 크기 · sha256 · 형식(GGUF 의 file_type) · 크기 표(general.size_label) · 기기(`all` — Q8_0 · Q4_0, `k` — k-양자화)와 확인한
  것만의 문장(생각 켬 · 끔, 템플릿에 도구 없음, 문맥이 그래픽 메모리로 줄어듦, 확인한 장치 · 날짜)과 그 영어. 모델 설명 · 크기(GB) ·
  저장소(`--저장소` 를 주면 주소를 짓는다) · 라이선스의 조건은 사람이 채운다.
