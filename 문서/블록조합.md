# 블록 조합 — 일반 경로 · Qwen3.5 · MoE · Gemma 4 (0.12.0 12-3)

0.12.0 의 큰 일([0.12.0.md](0.12.0.md)의 12-3 · 계획 바꿈). 층을 블록의 조합으로 짓고 GGUF 의 메타데이터에서 고르게 바꿔, 엔진이 받는
모델의 폭을 넓힌다. 사용자 2026-10-23:

- "12-3(qwen35)은 블록 조합 구조로 진행해"
- "연구엔진이라는 점에서는 오히려 다른 엔진보다 모델 가용성이 더 높아야 해 — 그래야 사용자가 연구를 통해 모델을 새로 만들어 낼 때
  이것을 테스트해볼 수 있는 공간이 될 수 있지. 연구자들이 qwen 2, 3 같은 모델만 만드는 게 아니잖아."
- 순서: "일반 경로 먼저 해 — F16 · BF16 · F32 가중치와 임의의 헤드 크기 · 너비를 받는 커널을 먼저 만들고, 그 위에 Qwen3.5 의 선형
  어텐션 → MoE → Gemma 4 순서로."

## 왜

- **받는 폭**: Hugging Face 의 GGUF 저장소 가운데 30 일 다운로드 상위 500 개의 텍스트 LLM 391 개(다운로드 1억 6,700만 — 2026-10-23)에서
  GeulPU 가 받는 것은 다운로드의 10.5 %(저장소 76 개), 구조 이름 48 가지 가운데 3(qwen2 · qwen3 · llama). llama.cpp 는 구조 구현이 약
  170 개다. 남은 큰 몫: Qwen3.5 · 3.8(`qwen35`) 38.0 %, Qwen3.6 MoE(`qwen35moe`) 12.0 %, Qwen3.8-Flash-Next(`qwen4exp`) 8.8 %,
  Gemma 4 8.3 %.
- **연구용 GGUF**: 다운로드 표에는 보이지 않지만, 학습 직후 변환한 GGUF 는 보통 양자화 전의 F16 · BF16 · F32 이고 작은 실험 모델은 헤드
  크기 · 너비가 제각각이다. 지금은 구조가 llama 여도 이런 파일을 받지 않는다(아래 '지금의 제한').
- **구조**: 지금 엔진은 모델 모양마다 모듈 하나이고 **모든 층이 같다**(어텐션 헤드 128 + SwiGLU FFN). 구조의 차이(qwen2 · qwen3 의
  q · k 정규화 · llama 의 줄 되돌리기 · eps)는 커널 생성기 · 엔진 · 앱 · CPU 참조에 분기 조건으로 들어 있다. Qwen3.5 는 층마다 종류가
  다르다 — 선형 어텐션(gated delta net) 셋에 전체 어텐션 하나.

## 일반 경로 (첫 단계)

같은 구조(qwen2 · qwen3 · llama)에서 가중치 형식과 모양의 제한을 없앤다. 모든 경로가 지금처럼 정밀도 계약을 지킨다(결정성 · CPU 참조와
비트 일치 · 실행 경로와 상관없음). 커널은 모양을 인자로 받는 일반 커널이 먼저이고, 속도는 많이 쓰는 모양만 뒤에 전용 커널로 올린다.

**계약 1.3(안) — 16비트 블록 가중치(F16 · BF16 · F32)**
1. 불러올 때 행렬곱에 쓰는 가중치를 출력 행마다 깊이 32 칸 블록으로: E_w = ⌊log₂ max|w|⌋([−98, 100] 로 자르고, 최댓값이 0 이면 −98),
   n_w = 가까운정수(w · 2^(13 − E_w))(같으면 짝수) ∈ [−2¹⁴, 2¹⁴] — 1 절의 활성값과 같은 16비트 형식(8비트 자리 둘). **손실은 여기
   하나**: 블록 최댓값의 2⁻¹⁴ 이하(F16 은 블록 최댓값의 1/8 이상인 값, BF16 은 1/64 이상인 값이 바뀌지 않는다 — 더 작은 값만 2^(E_w − 13)
   단위로 반올림된다).
2. 정밀 모드(활성값 16비트 형식): 블록 b 마다 자리 짝 넷의 정확한 정수 합 S_ij = Σ_k D_x,i,k · D_w,j,k, T = 2¹⁶ S₁₁ + 2⁸(S₁₀ + S₀₁) + S₀₀
   (정확 — |T| ≤ 2³³), u_b = fp32(T · 2^(E_x,b − 13))(반올림 하나 — 2 절의 점수와 같은 꼴), y ← FMA(u_b, 2^(E_w,b − 13), y) 를 b 오름차순으로,
   출력 = y + 치우침.
3. 빠른 모드(활성값 8비트 — 1.2): T = 2⁸ S₁ + S₀(S_j = Σ_k n_x,k · D_w,j,k — 정확, |T| < 2²⁶), u_b = fp32(T · 2^(E_x,b − 5)), 나머지 같다.
4. 임베딩(토큰 → 활성값)은 파일의 값 그대로(F16 · BF16 → fp32 는 정확, F32 그대로). 출력이 임베딩과 공유되면 로짓 행렬곱은 1 의 형식.
5. 커널: int8 텐서 코어 행렬곱(자리 짝 넷 — Q8_0 의 두 배)과 dp4a — 정수 합이라 차례와 상관없다. 메모리는 가중치마다 2 바이트 + 블록마다
   지수 1 바이트(F16 파일과 거의 같다).

**헤드 크기 · 너비**
- 헤드 크기 h(`key_length` = `value_length`, 32 ≤ h ≤ 256): q · k · v 의 헤드를 32 의 배수 h′ = ⌈h/32⌉ · 32 로 0 을 채워 2 · 3 절을 블록
  h′/32 개로 계산한다 — 0 은 블록의 최댓값 · 정수 합을 바꾸지 않아 채우지 않은 계산과 같다. 점수 스케일 c = fp32(1/√h)(블록 체인 뒤 곱
  하나 — 헤드 크기 128 과 같은 자리). 출력의 채운 칸은 버린다.
- RoPE: 돌리는 차원 n_rot(`rope.dimension_count`, 없으면 h)의 짝 (i, i + n_rot/2), 표 [위치][n_rot/2](θ_i = θ^(−2i/n_rot) — 바르게 반올림),
  나머지 차원은 그대로. llama 구조의 줄 되돌리기도 n_rot 로.
- 너비 · 질의 폭 · FFN · 어휘: 활성값 블록(32 칸)의 남는 칸은 0 으로 채운다(같은 값). RMSNorm 은 실제 너비로 나눈다(4.1 그대로).

**확인**
- CPU 참조(정수계약.py — 16비트 블록 가중치, 일반 헤드 크기 · 너비)와 계약 자체 시험(정확한 유리수 · 따로 쓴 계산).
- 받지 않고 할 수 있는 모델: Qwen2.5-0.5B Q8_0(헤드 64 · 너비 896 — 이미 있음), 이미 있는 Q8_0 · k-양자화 파일을 llama.cpp 의
  llama-quantize 로 F16 · BF16 · F32 로 다시 저장한 파일(값은 양자화 값을 푼 것이지만 형식 · 모양의 시험으로는 같다).
- 연구자가 변환한 실제 F16 · BF16 GGUF(예: SmolLM2 — 헤드 64 · 너비 960)는 받기 전에 허락을 받는다.
- 판정: 다섯 실행 경로 · 모든 행 로짓이 CPU 참조와 불일치 0, 지금 받는 모델의 모듈은 바이트까지 그대로, llama.cpp 대비 품질 B′,
  자동 모델 검증([모델검증.md](모델검증.md))으로 받는 범위를 다시 센다.

**16비트 블록 가중치의 커널 (12-3c-1 — [커널/생성W16.gl](../커널/생성W16.gl))**
- 커널 생성기의 옵션 `--W16` 이 헤드 128 모듈의 끝에 커널 변형을 붙인다(앞의 커널은 바이트까지 그대로 — 기본 형식의 커널과 함께 있어
  텐서마다 형식이 다른 파일도 한 모듈로). 이름 끝은 `_W16`.
- 엔진의 가중치 배치: 값 [블록][열][64 바이트](열마다 위 8비트 자리 32 바이트 · 아래 8비트 자리 32 바이트 — 깊이 칸 차례 그대로),
  지수 [블록][열을 64 의 배수로] 바이트(E_w + 114 — 2^(E_w − 13) 의 fp32 비트가 바이트 << 23). F16 파일과 거의 같은 크기(가중치마다
  2 바이트 + 블록마다 1 바이트).
- 타일 커널(프롬프트 — 텐서 코어 행렬곱): 열 하나를 8비트 자리 열 둘로 보아(위 자리 열 · 아래 자리 열) Q8_0 커널과 같은 B 를 올린다.
  행렬곱 출력에서 한 스레드가 같은 열의 두 자리 열을 갖고, 블록마다 정수 합 넷(정밀)이나 둘(빠른)을 묶어 T 를 fp32 로 반올림 하나 —
  계약 1.3 의 식 그대로. 타일 모양 11 × 에필로그 ""(치우침) · 잔차. gate · up 은 에필로그 "" 뒤에 `SwiGLU정수로_W16`(SwiGLU → down 의
  입력 — Q8_0 의 SwiGLU 에필로그와 같은 식).
- 한 행 줄 커널(생성 그래프 — dp4a): 열 32 개(SwiGLU 는 64 개) · 블록 넷(둘)씩 비동기 복사, 에필로그 셋("" · 잔차 · SwiGLU). 행이 둘
  이상이면 타일 커널(k-양자화와 같은 규칙).
- 임베딩: 임베딩 행렬(`token_embd`)은 파일의 행 그대로(F16 · BF16 · F32) — 값을 fp32 로(F16 · BF16 은 정확, F32 와 비정규수는 비트 그대로). 출력이
  임베딩과 공유되면 로짓 행렬곱은 불러올 때 바꾼 16비트 블록 가중치로(계약 1.3 의 4).

**16비트 블록 가중치의 엔진 · 앱 (12-3d-1)**
- 엔진: k-양자화의 경로(텐서마다 형식 — [엔진/가중치K.gl](../엔진/가중치K.gl) · [엔진/엔진K.gl](../엔진/엔진K.gl))에 다섯 번째 형식 W16 을
  더했다. F16 · BF16 · F32 행렬은 불러올 때 계약 1.3 의 바꿈(열마다 워커 스레드 — fp32 비트에서 정확한 정수 반올림, 무한 · NaN · 2¹⁰¹ 이상은
  오류), 임베딩은 파일의 행 그대로, 공유된 출력은 바꾼 것을 따로 둔다. gate · up 의 타일 커널은 에필로그 "" 의 fp32 출력(측정용 버퍼 —
  계산 중에는 비어 있다) 뒤에 `SwiGLU정수로_W16`. 튜닝 캐시의 키는 300 + g · 2 + s(k-양자화의 키는 그대로). GGUF 읽기에 BF16(형식 30).
- 모듈: 형식 W16(`커널생성 {구조}큰 W16 …`) — Q8_0 · k-양자화의 선형층 커널 없이 16비트 블록 가중치의 커널만(3 MB 안팎 — Q8_0 모듈의
  1/3). k-양자화와 섞인 파일은 K · KI 모듈에 `--W16`(엔진의 모듈 이름 `KW16` · `KIW16` — 앱은 아직 받지 않는다).
- 앱: 층 가중치 · 임베딩 · 출력이 F16 · BF16 · F32 인 파일을 받는다 — 모듈 W16, 빠른 모드는 F1(8비트 KV 는 Q8_0 파일처럼 아직 쓰지 않는다),
  Vulkan 은 협력 행렬 없는 모듈, 공유 메모리 32 KB 장치는 아직 받지 않는다(타일 커널 몇이 32 KB 를 넘는다).

**헤드 크기 · RoPE 차원 · 너비의 커널 (12-3c-2)**
- 헤드 크기 h ≤ 128(64 · 96)은 어텐션 안에서 128 로 0 을 채워 헤드 128 의 커널을 그대로 쓴다 — 0 블록은 점수의 체인 · 가중합에 0 을 더해 h′
  로 채운 계약과 같은 비트(계약.md '헤드 크기 · RoPE 차원' 1). 바뀌는 커널은 셋뿐: RoPEKV(실제 크기의 QKV 출력 [q 머리 · h | k · v KV 머리 · h]
  를 읽어 0 을 채운 q 자리 · KV 캐시로, 앞 n_rot 차원만 돌린다 — 짝 (i, i + n_rot/2), 표 [위치][n_rot/2]), 병합(묶음 · 조각 — 실제 크기의
  o 입력 [행][머리 · h]으로 쓴다), 점수 스케일 fp32(1/√h). 그 밖의 어텐션 커널(묶음 · 조각 · 표 스텝)은 바이트까지 그대로다.
- 커널 생성기 `--헤드 <h> --RoPE <n_rot>`(h 는 64 · 96 · 128, n_rot 은 8 의 배수 · h 이하 — 없으면 h). 질의 폭 = h · 머리 수(QKV 출력 ·
  o 투영의 입력), 어텐션 폭 = 128 · 머리 수(q 자리 — 머리 수는 짝수). 헤드 128 이 아니면 너비 · 질의 폭은 32 의 배수(헤드 128 은 256 그대로),
  RMSNorm 의 생성 커널(펼침)은 마지막 칸을 지키고, 줄 타일 커널(블록 여덟씩)은 깊이가 256 의 배수일 때만 넣는다. 8비트 KV · 빠른 어텐션 ·
  공유 메모리 32 KB · 협력 행렬 · qwen3(헤드 정규화)은 아직 헤드 128 만.
- 헤드 128 · n_rot 128 이면 모듈은 바이트까지 그대로.

## Qwen3.5 의 계산 (GGUF 의 뜻 — llama.cpp `src/models/qwen35.cpp` 와 같다)

받아 둔 파일(E:/geulpu-work/v12/models — unsloth) 셋의 메타데이터:

| | 0.8B Q8_0 | 4B Q4_K_M | 9B Q4_K_M |
|---|---|---|---|
| 층(전체 어텐션) | 24 (6) | 32 (8) | 32 (8) |
| 너비 · FFN · 어휘 | 1,024 · 3,584 · 248,320 | 2,560 · 9,216 · 248,320 | 4,096 · 12,288 · 248,320 |
| 전체 어텐션: 헤드 · KV 헤드 × 헤드 크기 | 8 · 2 × 256 | 16 · 4 × 256 | 16 · 4 × 256 |
| 선형 어텐션: k 헤드 · v 헤드 × 128 | 16 · 16 | 16 · 32 | 16 · 32 |
| 출력 가중치 | 임베딩과 공유 | 임베딩과 공유 | `output.weight` |

공통: RMSNorm eps 10⁻⁶, RoPE `dimension_count` 64 · θ 10⁷, `full_attention_interval` 4(층 l 은 (l + 1) % 4 = 0 이면 전체 어텐션),
`ssm.conv_kernel` 4, 문맥 262,144. k-양자화 파일도 `ssm_alpha` · `ssm_beta`(너비 → v 헤드 수의 작은 투영)는 Q8_0, `ssm_conv1d` · `ssm_a` ·
`ssm_dt.bias` · 정규화 가중치는 F32.

층 l: x ← x + 어텐션(RMSNorm(x; `attn_norm`)), x ← x + FFN(RMSNorm(x; `post_attention_norm`)), FFN 은 SwiGLU(`ffn_gate` · `ffn_up` ·
`ffn_down`). 끝은 RMSNorm(`output_norm`)과 로짓(`output.weight`, 없으면 `token_embd.weight`).

**전체 어텐션**(`attn_q` · `attn_k` · `attn_v` · `attn_q_norm` · `attn_k_norm` · `attn_output`)
1. `attn_q` 가 헤드마다 [q(256) | 게이트(256)] 를 낸다(출력 폭 2 × 헤드 × 256).
2. q · k 를 헤드마다 RMSNorm(가중치 256 개 — 헤드끼리 같다).
3. RoPE 는 헤드의 앞 64 차원만 — 짝 (i, i + 32), θ_i = 10⁷^(−2i/64), i < 32. 나머지 192 차원은 그대로(MRoPE 의 섹션 [11, 11, 10] 은
   텍스트만이면 위치가 모두 같아 보통 RoPE 와 같다).
4. 점수 × 1/√256 = 1/16, 인과 소프트맥스, GQA(질의 헤드 h → KV 헤드 ⌊h / (H / H_kv)⌋).
5. 출력 × sigmoid(게이트)(원소마다), 그다음 `attn_output`.

**선형 어텐션**(`attn_qkv` · `attn_gate` · `ssm_beta` · `ssm_alpha` · `ssm_dt.bias` · `ssm_a` · `ssm_conv1d` · `ssm_norm` · `ssm_out`)
1. `attn_qkv` → [q(H_k · 128) | k(H_k · 128) | v(H_v · 128)], `attn_gate` → z(H_v · 128), β = sigmoid(`ssm_beta` · x),
   g = softplus(`ssm_alpha` · x + `ssm_dt`) · `ssm_a`(`ssm_a` = −exp(A_log) — 파일에 이미 음수).
2. 합성곱: 채널마다 커널 4 의 인과 합성곱(앞 세 행은 그 시퀀스의 합성곱 상태 — 처음 0, 커널 칸 0 이 가장 오래된 토큰), 그다음 SiLU.
3. q · k 를 헤드마다 L2 정규화(x / max(‖x‖, eps)), q × 1/√128.
4. v 헤드 j 는 k 헤드 **j mod H_k** 를 쓴다(llama.cpp 의 `ggml_repeat` — 헤드 목록을 통째로 되풀이한 차례이고 repeat_interleave 가 아니다. GGUF
   변환기가 v 헤드의 차례를 그렇게 맞춰 둔다).
5. 토큰마다 v 헤드마다 상태 S(128 × 128, S[k 칸][v 칸]): **S ← e^g · S, δ = (v − Sᵀk) · β, S ← S + k δᵀ, o = Sᵀq**.
6. 출력 RMSNorm(o; `ssm_norm` — 헤드마다 128) × SiLU(z), 그다음 `ssm_out`.

**확인(12-3a)** — [시험/qwen35수학.py](../시험/qwen35수학.py)가 이 식을 파일의 가중치(양자화 값 그대로)와 fp64 활성값으로 계산해(엔진의 계약이
아닌 '이상적인 모델') llama.cpp b11719(f16 KV · 모든 층 GPU)의 로짓과 비교한다 — 텍스트 둘 × 256 토큰:

| 파일 | 평균 KL(수학 참조 ‖ llama.cpp) | 1위 일치 |
|---|---|---|
| Qwen3.5-0.8B Q8_0 | 1.23 × 10⁻³ | 97.27 % |
| Qwen3.5-4B Q4_K_M | 5.40 × 10⁻³(중앙값 0.7 ~ 2.2 × 10⁻³) | 97.07 % |

GGUF 의 뜻을 잘못 읽으면(게이트 배치 · 헤드 짝 · 합성곱 차례 하나만 틀려도) 대부분의 행이 0.1 을 크게 넘는다. 4B 는 v 헤드(32)가 k 헤드(16)의
두 배라 짝 규칙(j mod 16)까지 확인한다. 4B 의 KL 이 가장 큰 행(1.1)은 둘이 같은 1위 토큰을 고르고 확률만 다른 행이다(0.51 대 0.97 —
llama.cpp 의 8비트 활성값 양자화).

## 블록

층 = 정규화 → **어텐션 블록** → 더하기 → 정규화 → **FFN 블록** → 더하기. 어텐션 블록 · FFN 블록의 종류와 매개변수를 층마다 고른다.

| 블록 | 매개변수 | 쓰는 구조 |
|---|---|---|
| RMSNorm | 너비 · eps | 모두 |
| 어텐션 | 헤드 크기 h(32 ~ 256), 돌리는 차원 n_rot, q · k 정규화(qwen3 · qwen35), 치우침(qwen2), 줄 되돌리기(llama), 출력 게이트(qwen35) | qwen2 · qwen3 · llama, qwen35 의 전체 어텐션 층 |
| 선형 어텐션 GDN | k 헤드 · v 헤드 · 128 · 합성곱 커널 4 | qwen35 의 선형 층 |
| FFN SwiGLU | 확장폭 | 모두 |
| (뒤) MoE FFN · Gemma 4 의 블록 · … | | qwen35moe · gemma4 … |

**층 구성**: GGUF 에서 짓는다 — qwen2 · qwen3 · llama 는 모든 층 [어텐션 + SwiGLU], qwen35 는 (l + 1) % `full_attention_interval` = 0 이면
[어텐션(h 256 · n_rot 64 · 게이트) + SwiGLU], 아니면 [GDN + SwiGLU](GGUF 에 순환 층 배열이 있으면 그것 — llama.cpp 와 같다).

## 계약 (Qwen3.5 의 새 연산 — 계약.md 4.9 · 4.10 으로)

계약의 원칙 그대로: GPU 가 고를 재량(반올림 · 더하는 차례 · 근사 명령)을 남기지 않고, 손실은 적힌 곳에서만. fp32 연산은 규칙 R(비정규수
버림)을 따르고, FMA 는 계약이 적은 곳에서만. 헤드 크기 256 · RoPE 앞 64 차원 · 헤드 정규화(D = h — 4.6 의 식을 원소 h 개로, 간격 h/2
부터)는 일반 경로의 것을 그대로 쓴다.

### 4.9 출력 게이트(Qwen3.5 의 전체 어텐션)
1. **q · 게이트 나누기**: q 투영의 출력에서 헤드마다 앞 h 가 q, 뒤 h 가 게이트(1 절의 정수 블록 계약 — 형식마다).
2. **게이트**: o_d = O_d / L(나눗셈 하나), σ(x) = x ≥ 0 이면 1 / (1 + e), 아니면 e / (1 + e)(e = 적힌지수(−|x|) — 계약의 지수 함수, 연산마다
   IEEE), o′_d = o_d · σ(게이트_d)(곱 하나), 그다음 `attn_output` 입력의 16비트 형식(빠른 모드는 1.2 의 8비트).
3. 헤드 256 의 점수 스케일은 c = 1/16(2 의 거듭제곱이라 정확). 8비트 KV · 빠른 어텐션(F2)은 이 버전에서 받지 않는다 — 앱의 허용 규칙(질의
   폭 = 128 × 헤드)이 아니고, 헤드 256 의 커널이 따로 든다.

### 4.10 선형 어텐션 GDN
1. **투영**: `attn_qkv` · `attn_gate` · `ssm_beta` · `ssm_alpha` · `ssm_out` 은 1 절의 정수 블록 계약(행렬마다 형식 — k-양자화 파일의
   `ssm_alpha` · `ssm_beta` 는 Q8_0).
2. **합성곱**: 채널 c 마다 y = w_c,0 · x_c(t − 3)(곱 하나), y ← FMA(w_c,1, x_c(t − 2), y), y ← FMA(w_c,2, x_c(t − 1), y), y ← FMA(w_c,3, x_c(t), y)
   — t 앞의 행은 그 시퀀스의 합성곱 상태(처음 0). **SiLU**: e = 적힌지수(−|y|), y ≥ 0 이면 y / (1 + e), 아니면 (y · e) / (1 + e)(4.3 의 식).
3. **L2 정규화**(q · k 헤드마다 128): 4.6 의 트리(p_t = x_t², 간격 64 부터)로 S, n = 제곱근(S), r = 1 / max(n, eps), y = x · r.
   q 는 다시 × c_k(c_k = fp32(1/√128) = 0x3DB504F3 — 곱 하나).
4. **게이트 값**(v 헤드마다): β = σ(b)(4.9 의 σ), u = a + dt(더하기 하나), sp = u > 0 이면 u + L, 아니면 L(L = log1p(적힌지수(0 − |u|)) — 적힌지수의
   입력이 늘 0 이하이고 문턱이 없는 softplus), g = sp · A(곱 하나), γ = 적힌지수(g). log1p 는 fdlibm `s_log1pf.c` 를 [0, 1] 로 줄인 fp32 식(12-3e —
   계약.md 4.10 — 최대 오차 0.85 ulp).
5. **순환 계산**(v 헤드 h — k 헤드 h mod H_k, 토큰 차례로, 상태 S[i][j] fp32 128 × 128, 처음 0):
   1. S_ij ← γ · S_ij(곱 하나)
   2. kv_j: 행 블록 넷(i ∈ [32b, 32b + 32))마다 P_b = S_(32b)j · k_(32b), 그다음 i 오름차순으로 P_b ← FMA(S_ij, k_i, P_b) — kv_j = (P_0 + P_1) + (P_2 + P_3)
   3. δ_j = (v_j − kv_j) · β(빼기 · 곱 하나씩)
   4. S_ij ← FMA(k_i, δ_j, S_ij)
   5. o_j = 2 와 같은 차례로 Σ_i S_ij · q_i
   토큰마다 같은 차례라 프롬프트 · 생성 · 표 스텝 어느 실행 경로든 비트가 같다. 커널은 이 차례를 지키는 한 스레드 배치가 자유다(예: 열 j 마다
   스레드 넷이 행 블록 하나씩 — 워프 셔플 둘로 트리).
6. **출력**: o 를 헤드마다 4.6 의 RMSNorm(D = 128, `ssm_norm`), × SiLU(z)(곱 하나), 그다음 `ssm_out` 입력의 16비트 형식(빠른 모드 8비트).

이 숫자(fp32 FMA 체인 · 블록 넷의 트리)는 12-3e 의 정확도(수학 참조 대비)와 시제품(속도)으로 확정한다. 대안은 상태를 정수 블록으로
두는 것(합의 차례가 자유 — 메모리 두 배).

- **앱**: 모델 확인(qwen35 · 헤드 256 · 선형 층), 메모리 계획(KV 는 어텐션 층만 + 상태), 모델 목록 — 자동 모델 검증(문서/모델검증.md)으로.

## MoE (12-3g) — 계획(안, 2026-10-24)

**대상 — `qwen35moe`**: Qwen3.5 · 3.6-35B-A3B 와 그 미세조정(Hugging Face 의 GGUF 상위 500 가운데 텍스트 LLM 다운로드의 12.0 % — MoE 의 가장 큰
몫, 다음은 `qwen4exp` 177B · `deepseek4` · `gpt-oss`). 층은 Qwen3.5 와 같고(전체 어텐션 10 · GDN 30, 너비 2048, 헤드 16 × 256 · KV 헤드 2, GDN k 헤드 16
· v 헤드 32) FFN 만 MoE 다: 전문가(expert) 256 개 가운데 라우터가 고른 8 개(각각 SwiGLU · 확장폭 512)와 공유 전문가(shared expert) 하나(SwiGLU 512 ·
sigmoid 게이트). 이 PC 에 Qwen3.6-35B-A3B Q4_K_M(unsloth, 20.4 GB — 2026-10-19 MoE 측정 때 받은 것)이 있다.

**파일의 형식**(Q4_K_M): 전문가 행렬(`ffn_gate_exps` · `ffn_up_exps` · `ffn_down_exps` — [전문가 256][512][2048] 의 3 차원 텐서)은 Q4_K 로 약
18.1 GB, 어텐션 · GDN · 공유 전문가는 Q8_0, 라우터(`ffn_gate_inp` 2048 × 256 · `ffn_gate_inp_shexp` 2048)는 F32, 임베딩 Q4_K · 출력 Q6_K. 텐서마다
형식이 다르다 — 일반 경로의 가중치 표(텐서마다 형식)로 받는다.

**계약 4.11(안) — MoE FFN**(h = RMSNorm(x; post_attention_norm) — 4.1)
1. 라우터: l = ffn_gate_inp · h(전문가마다 하나) — 1 절의 정수 블록 계약(F32 가중치는 계약 1.3 의 16비트 블록). 라우팅은 값이 조금만 달라도 고른
   전문가가 바뀌는 곳이라 fp32 FMA 체인(k 오름차순, F32 가중치 그대로)과 CPU 참조로 비교했다(12-3g-1) — 블록 계약이 수학 참조에 더 가깝다(KL
   1.51 × 10⁻³ 대 1.96 × 10⁻³, 고른 전문가 집합이 같은 (층, 행) 93.5 % 대 92.3 % — 블록마다 정확한 정수 합이라 반올림이 64 번, FMA 체인은
   2,048 번). 공유 게이트(ffn_gate_inp_shexp)는 열 하나 더 — 라우터와 행렬 하나(열 E + 1 개).
2. softmax: m = max l, e_i = 적힌지수(l_i − m), S = 가닥 32 의 부분합(가닥 t 는 번호 t, t + 32, … 차례)을 16 부터 반씩 더한 합(4.1 RMSNorm 의
   접기와 같은 꼴 — 커널은 워프 하나의 나비), p_i = e_i / S.
3. 상위 k(k = expert_used_count = 8): l 의 내림차순(같으면 작은 번호 먼저) 앞 k 개 — 순위 r = 0 … k − 1.
4. 무게: s = Σ p_(e_r)(순위 차례), w_r = p_(e_r) / max(s, 2⁻¹⁴)(llama.cpp 의 하한 6.103515625e-5 = 2⁻¹⁴ — 나눗셈 하나).
5. 전문가 r: y_r = down_(e_r)(SwiGLU(gate_(e_r) · h, up_(e_r) · h)) — 1 절 · 4.3 의 계약(행렬마다 형식).
6. 합: o = w_0 · y_0, 그다음 r = 1 … k − 1 차례로 o ← FMA(w_r, y_r, o).
7. 공유 전문가: y_s = down_s(SwiGLU(gate_s · h, up_s · h)), g = σ(ffn_gate_inp_shexp · h)(내적은 1 의 길, σ 는 4.9), o ← FMA(g, y_s, o).
8. 잔차: x ← x + o.
llama.cpp 와 같은 식이다(build_moe_ffn — softmax → 상위 k → 합으로 나누기 → 전문가 출력 × 무게를 순위 차례로 더함, 공유 전문가 × sigmoid 게이트).

**메모리 — 전문가를 CPU 메모리에**: 12 GB 에 전문가 행렬(18.1 GB)이 들지 않는다(전문가 밖은 약 2.3 GB).
- 전문가 행렬을 엔진 배치로 깔아 고정(pinned) 호스트 메모리에 두고 GPU 주소 공간에 대응시킨다(UVA). 커널은 (층, 전문가)마다 주소를 적은 표를 장치에서
  읽어, VRAM 에 둔 전문가는 VRAM 에서, 나머지는 PCIe 로 바로 읽는다(zero-copy). 라우팅이 고른 전문가를 호스트가 알 필요가 없어, 실행 계획 · CUDA
  그래프가 지금처럼 고정된다.
- VRAM 의 남는 자리에는 자주 쓰는 전문가를 둔다 — 처음 판은 불러올 때 고르는 고정 집합(짧은 보정 프롬프트의 라우팅 빈도), 뒤에 GPU 의 LRU 캐시.
- 결정성: 전문가가 어디 있든 같은 정수 계약이라 비트가 같다(시험이 VRAM 에 둔 몫을 바꿔 가며 본다).
- 메모리 비용: 고정 호스트 메모리 약 18 GB(이 PC 는 32 GB). 대안은 전문가를 VRAM 캐시로 복사하는 길(llama.cpp 의 `--moe-cache-mib`) — 층마다 호스트가
  고른 전문가를 읽고 복사해야 해 실행 계획이 층마다 끊긴다.
- 생성 속도 어림: 토큰마다 층 40 × 전문가 8 × 1.7 MB = 544 MB 를 읽는다 — 모두 PCIe(약 25 GB/s)면 토큰당 약 22 ms(약 45 tok/s), VRAM 에 둔 몫만큼
  준다. 비교: llama.cpp b11727 은 이 PC 에서 GPU LRU 캐시 6.4 GB 로 77 tok/s([MoE재기.md](MoE재기.md)).

**실행 경로**: 프롬프트(청크)는 라우팅 뒤 행을 전문가마다 묶어(장치에서 정렬) 전문가마다 타일 행렬곱(그룹 행렬곱), 생성(행 하나)은 고른 8 전문가의 한 행
행렬곱. 한 행의 전문가 출력은 계약 6 의 순위 차례로 더하므로, 행을 어떻게 묶든 비트가 같다.

## Gemma 4 (12-3h) — 계획(안, 2026-10-24)

0.12.0 을 낸 뒤(사용자 "0.12.0 먼저 배포" → "gemma작업 진행해봐"). 다음 판(0.13.0 — 버전의 경계는 단계가 끝날 때 정한다)에 든다. GGUF 구조
`gemma4`(llama.cpp `src/models/gemma4.cpp`, master 7894e8b). 크기는 E2B · E4B(층마다 따로 쓰는 임베딩 — PLE) · 12B · 31B(dense) · 26B-A4B(MoE).
**첫 대상은 12B** — PLE · KV 공유 · MoE 가 없는 가장 단순한 Gemma 4 다(Hugging Face 의 Gemma 4 GGUF 가운데 unsloth 의 12B 가 내려받기 1 위).

**12B 의 모양**(google/gemma-4-12B-it 의 config): 너비 3,840 · 층 48 · 질의 헤드 16 · FFN 15,360 · 어휘 262,144(출력은 임베딩과 묶임) · eps 10⁻⁶.
층은 슬라이딩 윈도 어텐션 다섯에 전체 어텐션 하나(`layer_types`):

| | 슬라이딩 윈도 층(40) | 전체 어텐션 층(8) |
|---|---|---|
| 헤드 크기 · KV 헤드 | 256 · 8 | 512 · 1 |
| v_proj | 있다 | 없다 — V = K(정규화 전) |
| RoPE | θ 10,000, 헤드 전체 | θ 1,000,000, 부분(0.25 — 128 차원) · 비례 RoPE(`rope_freqs` 텐서) |
| 보는 범위 | 앞 1,024 위치(윈도) | 처음부터 |

**층의 계산**(llama.cpp 와 같다): 입력 x = 임베딩 × √3,840 → RMSNorm(attn_norm) → q: 헤드마다 RMSNorm(가중치) · RoPE, k: RMSNorm(가중치) ·
RoPE, v: RMSNorm(**가중치 없이**) → 어텐션(**배율 1** — 1/√d 없이) → RMSNorm(attn_post_norm) → + x → RMSNorm(ffn_norm) → **GeGLU**(GELU(tanh 근사) ·
gate × up) → RMSNorm(ffn_post_norm) → + . 끝에 RMSNorm → 출력 → **소프트캡** 30 · tanh(로짓 / 30).

**지금 엔진에 없는 것**:

  RMSNorm, 비례 RoPE(차원마다 인자), 슬라이딩 윈도의 마스크.
- 커널: 헤드 512 의 어텐션(지금은 128 · 256 까지), 한 모델 안의 두 어텐션 모양(헤드 · KV 헤드 · RoPE 가 층마다 다르다), GeGLU 에필로그, 소프트캡.
