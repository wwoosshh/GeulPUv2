# 빠른 어텐션 계약 F2 — 긴 프롬프트에서 llama.cpp 앞서기 (계획 2026-10-21)

사용자 2026-10-21: "릴리스 배포 진행하고 그다음으로 계약 개정 진행해" — ③c(0.9.0) 뒤에 남은 열세인 긴 프롬프트 처리를 계약을 바꿔
줄인다. 이 문서는 측정 전에 쓴 계획과 판정 기준이다.

## 왜

③c 의 비교(문서/긴문맥.md — llama.cpp b11768, Qwen2.5-7B Q4_K_M, 비 = GeulPU 시간 ÷ llama.cpp 시간): 생성 · 추측 검증 · 짧은 프롬프트는
이미 앞서지만 긴 프롬프트는 진다.

| 측정 | 8비트 KV ↔ q8_0 KV | 16비트 ↔ f16 KV |
|---|---|---|
| 빈 프롬프트 16k · 32k · 64k | 1.03 · 1.14 · 1.18 | 1.19 · 1.40 · 1.52 |
| 깊이 8k · 32k · 64k 의 새 입력 1,024 토큰 | 1.00 · 1.18 · 1.02 | 1.17 · 1.51 · 1.36 |

까닭은 프롬프트 어텐션의 계산이다. 점수 하나(행 · 키 · 헤드)마다 스레드 명령이 약 140 개(8비트 KV)이고, 대부분이 계약이 정한 연산이다.
③c 의 명령 줄이기(출력 비트는 그대로)로는 2 ~ 3 % 가 남은 몫이었다. 점수 하나당 연산을 커널 생성기의 줄(`커널/생성머리128.gl` 의 `큰조각셈`)로
센 어림:

| 부분 | 명령(어림) | 무엇이 드는가 |
|---|---|---|
| 점수(QK) | 약 23 | 블록 넷마다: 텐서 코어 행렬곱(MMA) 둘(q 의 8비트 자리 둘 × 키 int8), 두 합을 합쳐 fp32 로(정수 곱셈 · 변환), 2^E_q 곱, 키 스케일 FMA. 키 · 스케일 읽기 |
| 소프트맥스 | 약 20 | 타일 최댓값, 적힌지수(범위 줄이기와 7차 다항식 — 17 명령), 합 l |
| 가중합(PV) | 약 42 | 값의 블록 넷마다 따로: e′ = e × s_v, 키 32 개마다 최댓값 · 지수 · 16비트 자리 · 바이트 모으기(약 21). MMA 와 키 32 개 블록마다의 fp32 변환 · 두 블록 합치기(약 16), 병합(4) |
| 나머지 | 약 55 | 주소 계산 · 공유 메모리 읽기 · 레지스터 넘침(8비트 448 바이트) · 동기화 |

가중합이 셋 가운데 가장 크다. 품질의 단서는 둘이다.

- 손실은 키(점수) 쪽에서 온다(③b-1): 값만 8비트(V8)는 KL 비가 F1 과 ±0.01 안이었다.
- q 를 8비트 자리 하나로 하면 손실이 는다(2b-1): Llama-3.1-8B Q4_K_M 의 KL 비 F1+KV 0.94 → F1+QKV 1.23(2 의 거듭제곱 스케일의
  결과지만 방향은 같다).

그래서 F2 는 점수 쪽(q 16비트 · 키 8비트와 블록 스케일)을 거의 그대로 두고 가중합과 소프트맥스를 줄인다.

## 무엇 — F2 의 후보(F1A′ 와 다른 점)

구성은 F2-1 에서 품질로 고른다.

1. **값 스케일을 토큰마다 하나** [V128]: 값 캐시는 int8 그대로이고, fp32 스케일을 헤드의 값 128 개마다 하나(s_v = max|v| / 127) 둔다.
   F1A′ 는 32 개마다다. e′ = e × s_v 를 키마다 한 번 계산하고 값의 블록 넷이 함께 쓴다(지금은 블록마다 따로 — 넷).
2. **확률을 타일마다 한 지수로** [P16 · P8]: 행마다 타일(키 64)의 e′ 최댓값으로 지수 E 를 하나 정해 e′ 를 정수로 바꾼다 — 16비트(8비트
   자리 둘) 또는 8비트 하나. 가중합의 정수 합은 타일 전체(키 64)에서 한 번에 낸다. 키 32 개마다의 변환과 두 블록 합치기가 없어진다.
   8비트 하나면 정수 합이 fp32 로 정확해(|합| < 2²⁰) 변환이 매직 넘버 덧셈 하나다.
3. **밑이 2 인 지수 함수** [X2]: 점수에 c′ = fp32(c · log₂e)를 곱해 log₂ 단위로 두고, e = 2^(s − m) 를 [−½, ½] 의 5차 다항식과
   매직 넘버 반올림으로 계산한다. 아래로 넘침은 자르기(−126) 하나로 막는다(분기 없음). 17 명령 → 약 11.
4. **q 의 지수를 헤드마다 하나** [Q1E]: q 는 16비트 형식(8비트 자리 둘) 그대로이고 지수만 블록 넷이 함께 쓴다. 블록마다의 2^E 곱(점수
   하나에 넷)이 끝의 곱 하나가 된다. q 는 16비트라 키의 8비트보다 훨씬 작은 차이일 것이다(F2-1 에서 잰다).
5. **그대로**: 키 캐시(int8 + 값 32 개마다 fp32 스케일), 점수의 블록 차례(FMA 체인), 타일 64 · 그룹 1024 의 두 층 병합 구조, 합 l 의
   정수 합.

어림: 구성 1 ~ 4 를 모두 쓰면(P8) 점수 하나당 명령이 약 85 → 약 45 다(나머지 제외 — 레지스터가 줄어 넘침도 줄 것이다). 32k 빈 프롬프트에서
어텐션이 시간의 반쯤이라, 어텐션이 2 배 빨라지면 다음과 같다. 어림이라 F2-0 에서 잰다.

| 측정 | 0.9.0 8비트 KV | F2 어림 | llama.cpp b11768 q8_0 · f16 |
|---|---|---|---|
| 빈 프롬프트 32k | 8,890 ms | 약 6,600 ms | 7,788 · 7,670 |
| 깊이 64k 의 새 입력 1,024 | 716 ms | 약 420 ms | 705 · 689 |

결정성 · CPU 참조와의 비트 같음 · 실행 경로 불변은 그대로다 — 정수 합은 정확하고, 차례는 정해져 있고, fp32 연산은 규칙 R 을 따른다.
F2 는 새 계약이라 출력 비트가 F1A′ 와 다르다.

## 버전 · 설정

- 빠른 모드의 KV 캐시 설정에 F2 를 하나 더한다. 기본은 그대로(16비트 KV)다. 지금의 모드 · 설정은 출력 비트가 그대로라 버전 규칙의
  MINOR 다. F2 를 기본으로 해도 같은 계산 방식(설정 포함)끼리의 출력 비트는 그대로라 호환을 깨지 않는다 — 0.11.0 에서 기본으로 했다
  ([문서/0.11.0.md](0.11.0.md)의 1-5. 계획 때 'MAJOR(1.0.0)'라 적은 것은 버전 규칙을 잘못 읽은 것이었다).
- CUDA 만이다(8비트 KV 와 같다). 정밀 모드 · Vulkan 은 그대로다. k-양자화 파일만 받는다(F1A′ 처럼 Q8_0 · Q4_0 은 막는다).
- 프롬프트 캐시는 청크 이름에 계약을 넣어 섞지 않는다(값 스케일이 달라 KV 바이트가 다르다).

## 0.11.0 1-4 — qwen3 구조의 F2B (2026-10-23)

F2-3 에서 qwen3 구조만 판정 B″ 의 1위 일치가 문턱에 못 미쳐(Qwen3-8B −0.51 %p) 앱이 빠른 어텐션을 막았다. 0.11.0 계획([문서/0.11.0.md](0.11.0.md))의 1-4 는

**시제품 — Q1E 만 뺀다.** F2 가 F1A′(8비트 KV)와 다른 것은 V128 · P16 · X2 · Q1E 넷이다. Qwen3 은 RoPE 앞에 q · k 를 헤드마다 정규화하고(계약

거칠어진다. 생성기에 q 의 지수만 블록마다로 두는 깃발(RoPE · KV 저장 커널의 최댓값 넓힘을 값에만, 점수는 블록마다 u · 2^(E_q,b − 13) 의 사슬 —
