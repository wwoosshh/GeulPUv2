# 에이전트 호환 — 사용자가 고른 코딩 에이전트를 GeulPU 에 붙이게 (조사 · 설계 2026-10-28 — 1 단계, 승인 전)

## 왜

- GeulPU 의 방향은 재현되는 로컬 에이전트 엔진이다. 그런데 서버가 받는 API 는 OpenAI 호환 하나뿐이고, 실제로 시험한 에이전트는
  Qwen Code 하나다([도구.md](도구.md) — 0.25.3, 비대화 · --yolo). 사용안내는 OpenCode · Continue · Cline 도 붙는다고 적지만 시험하지 않았다.
- 많이 쓰는 에이전트 가운데 Claude Code 는 Anthropic 꼴 API 만, Codex CLI 는 OpenAI 의 Responses API 만 써서 지금은 둘 다 붙지 않는다
  (§에이전트마다). Ollama 는 2026-01 부터 `ollama launch` 로 Claude Code · OpenCode · Codex 등을 로컬 모델에 붙여 띄우고, Ollama ·
  LM Studio · llama.cpp · vLLM 모두 `/v1/messages` 와 `/v1/responses` 를 더했다.
- 다음 일(도구 오류 안내 — 오류를 모델에게 알리는 꼴을 연구대로 고치는 것)은 에이전트마다 오류를 쓰는 꼴이 달라, 한 에이전트에 맞춰
  지으면 그 에이전트에 굳는다. 그래서 먼저 붙는 폭을 넓히고, 오류 층은 에이전트를 모르는 한 곳에 짓는다.

## 순서

1. **조사 · 설계(이 문서)** — 에이전트마다 쓰는 API · 도구 호출 방식 · 꼭 필요한 칸 · 기본 지시문 크기 · 도구 오류를 쓰는 꼴.
2. **API 층** — 서버 안의 대화 표현을 하나로 두고, 그 앞에 받는 문(Anthropic · Responses)을 더한다. 틀 그리기 · 호출 읽기는 지금 것을
   함께 쓴다.
3. **에이전트마다 확인** — 같은 작은 일을 에이전트마다 이 PC 의 로컬 모델로 돌리고, 주고받은 것을 녹화해 되는지 · 어디서 막히는지를 표로
   적는다. 이 녹화가 4 의 오류 글 모음이 된다.
4. **도구 오류 층** — 2 의 대화 표현 위에 한 번만 짓는다. 에이전트마다 다른 것은 오류를 알아보는 규칙표뿐이다. 꼴의 기본값은 연구
   (기록을 남기는 안내 차례 — C2 대 C3)의 결과로 정한다.

## 지금 GeulPU 서버가 주는 것 (0.13.0 · main 89d46bf — `엔진/서버몸.gl`)

- 문: `/v1/chat/completions` · `/v1/completions` · `/v1/models`(`max_model_len` = 슬롯의 문맥) · `/v1/tokenize` · `/v1/detokenize` ·
  `/v1/tokenizer_info` · `/v1/health`. 앱이 넘겨주는 주소는 `http://127.0.0.1:44544/v1`, API 키 · 모델 이름은 보지 않는다(불러 둔 모델이
  답한다).
- 채팅: `tools`(type function) · `tool_choice`(auto · none) · `parallel_tool_calls` · `stream`(SSE, `delta.tool_calls`,
  `stream_options.include_usage`, `[DONE]`) · `max_tokens` · `max_completion_tokens` · `temperature` · `top_p` · `top_k` · `min_p` ·
  `seed` · `stop` · `logprobs` · `top_logprobs`(20 까지) · `chat_template_kwargs` · `geulpu`(확장).
- 생각: Qwen3 의 `<think>…</think>` 는 도구를 보낸 요청이면 `reasoning_content` 로 뗀다.
- 호출 읽기: 다섯 꼴 — Qwen 의 `<tool_call>` JSON · Llama 3 의 JSON · Qwen3.5 · Qwen3-Coder 의 XML · MiniCPM 의 XML · Gemma 4 의
  `<|tool_call>call:이름{…}`.
- 문맥을 넘으면 400 `code: context_length_exceeded`(토큰 수 포함) — 에이전트가 스스로 대화를 줄인다.
- **400 으로 거절하는 칸**(지킬 수단이 없거나 계약 밖): `tool_choice` 의 required · 함수 지정, 0 이 아닌 `presence_penalty` ·
  `frequency_penalty`, text 가 아닌 `response_format`, 비지 않은 `logit_bias`, `n` > 1, `best_of` > 1, `suffix`, 옛 `functions`, 도구를
  그리지 않는 틀의 모델에 `tools`. 에이전트가 이 칸을 보내면 그 요청은 막힌다(§에이전트마다 의 "GeulPU 에 걸리는 것").
- 동시 처리는 슬롯 8 개까지(#138).

**GeulPU 에 걸리는 것(2 단계에서 고침 · 확인)**
- Qwen Code 의 JSON 보조 요청(`baseLlmClient.generateJson` — 세션 제목 · 요약 · 권한 분류 등)은 도구 하나(`respond_in_schema`)를 두고
  호출을 강제한다(`mode: ANY` → OpenAI 의 `tool_choice: "required"`, 비흘림) — 지금 400 이라 그 기능들이 조용히 빠진다. 인자 없는 도구는
  `parameters` 칸 없이 보내고, tool 메시지의 content 는 조각 배열이다(받는지 확인).
- OpenCode 는 늘 흘리고(`include_usage`), `max_tokens` 대신 `max_completion_tokens` 를 보내며, 흘림이 finish_reason 없이 끝나면 멈춘다. 도구
  정의의 `strict` 칸이 틀에 그대로 그려지는지 확인한다.
- Cline 새 묶음은 흘림의 각 호출 첫 조각에 이름이 있어야 한다 — GeulPU 는 호출 하나를 다 모은 뒤 한 조각에 통째로 보내므로 맞다
  (`호출흘리기`). 옛 묶음은 모델 이름으로 꼴을 고르므로, 표준 tools 를 쓰게 하려면 이름을 그 계열로 두어야 한다(GeulPU 는 이름을 보지
  않는다).
- Claude Code 는 모르는 모델 이름에 `thinking` · `output_config` · `context_management` · messages 안의 `role: system` 을 보내고, 정해진
  오류 글의 400 일 때만 빼고 다시 보낸다. 문맥은 200K, `max_tokens` 는 32,000 으로 여기므로 서버가 줄여야 한다. 첫 요청이 22 ~ 27k 토큰.
- Codex 는 `response.completed` 에 `response.id` 와(usage 가 있으면) input · output · total 토큰을 꼭 바란다. web_search 는 설정으로 꺼야
  한다. 첫 요청 약 9k 토큰.

## 설계 — 하나의 대화 표현과 여러 문

- **하나의 대화 표현**은 지금 서버가 쓰는 것 그대로다: OpenAI 채팅 꼴의 messages · tools · 매개변수(JSON). 틀 그리기(`채팅틀.gl`) ·
  생성 · 호출 읽기(다섯 꼴) · 생각 떼기 · 문맥 검사는 모두 이 표현에서 한 번만 돈다.
- **문**은 바깥 꼴을 이 표현으로 바꾸고(요청), 결과(content · reasoning_content · tool_calls · finish_reason · usage)를 바깥 꼴로 다시
  쓴다(답 · 흘림). 같은 바깥 요청은 늘 같은 표현이 되어 같은 토큰을 낸다 — 엔진의 계약은 그대로다. 바꾸는 규칙은 문마다 표로 적는다.
- **문 1 — OpenAI 채팅(있음)**: 에이전트가 실제로 보내는 칸을 받게 넓힌다(§에이전트마다 의 "GeulPU 에 걸리는 것").
  - `tool_choice` 의 required · 함수 지정: 지킬 수단(제약 생성)이 없어 지금은 400. 후보 — (가) 틀의 호출 여는 꼴(예: Qwen 의
    `<tool_call>`)을 생성 머리 뒤에 미리 넣어 호출을 강제(같은 입력 → 같은 토큰, 꼴은 계열마다 표), (나) 받기만 하고 auto 로 그림(지키지
    못함을 답의 확장 칸에 적음). 2 단계에서 하나를 고른다.
- **문 2 — Anthropic Messages(새로)**: `POST /v1/messages`(`?beta=true` 도) · `POST /v1/messages/count_tokens`.
  - 요청: `system`(글 · 블록 — `cache_control` 은 무시), messages 의 블록(text · `tool_use` → tool_calls · `tool_result` → tool 메시지,
    `is_error` 는 표현의 확장 칸에 남김 · thinking 블록은 뗌 · 이미지는 400), `tools`(name · description · `input_schema` — `cache_control` ·
    `defer_loading` · `strict` 은 무시), `tool_choice`(auto · any · tool · none — any · tool 은 문 1 과 같은 길), `max_tokens`(문맥에 맞춰
    줄임), `stop_sequences` · `temperature` · `top_p` · `top_k` · `stream`. 머리 칸 `anthropic-version` · `anthropic-beta` 는 받고 무시한다.
  - 모르는 모델에 보내는 칸(`thinking` · `output_config` · `context_management` · messages 안의 `role: system`)은 받고 무시하거나 표현으로
    옮긴다 — 400 을 내면 Claude Code 는 정해진 오류 글일 때만 칸을 빼고 다시 보낸다.
  - 답: `content` 블록(text · `tool_use` — input 은 객체), `stop_reason`(end_turn · tool_use · max_tokens · stop_sequence), `usage`
    (input_tokens · output_tokens · 캐시 칸 0). 흘림: `message_start` → `content_block_start` / `content_block_delta`(text_delta ·
    input_json_delta) / `content_block_stop` → `message_delta`(stop_reason · usage) → `message_stop`, 사이사이 `ping`. 비흘림도 된다(흘림이
    끊기면 Claude Code 가 비흘림으로 다시 묻는다). 오류는 Anthropic 꼴(`{"type":"error","error":{…}}`).
- **문 3 — OpenAI Responses(새로)**: `POST /v1/responses`(상태 없음 — `store` 는 거짓만, `previous_response_id` 는 400).
  - 요청: `input`(글 · 항목: message — role user · assistant · developer · system, 조각 input_text · output_text — · `function_call` →
    tool_calls · `function_call_output` → tool 메시지 · reasoning 항목은 뗌), `instructions`, `tools`(type function — 다른 type 은 빼고 확장
    칸에 적음), `tool_choice`, `parallel_tool_calls`, `max_output_tokens`, `stream`. `reasoning` · `include` · `prompt_cache_key` · `text` ·
    `client_metadata` 는 받고 무시.
  - 답: `output` 항목(message 의 output_text · function_call — call_id · name · arguments), `usage`(input_tokens · output_tokens ·
    total_tokens). 흘림: `response.created` → `response.output_item.added` → `response.output_text.delta` … → `response.output_item.done` →
    `response.completed`(response.id · usage 를 꼭 담음).
- **문 4 — Gemini(generateContent)**: 나중. 로컬 서버 가운데 이 꼴을 주는 곳이 없어 사람들은 프록시를 쓴다.
- **오류 층의 자리(4 단계)**: 문이 표현으로 옮긴 tool 메시지에 "실패" 표시를 단다 — Anthropic 은 `is_error`, Gemini 는
  `functionResponse.response.error`, OpenAI 채팅 · Responses 는 표시가 없어 에이전트마다의 오류 글 규칙(§에이전트마다)으로. 에이전트는
  머리 칸(User-Agent — 3 단계에서 녹화로 확인)이나 설정으로 알아본다. 바꾸기(C2 · C3)는 표현에서 한 번만 짓는다.

## 확인 계획 (3 단계)

- **일**: 에이전트마다 같은 작은 일 하나 — "fib.py 를 만들고 실행해 출력이 맞는지 확인"([도구.md](도구.md) 의 시험과 같음). 그 뒤
  일부러 오류 셋(없는 파일 읽기 · 실패하는 명령 · 권한 없는 파일)을 내게 해 에이전트마다의 오류 글을 받는다(4 단계의 규칙표 자료).
- **비대화 모드**: Qwen Code `qwen -p` · OpenCode `opencode run` · Claude Code `claude -p` · Codex `codex exec` · Aider `--message` ·
  편집기 확장은 그 CLI 가 있으면 CLI 로, 없으면 편집기에서 손으로.
- **모델**: 이 PC(12 GB)에서 긴 지시문을 받는 것 — Qwen2.5-7B Q4_K_M(YaRN 87,488)을 기본으로, 도구에 강한 Qwen3.5-9B · Qwen3.6-35B-A3B 를
  곁으로. Claude Code 는 첫 요청이 22 ~ 27k 토큰이라 문맥 64k 이상이 든다.
- **녹화**: 에이전트와 서버 사이에 연구의 녹화 프록시(요청 · 답 · 흘림을 그대로 적음)를 둔다. 머리 칸(User-Agent)도 적는다.
- **통과**: 일을 끝냄(파일이 있고 출력이 맞음) · 서버의 4xx · 5xx 가 없음 · 호출이 모두 읽힘(content 에 날 호출 글이 남지 않음) · 흘림이
  끊기지 않음. 막히면 어디서 · 무엇 때문인지 적는다.
- **설치**: 에이전트를 이 PC 에 설치해야 한다(npm · pip · 편집기 확장) — 사용자의 허락을 받은 뒤에.
