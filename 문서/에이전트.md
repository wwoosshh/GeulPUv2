# 에이전트 호환 — 사용자가 고른 코딩 에이전트를 GeulPU 에 붙이게 (조사 · 설계 2026-10-28 — 1 단계, 승인 전)

## 왜

- GeulPU 의 방향은 재현되는 로컬 에이전트 엔진이다. 그런데 서버가 받는 API 는 OpenAI 호환 하나뿐이고, 실제로 시험한 에이전트는
  Qwen Code 하나다([도구.md](도구.md) — 0.25.3, 비대화 · --yolo). 사용안내는 OpenCode · Continue · Cline 도 붙는다고 적지만 시험하지 않았다.
- 많이 쓰는 에이전트 가운데 Claude Code 는 Anthropic 꼴 API 만, Codex CLI 는 OpenAI 의 Responses API 만 써서 지금은 둘 다 붙지 않는다
  (§에이전트마다). Ollama 는 2026-01 부터 `ollama launch` 로 Claude Code · OpenCode · Codex 등을 로컬 모델에 붙여 띄우고, Ollama ·
  LM Studio · llama.cpp · vLLM 모두 `/v1/messages` 와 `/v1/responses` 를 더했다.
- 다음 일(도구 오류 안내 — 오류를 모델에게 알리는 꼴을 연구대로 고치는 것)은 에이전트마다 오류를 쓰는 꼴이 달라, 한 에이전트에 맞춰
  지으면 그 에이전트에 굳는다. 그래서 먼저 붙는 폭을 넓히고, 오류 층은 에이전트를 모르는 한 곳에 짓는다.

## 순서

1. **조사 · 설계(이 문서)** — 에이전트마다 쓰는 API · 도구 호출 방식 · 꼭 필요한 칸 · 기본 지시문 크기 · 도구 오류를 쓰는 꼴.
2. **API 층** — 서버 안의 대화 표현을 하나로 두고, 그 앞에 받는 문(Anthropic · Responses)을 더한다. 틀 그리기 · 호출 읽기는 지금 것을
   함께 쓴다.
3. **에이전트마다 확인** — 같은 작은 일을 에이전트마다 이 PC 의 로컬 모델로 돌리고, 주고받은 것을 녹화해 되는지 · 어디서 막히는지를 표로
   적는다. 이 녹화가 4 의 오류 글 모음이 된다.
4. **도구 오류 층** — 2 의 대화 표현 위에 한 번만 짓는다. 에이전트마다 다른 것은 오류를 알아보는 규칙표뿐이다. 꼴의 기본값은 연구
   (기록을 남기는 안내 차례 — C2 대 C3)의 결과로 정한다.

## 지금 GeulPU 서버가 주는 것 (0.13.0 · main 89d46bf — `엔진/서버몸.gl`)

- 문: `/v1/chat/completions` · `/v1/completions` · `/v1/models`(`max_model_len` = 슬롯의 문맥) · `/v1/tokenize` · `/v1/detokenize` ·
  `/v1/tokenizer_info` · `/v1/health`. 앱이 넘겨주는 주소는 `http://127.0.0.1:44544/v1`, API 키 · 모델 이름은 보지 않는다(불러 둔 모델이
  답한다).
- 채팅: `tools`(type function) · `tool_choice`(auto · none) · `parallel_tool_calls` · `stream`(SSE, `delta.tool_calls`,
  `stream_options.include_usage`, `[DONE]`) · `max_tokens` · `max_completion_tokens` · `temperature` · `top_p` · `top_k` · `min_p` ·
  `seed` · `stop` · `logprobs` · `top_logprobs`(20 까지) · `chat_template_kwargs` · `geulpu`(확장).
- 생각: Qwen3 의 `<think>…</think>` 는 도구를 보낸 요청이면 `reasoning_content` 로 뗀다.
- 호출 읽기: 다섯 꼴 — Qwen 의 `<tool_call>` JSON · Llama 3 의 JSON · Qwen3.5 · Qwen3-Coder 의 XML · MiniCPM 의 XML · Gemma 4 의
  `<|tool_call>call:이름{…}`.
- 문맥을 넘으면 400 `code: context_length_exceeded`(토큰 수 포함) — 에이전트가 스스로 대화를 줄인다.
- **400 으로 거절하는 칸**(지킬 수단이 없거나 계약 밖): `tool_choice` 의 required · 함수 지정, 0 이 아닌 `presence_penalty` ·
  `frequency_penalty`, text 가 아닌 `response_format`, 비지 않은 `logit_bias`, `n` > 1, `best_of` > 1, `suffix`, 옛 `functions`, 도구를
  그리지 않는 틀의 모델에 `tools`. 에이전트가 이 칸을 보내면 그 요청은 막힌다(§에이전트마다 의 "GeulPU 에 걸리는 것").
- 동시 처리는 슬롯 8 개까지(#138).

**GeulPU 에 걸리는 것(2 단계에서 고침 · 확인)**
- Qwen Code 의 JSON 보조 요청(`baseLlmClient.generateJson` — 세션 제목 · 요약 · 권한 분류 등)은 도구 하나(`respond_in_schema`)를 두고
  호출을 강제한다(`mode: ANY` → OpenAI 의 `tool_choice: "required"`, 비흘림) — 지금 400 이라 그 기능들이 조용히 빠진다. 인자 없는 도구는
  `parameters` 칸 없이 보내고, tool 메시지의 content 는 조각 배열이다(받는지 확인).
- OpenCode 는 늘 흘리고(`include_usage`), `max_tokens` 대신 `max_completion_tokens` 를 보내며, 흘림이 finish_reason 없이 끝나면 멈춘다. 도구
  정의의 `strict` 칸이 틀에 그대로 그려지는지 확인한다.
- Cline 새 묶음은 흘림의 각 호출 첫 조각에 이름이 있어야 한다 — GeulPU 는 호출 하나를 다 모은 뒤 한 조각에 통째로 보내므로 맞다
  (`호출흘리기`). 옛 묶음은 모델 이름으로 꼴을 고르므로, 표준 tools 를 쓰게 하려면 이름을 그 계열로 두어야 한다(GeulPU 는 이름을 보지
  않는다).
- Claude Code 는 모르는 모델 이름에 `thinking` · `output_config` · `context_management` · messages 안의 `role: system` 을 보내고, 정해진
  오류 글의 400 일 때만 빼고 다시 보낸다. 문맥은 200K, `max_tokens` 는 32,000 으로 여기므로 서버가 줄여야 한다. 첫 요청이 22 ~ 27k 토큰.
- Codex 는 `response.completed` 에 `response.id` 와(usage 가 있으면) input · output · total 토큰을 꼭 바란다. web_search 는 설정으로 꺼야
  한다. 첫 요청 약 9k 토큰.

## 설계 — 하나의 대화 표현과 여러 문

- **하나의 대화 표현**은 지금 서버가 쓰는 것 그대로다: OpenAI 채팅 꼴의 messages · tools · 매개변수(JSON). 틀 그리기(`채팅틀.gl`) ·
  생성 · 호출 읽기(다섯 꼴) · 생각 떼기 · 문맥 검사는 모두 이 표현에서 한 번만 돈다.
- **문**은 바깥 꼴을 이 표현으로 바꾸고(요청), 결과(content · reasoning_content · tool_calls · finish_reason · usage)를 바깥 꼴로 다시
  쓴다(답 · 흘림). 같은 바깥 요청은 늘 같은 표현이 되어 같은 토큰을 낸다 — 엔진의 계약은 그대로다. 바꾸는 규칙은 문마다 표로 적는다.
- **문 1 — OpenAI 채팅(있음)**: 에이전트가 실제로 보내는 칸을 받게 넓힌다(§에이전트마다 의 "GeulPU 에 걸리는 것").
  - `tool_choice` 의 required · 함수 지정: 지킬 수단(제약 생성)이 없어 0.13.0 까지는 400. 후보 — (가) 틀의 호출 여는 꼴(예: Qwen 의
    `<tool_call>`)을 생성 머리 뒤에 미리 넣어 호출을 강제(같은 입력 → 같은 토큰, 꼴은 계열마다 표), (나) 받기만 하고 auto 로 그림(지키지
    못함을 답의 확장 칸에 적음).
  - **(가)로 정했다(2 단계 — `feat/agent-door1`, `엔진/서버몸.gl` 의 `호출강제열기`)**. 여는 글은 꼴마다 아래와 같고, 함수 지정이면 이름과
    인자 머리까지 넣는다. 넣은 글 가운데 여는 토큰 뒤의 몫은 도구 칸의 글에도 넣어, 호출을 풀 때 모델이 이어 쓴 글과 이어진다.

    | 꼴 | required | 함수 지정(이름 X) |
    |---|---|---|
    | 1 Qwen JSON | `<tool_call>\n{"name": "` | `<tool_call>\n{"name": "X", "arguments": ` |
    | 2 Llama 3 | `{"name": "` | `{"name": "X", "parameters": ` |
    | 3 Qwen3.5 · Coder XML | `<tool_call>\n<function=` | `<tool_call>\n<function=X>\n` |
    | 5 Gemma 4 | `<\|tool_call>call:` | `<\|tool_call>call:X{` |
    | 4 MiniCPM XML | 400(아직) | 400(아직) |

    여는 글은 늘 틀의 생각 끔 꼴 뒤에 둔다: 생각을 연 채 끝나는 머리(Qwen3.5 의 `<think>\n` · Gemma 4 의 `<|channel>thought`)는 닫고,
    생각 묶음이 없는 머리(Qwen3 · Gemma 4 의 생각 켬)에는 빈 묶음(`<think>\n\n</think>\n\n` · `<|channel>thought\n<channel|>`)을 넣는다.
    생각 칸 없이 곧바로 호출을 열면 Gemma 4 가 호출을 깨진 꼴(괄호)로 쓰고 되풀이했다. 도구가 하나면 `required` 는 그 이름의 함수
    지정과 같다(Qwen Code 의 JSON 보조 요청이 이 꼴). 도구가 여럿이면 호출만 지키고 이름은 모델이 고른다 — Qwen3.5-9B 는 없는 이름을
    지어냈다(한계). 함수 이름은 tools 에 있어야 하고 OpenAI 의 이름 규칙(영문 · 숫자 · _ · -, 64 자까지)이어야 한다. tools 없이 강제하면
    400. `/tokenize` 는 여는 글을 넣지 않는다(강제할 때만 몇 토큰 적게 센다).
  - 시험(`시험/도구호출.py`, 꼴마다 대표 모델 — Qwen3-8B · Llama-3.1-8B · Qwen3.5-9B · Gemma-4-12B 생각 켬): 모두 맞음. tool_choice 를 쓰지
    않는 요청 넷(Qwen3-8B)은 main 과 바이트까지 같다(시간 · 정하지 않은 씨앗 · 캐시 칸 빼고).
- **문 2 — Anthropic Messages(새로)**: `POST /v1/messages`(`?beta=true` 도) · `POST /v1/messages/count_tokens`.
  - 요청: `system`(글 · 블록 — `cache_control` 은 무시), messages 의 블록(text · `tool_use` → tool_calls · `tool_result` → tool 메시지,
    `is_error` 는 표현의 확장 칸에 남김 · thinking 블록은 뗌 · 이미지는 400), `tools`(name · description · `input_schema` — `cache_control` ·
    `defer_loading` · `strict` 은 무시), `tool_choice`(auto · any · tool · none — any · tool 은 문 1 과 같은 길), `max_tokens`(문맥에 맞춰
    줄임), `stop_sequences` · `temperature` · `top_p` · `top_k` · `stream`. 머리 칸 `anthropic-version` · `anthropic-beta` 는 받고 무시한다.
  - 모르는 모델에 보내는 칸(`thinking` · `output_config` · `context_management` · messages 안의 `role: system`)은 받고 무시하거나 표현으로
    옮긴다 — 400 을 내면 Claude Code 는 정해진 오류 글일 때만 칸을 빼고 다시 보낸다.
  - 답: `content` 블록(text · `tool_use` — input 은 객체), `stop_reason`(end_turn · tool_use · max_tokens · stop_sequence), `usage`
    (input_tokens · output_tokens · 캐시 칸 0). 흘림: `message_start` → `content_block_start` / `content_block_delta`(text_delta ·
    input_json_delta) / `content_block_stop` → `message_delta`(stop_reason · usage) → `message_stop`, 사이사이 `ping`. 비흘림도 된다(흘림이
    끊기면 Claude Code 가 비흘림으로 다시 묻는다). 오류는 Anthropic 꼴(`{"type":"error","error":{…}}`).
  - **지었다(2 단계 — `feat/agent-door2`, `엔진/서버몸.gl` 의 `앤바꾸기` · `앤받기` · `앤셈응답` · `앤…보내기`)**. 위의 옮김 그대로이고,
    더한 규칙: system 블록과 messages 안의 `role: system` 은 맨 앞 system 하나로(사이에 줄바꿈 둘), user 의 tool_result 는 차례대로 tool
    메시지로 · 남은 글 블록은 그 뒤 user 메시지로, `is_error` 는 tool 메시지의 확장 칸 `geulpu_error`(틀은 쓰지 않는다 — 4 단계의 자리),
    이미지 · 문서 블록은 `[image]` · `[document]`, input_schema 가 없는 서버 도구는 뺀다, stop_sequences 는 넷까지, `thinking.type`
    disabled 는 틀의 `enable_thinking` 거짓으로. 생각은 늘 떼고 내지 않는다(도구가 없어도 — 글 답에 섞이지 않게). usage 는

## 4 단계 — 도구 오류 층 (설계 승인 2026-10-28)

에이전트가 보낸 대화 안에서 **실패한 도구 결과**를 찾아, 연구가 고른 꼴로 바꿔 틀에 그린다. 세 문은 모두 같은 표현(OpenAI 채팅 꼴의
`messages`)으로 옮긴 뒤 `채팅틀그리기` 하나로 그리므로(`엔진/서버몸.gl` — 생성 · `/tokenize` · `count_tokens`), 바꾸기는 그 바로 앞에서
**한 번만** 한다. 사용자가 고르는 에이전트가 무엇이든 같은 층을 지난다.

- **꼴**(연구의 글을 바이트까지 그대로 — 참조 구현은 errmsg2 `세션.py` 의 `꼴`):
  - 알림 = `Note from the tool runtime: the last attempt called {이름} with {인자} and it failed with: {오류}\n{안내}`(인자 = `k=v, k=v`).
  - 안내 셋 — 일시 `This is a temporary failure. Retrying the same call is expected to succeed.` · 고침 `This call cannot succeed as
    written. The error says what to change; call the tool again with the corrected value.` · 해없음 `This cannot be fixed by retrying or
    by changing the arguments. Tell the user what happened.`
  - C1 = tool 메시지 끝에 `\n` + 안내. C2(= A2B2, 첫 연구가 고른 꼴) = 실패한 호출 · 결과를 지우고 마지막 사용자 메시지 끝에 `\n\n` +
    알림. C3(errmsg2 에서 재는 꼴) = 기록은 그대로, 실패 교환 뒤 첫 사용자 메시지 끝에 `\n\n` + 알림(없으면 그 자리에 새 사용자 메시지).
- **기본은 끔(C0 — 오늘과 비트까지 같다).** 어느 꼴을 켤지가 바로 errmsg2(C3 대 C2)의 결론이고, 그 결과는 등록 3 을 OSF 에 올린 뒤에
  연다. 결과를 보기 전에는 기본을 정하지 않는다.
- **실패 찾기 — 정밀도 먼저**(틀린 안내는 해가 된다 — 첫 연구에서 안내 없이 자리만 옮기면 멈춰야 할 때 멈추지 않았다):
  1. 명시 표시 — Anthropic `is_error`(문 2 가 확장 칸 `geulpu_error` 로 옮김) · Cline 결과 JSON 의 `"success": false` · OpenCode 의
     `{"error":{"type":"tool.execution", …}}`. 에이전트를 몰라도 쓴다(Cline 의 User-Agent 는 SDK 의 것이라 꼴로 알아본다).
  2. User-Agent 로 고른 글 규칙(3 단계 녹화): Qwen Code `File not found:` · 셸의 `Exit Code: N`(N ≠ 0) · `Error …`; Codex
     `Process exited with code N` · `Exit code: N` · `command timed out` · `apply_patch verification failed`; Kilo `File not found:` ·
     `Unknown: FileSystem.…` · `oldString …`; OpenCode 셸의 끝 줄 `Exited with code N`.
  3. 모르는 에이전트는 1 만 본다. Kilo 의 셸 실패는 종료 코드가 오지 않아 못 잡는다(한계).
- **종류**(오류 글의 낱말, 앞 4 KB): 해없음(EACCES · EPERM · permission denied · 읽기 전용 · Unable to write · Forbidden) > 일시(연결
  끊김 · 거절 · ETIMEDOUT · Too Many Requests · Service Unavailable · Gateway Timeout) > 고침(도구 사용법 오류 — 에이전트가 고칠 값을
  알려 줌: must not be empty · has not been read · No replacement performed · Invalid insert_line · verification failed 등) > 그 밖은
  **모호**(없는 파일 · 0 이 아닌 종료 코드 · 명령의 시간 초과 — 같은 호출로 다시 해도 또 넘을 수 있다). 모호에는 안내를 붙이지 않는다.
- **캐시**: C3 는 기록을 지우지 않는다 — 실패 교환마다 같은 자리에 같은 알림을 늘 다시 넣으면 다음 요청의 앞부분이 바이트까지 같아
  프롬프트 캐시가 맞는다. C2 는 기록을 지워 앞부분이 바뀐다.
- **고르기 · 기록**: 요청 칸 `geulpu_tool_errors`(`"off"` · `"c1"` · `"c2"` · `"c3"`) > 서버 옵션 `--도구오류` > 기본(끔). 감지는 서버
  로그 한 줄과 답의 머리 칸 `X-GeulPU-Tool-Errors`(몸은 그대로)로 적는다.
- **아직 모르는 것**: 연구는 결정 스텝 하나를 쟀다 — 여러 턴 동안 C3 를 기록 전체에 거는 꼴은 3 단계 하네스로 따로 확인한다. 첫 연구의 실제
  세션 탐색에서 A2B2 가 셋 가운데 둘을 놓쳤다(errmsg2 주장 2 가 답한다). 연속된 사용자 차례를 거절하는 틀에서는 C3 대신 C1 이나 끔.
- **순서**: 4a 감지 + 기록(출력 그대로) → 4b 꼴 C1 · C2 · C3(기본 끔) → 4c errmsg2 결과를 연 뒤 기본값 · 모델 예외.

**4a — 지었다(`feat/agent-step4a`, `엔진/도구오류.gl` · `엔진/서버몸.gl` 의 `도구오류적기`).** 머리 읽기에서 User-Agent 를 떼어 두고,
`일감채우기` 가 틀을 그리기 직전에 messages 의 role tool 메시지를 훑어 (메시지 번호 · 종류 · 규칙)을 모은다. 찾으면 서버 로그에
`[n] 도구 오류 감지 2 — #3 고침(opencode) · #5 해없음(opencode) · 꼴 끔` 한 줄(바로 비움 — 400 으로 끝나는 요청도 보이게)과 다음 답의
머리 `X-GeulPU-Tool-Errors: 2; 3=fixable:opencode, 5=unrecoverable:opencode`(흘림 · 온 답 모두). 그리는 글은 그대로다.
