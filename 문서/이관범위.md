# GeulPUv2 — 실사용 엔진으로 옮기는 범위 (2026-10-18)

> **결정(2026-10-18, 사용자)**: 엔진 · 앱의 기능은 모두 둔다 — 연구 패널 · 교차검증도 이 엔진의 기능이다. 정리하는 것은 **문서**다
> (연구 기록은 GeulPU 에, 기능을 설명하는 문서는 여기로 — 1단계). 버전은 0.5.0 에서 이어 간다(다음 0.6.0). 아래 6절의 권고 2(패널 제외) ·
> 8(버전 0.1.0)과 7절 5 는 이 결정으로 바뀌었다 — 원문은 기록으로 둔다.

GeulPU 는 2026-10-16 에 연구를 동결했다(40단계 — 계산 손실은 답을 흔들지만 증상을 늘리지 않는다). 이 문서는 그 저장소를 **그대로 두고**,
실사용(성능 · 안정성 · 편안함)을 목적으로 하는 새 프로젝트 `GeulPUv2` 에 무엇을 옮기고 무엇을 두고 갈지 적은 것이다. 결정이 필요한 것은
6절에 모았다.

## 4. 실사용 눈으로 본 지금의 격차

**성능** (RTX 4070 Ti · 문서의 값)
- 프롬프트 처리가 llama.cpp 의 1.13 ~ 1.56 배 시간(7B, 2048 · 8192 토큰). 생성은 같은 급(0.97 ~ 1.05 배). 원인은 계약이 정한 활성값 자리 둘
  (정수 텐서 일이 두 배)과 어텐션의 정확한 합 · 적힌 지수 — 문맥이 길수록 어텐션의 몫이 커진다.
- 동시 요청 처리량: 넷 302 · 여덟 508 토큰/초(llama-server 360 · 632, 28단계) — 행 여럿 줄 커널 변형이 다음 일로 남아 있다.
- 첫 실행에 모델 · 장치마다 커널을 만든다(생성 0.04 초 + PTX 약 26 초 × 모듈 + 드라이버 JIT + 판 재기 = 1 ~ 3 분). 모듈 캐시가 **앱 버전마다**
  따로라(`모듈/0.2.0 · 0.3.0 · 0.5.0`) 새 버전을 깔면 다시 만든다.
- Vulkan: NVIDIA 에서 CUDA 의 프롬프트 1.19 ~ 1.27 배 · 생성 1.00 ~ 1.06 배, AMD RX 9060 XT 는 기준 PC Vulkan 의 3.3 ~ 3.7 배(어텐션 · 행 여덟 행렬곱).
- 서버가 토큰마다 스레드를 띄우는 비용(약 5 ms, 38f 에서 일부만 숨김).

**안정성**
- 윈도 TDR(긴 제출) · 범위 밖 쓰기 → DEVICE_LOST(Vulkan) — 커널 쪽 안전장치가 없다.
- 모델 하나 = 서버 프로세스 하나. 모델을 바꾸면 서버를 내리고 다시 올린다(가중치 다시 깔기). 여러 모델 동시 불가.
- 받지 않는 것: MoE, Gemma · Phi 구조, 질의 폭 ≠ 너비(Qwen3 0.6B · 4B · 32B · Mistral NeMo), 헤드 크기 64 의 작은 llama(3.2 1B), IQ · Q2_K · Q3_K · Q5_0,
  다른 채팅 템플릿의 미세조정(ChatML 등), 윈도 AMD 의 k-양자화.
- R1 · Qwen3 의 `<think>` 토큰을 서버가 떨어뜨리고 화면이 `\n\n\n` 으로 가른다(정식 처리가 아니다).
- 서명하지 않은 실행 파일(SmartScreen), 콘솔 창을 닫으면 종료.

**편안함**
- 채팅 저장이 브라우저 localStorage 다(용량 한도 — "브라우저 저장 공간이 부족해" 안내가 이미 있다). 첨부 없음, 대화 폴더 없음, 자동 업데이트 없음(알림만).
- API 에 tools(함수 호출) · 벌점 · JSON 모드 · 인증이 없다 — 바깥 앱(코딩 도구 등)을 붙일 때 걸린다.
- 모델을 바꾸는 데 수십 초(위), 트레이 · 자동 시작 · 창 없는 실행 없음.

## 5. GeulPUv2 의 꼴 (제안)

```
GeulPUv2/
  엔진/        ← 호스트/ 의 제품 닫힘(핵심 · GPU 층 · 서버 · 장치 · 진단)
  커널/        ← 생성기 + 진단 커널
  앱/          ← 관리자 + web/ + data/ + 꾸리기.ps1
  계약/        ← 계약.md + 정수계약.py · 로그확률.py (시험 오라클)
  시험/        ← 빠른점검 + 비트 회귀 시험(판 · 다섯 길 · 참조7B) + 모듈해시 · SASS넘침 · 글저장소커밋
  문서/        ← 새 로드맵 · 바뀐것 (1단계부터)
  .github/     ← ci.yml · release.yml (경로만 바꿈)
```

- 폴더 이름은 역할대로 바꾼다(`호스트` → `엔진`). 파일 안의 `포함` 경로와 `꾸리기.ps1` · `빠른점검.py` 의 경로를 같이 고친다.
- 글(geul) 컴파일러 의존은 지금처럼 **고정 커밋**으로 시작한다(`../geul-lang-v2` 옆 폴더 — CI 와 같은 배치). 백엔드를 v2 안으로 가져오는 것(6절 6)은 뒤에.
- 옮긴 직후의 판정: 같은 고정 커밋으로 꾸리면 서버 · 생성기 · 백엔드의 SHA-256 이 `expected.json` 의 빌드 해시와 **같아야** 한다(폴더 이름만 바뀌면
  바이트는 같다 — 다르면 옮기다 무엇이 바뀐 것). 그다음 CI 녹색, 7B 하나로 채팅. 이것이 v2 의 0 단계다.

## 6. 결정이 필요한 것

1. **계약(비트 재현)을 어디까지 두나.** 생성은 가중치 읽기가 정하므로 계약의 값이 0 에 가깝고, 값은 프롬프트(1.26 ~ 1.38 배 하한)에만 있다.
   권고: 계약을 버리지 말고 **정밀도 수준을 하나 더 적는다** — 지금의 '두 자리' 계약은 정확 모드로 두고(시험 오라클 · 재현 보장), 활성값 8 비트
   계약(llama.cpp 급 — 40단계의 V 는 7 비트라 llama.cpp 보다 손실이 커서 그대로는 안 된다)을 빠른 모드로 새로 짜 실사용 기본으로 한다.
   둘 다 CPU 참조가 있어 비트 시험이 그대로 선다. 이것이 v2 성능 작업의 첫 큰 단계다.
2. **연구 패널 · 교차검증을 남기나.** 실사용엔 '토큰마다 확률 보기' 정도면 되고, 분기 · 비교 · 재현 파일 · 교차검증은 연구 기능이다. 빼면 화면 950 줄 ·
   서버의 echo 길 · `data/crosscheck` 가 준다. 권고: 로그확률 API(표준)는 두고 패널 · 교차검증은 뺀다. **→ 결정(2026-10-18): 둔다 — 이 엔진의 기능이다.**
3. **영어 화면.** 상업 목적이면 유지(사전 800 개는 이미 있다). 빼면 유지 비용이 준다.
4. **글(geul) 언어 유지.** 방향전환 문서는 "GPU 일은 계속 글로" 였다. 실사용 목적이어도 같은가(컴파일러 고정 커밋에 묶이는 비용 포함).
5. **자료 폴더.** `%USERPROFILE%\GeulPU` 를 그대로 쓰면 받은 모델 50 GB 를 다시 받지 않는다. 다만 `모델목록.json` 의 일부 경로가 `GeulPU/모델/` 을
   가리키고, 모듈 캐시는 버전마다다. 권고: 같은 폴더를 쓰되 v2 가 모듈 캐시를 생성기 · 백엔드 해시로 키를 만들어 버전이 바뀌어도 다시 만들지 않게 한다.
6. **글 컴파일러 의존.** (a) 고정 커밋 그대로, (b) PTX · SPIR-V 백엔드(6,000 줄)을 v2 저장소로 가져와 컴파일러 배포판(geulc.exe)만 쓰기,
   (c) `research/gpu` 를 geul-lang `main` 에 병합. 권고: 0 단계는 (a), 뒤에 (b).
