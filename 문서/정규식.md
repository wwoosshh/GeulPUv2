# 정규식 사전 처리 (0.12.0 12-G2)

0.12.0 의 일반화([0.12.0.md](0.12.0.md)의 계획 바꿈) 둘째 단계. BPE 토크나이저의 사전 처리(pre-tokenizer — 텍스트를 BPE 앞에 조각(piece)으로
자르는 정규식)를 모델마다 글(geul)로 손으로 옮기던 것을, llama.cpp 와 같은 **이름 → 정규식 표**와 **정규식 엔진**으로 바꾼다.

## 왜

- 엔진은 사전 처리 넷(qwen2 · llama-bpe · dbrx · minicpm5)을 손으로 짠 나누기 함수로 받는다. 새 모델이 나올 때마다 GGUF 의
  `tokenizer.ggml.pre` 가 새 이름이면 받지 못한다 — Qwen3.5 · 3.8 의 `qwen35`(내려받기의 38 %)도 그렇다.
- llama.cpp 는 이름마다 정규식 목록을 두고(llama-vocab.cpp — 이름 70 여 개), 흔한 정규식 몇은 손으로 짠 빠른 경로(fast path — unicode.cpp 의
  `unicode_regex_split_custom_*`)로, 나머지는 `std::regex` 로 자른다.

## llama.cpp 의 규칙(b11829 — 그대로 따른다)

- 이름 → 정규식 목록(차례대로): 목록의 정규식마다 앞 정규식이 낸 조각 안에서 다시 자른다. 매치된 곳과 그 사이의 텍스트가 모두 조각이 된다
  (`unicode_regex_split_stl` — 조각의 끝이 텍스트의 끝이다: `$` · `(?!\S)` 가 조각 안에서 본다).
- 정규식의 문자열이 빠른 경로의 것과 같으면(gpt2 · llama3 · qwen2 · qwen35 · k2-horizon · kimi-k2 · afmoe · 줄바꿈 · tiny_aya 의 숫자) 그
  손으로 짠 나누기 함수를 쓴다.
- 아니면 ECMAScript `std::regex`(C++)로 — `\p{…}` 가 있으면 텍스트를 **범주 바이트로 바꾼 텍스트**(llama.cpp 의 collapsed text)로 바꿔서:
  128 미만의 코드포인트는 그대로, 나머지는 범주 하나의 바이트(공백이면 0x0B, 숫자 0xD1 · 글자 0xD2 · 구두점 0xD3 · 결합 문자 0xD4 · 기호 0xD5,
  그 밖 0xD0)로, 정규식의 `\p{X}` 는 `[바이트 + 그 범주의 ASCII]` 로. `\p{Lu}` · `\p{Ll}` · `\p{Lt}` · `\p{Lm}` · `\p{Lo}` 는 모두 글자(L)가
  된다. `\p{…}` 가 없으면 코드포인트 그대로(128 이상의 공백만 0x0B).
- 범주 · 공백은 llama.cpp 의 unicode-data.cpp(scripts/gen-unicode-data.py 가 만든 표)로.

## 무엇을

1. 범주 표: unicode-data.cpp 의 `unicode_ranges_flags` · `unicode_set_whitespace` 를 글(geul) 표로(만드는 스크립트 — 표는 MIT 의
   llama.cpp 에서 왔다고 적는다).
2. 빠른 경로: 지금의 qwen2 · llama3(llama-bpe · dbrx) 나누기 함수는 두고, gpt2 · qwen35 의 손으로 짠 나누기 함수를 llama.cpp 의 것과 같은
   규칙으로.
3. 정규식 엔진: ECMAScript 의 백트래킹(backtracking) 매칭 — 대안(처음 매치되는 것), 그리디(greedy) 반복(`* + ? {n,m}`), 그룹 `( )` · `(?: )`,
   전방 탐색(lookahead) `(?= )` · `(?! )`, 문자 클래스(범위 · 부정 · `\p{…}` · `\s` · `\d`), `$`. 위의 범주 바이트로 바꾼 텍스트 그대로.
4. 이름 → 정규식 목록 표(llama-vocab.cpp 와 같은 문자열)와 이름마다의 설정(ignore_merges).
5. 시험: llama.cpp 의 어휘 시험(models/ggml-vocab-*.gguf · .inp · .out — tests/test-tokenizer-0 과 같은 형식, 엔진/시험_토큰.gl ·
   시험/어휘시험.py).
