# jinja 템플릿 해석기 (0.12.0 12-G1)

0.12.0 의 일반화([0.12.0.md](0.12.0.md)의 계획 바꿈) 첫 단계. 서버가 모델마다 채팅 템플릿을 글(geul)로 손으로 짜던 것을, GGUF 의
`tokenizer.chat_template` 을 그대로 실행하는 해석기로 바꾼다 — 해석기와 그 시험(12-G1a), 서버 · 앱에 붙임(12-G1b — 아래
[서버에 붙임](#서버에-붙임-12-g1b)).

## 무엇

- **같은 글이 목표**: transformers 가 채팅 템플릿에 쓰는 jinja2 환경과 바이트까지 같은 글을 낸다 — `ImmutableSandboxedEnvironment`
  (trim_blocks · lstrip_blocks · loopcontrols · `{% generation %}` 태그), `tojson` = `json.dumps(x, ensure_ascii=False, indent=…,
  separators=…)`, 전역 `raise_exception`. `strftime_now` 는 두지 않는다 — 같은 요청이 같은 토큰이 되도록 날짜는 맥락의 `date_string`
  (서버의 기본 '26 Jul 2024', 39단계의 사용자 결정 그대로).
- **파일**: [엔진/진값.gl](../엔진/진값.gl)(값 — 제이슨.gl 의 마디에 Undefined · namespace · macro 를 더한 것, 파이썬의 str · repr · ==
  · < · in), [엔진/진풀기.gl](../엔진/진풀기.gl)(템플릿 → 마디 나무 — jinja2 의 lexer · parser 와 같은 공백 다루기와 식의 우선순위),
  [엔진/진해석.gl](../엔진/진해석.gl)(실행 — 문장 · 식 · 거르개 · 시험 · 메서드). 시험 도구는 [엔진/시험_틀해석.gl](../엔진/시험_틀해석.gl)
  과 [시험/틀해석.py](../시험/틀해석.py).
- **받는 것**: if · elif · else, for(loop 의 index · index0 · revindex · first · last · length · previtem · nextitem, else, `if` 거르기,
  break · continue), set(이름 · 튜플 · `ns.x`, 덩이 set 과 그 거르개), macro(기본값 · 이름 붙은 인자), filter 덩이, raw, 주석.
  식은 jinja2 의 우선순위 그대로(`~` 가 `+` · `-` 보다 단단하다, 거르개 · 시험은 홑셈 뒤, `a if b else c`, 견줌의 사슬). 거르개 —
  length · count · trim · tojson · string · safe · list · first · last · join · default · upper · lower · title · capitalize · replace ·
  items · dictsort · sort · unique · reverse · min · max · sum · map · select · reject · selectattr · rejectattr · int · float · abs ·
  indent · escape · format(`%` 서식). 시험 — defined · undefined · none · string · number · integer · float · boolean · true · false ·
  mapping · iterable · sequence · callable · even · odd · divisibleby · eq · ne · lt · le · gt · ge · in · lower · upper · sameas.
  메서드 — 글의 strip · lstrip · rstrip · split · rsplit · startswith · endswith · replace · upper · lower · title · capitalize · find ·
  rfind · index · count · join · splitlines · is… · format, 사전의 items · keys · values · get. 전역 — namespace · range · dict ·
  raise_exception.
- **이름의 범위**: jinja2 그대로 — 맨 위의 set 은 전역(매크로도 본다), for 의 몸은 바퀴마다 새 범위(밖으로도 다음 바퀴로도 이어지지
  않는다 — 그래서 템플릿은 namespace 를 쓴다), if 는 범위를 만들지 않는다. 정의되지 않은 이름은 Undefined(찍으면 빈 글 · 거짓 · 빈
  반복), 그 속성 · 첨자를 읽으면 오류.
- **아직 받지 않는 것**: 글 format 의 서식(`'{:>5}'`), recursive 반복, call 덩이, with · include · import · extends, `*args` · `**kwargs`.
  유니코드의 대소문자 바꿈(upper · lower 는 ASCII 만)과 파이썬 repr 의 '찍을 수 없는 글자' 판정은 어림이다.
- **망가진 GGUF 에 대비한 한도**: 식 · 블록의 겹침 40, 매크로 부르기 깊이 40, 걸음 5,000만, 글 · 출력 64 MB, range 10만, 값의 겹침
  200 — 넘으면 죽지 않고 오류로 끝난다(시험의 '한도' 사례).

## 서버에 붙임 (12-G1b)

서버([엔진/채팅틀.gl](../엔진/채팅틀.gl))는 모델을 올릴 때 GGUF 의 템플릿을 한 번 풀고, `/v1/chat/completions` · `/tokenize`(messages)마다
맥락을 지어 그린다. 손으로 짠 템플릿(ChatML · Qwen3 · Llama 3 · Mistral · DeepSeek-R1 · 기본 ChatML · MiniCPM5)과 모델마다의 꼴 고르기는
지웠다. 터미널 실행기(엔진/대화.gl — 차례마다 캐시를 이어 쓰는 덩이)는 그대로다.

- **맥락**: `messages`(아래의 다듬기), `tools`(보냈고 tool_choice 가 none 이 아닐 때), `add_generation_prompt` 참, `bos_token` · `eos_token`
  (GGUF 의 bos · eos_token_id 의 글 — 모델의 갈래와 상관없이), `date_string`(기본 '26 Jul 2024'), `enable_thinking`(chat_template_kwargs 에
  있을 때만), 그 밖의 `chat_template_kwargs` 그대로.
- **메시지 다듬기**(vLLM · llama.cpp 와 같은 규칙, 모델마다의 갈래 없음): role 의 developer → system · ipython → tool, content 의 조각 배열
  (type text)은 이어 붙인 글 · null · 없음은 빈 글, tool_calls 의 arguments 가 글이면 JSON 으로 풀어서(템플릿이 `arguments is string` 으로
  글을 그대로 쓰는 꼴 — Qwen3 — 이면 글 그대로), 템플릿이 system 말을 그리지 않으면(올릴 때 그려 본다 — Mistral v0.3) 맨 앞 system 말을 첫
  user 말 앞에 `{system}\n\n` 으로(39단계와 같다).
- **BOS**: 템플릿이 그린 글(`{{ bos_token }}`)을 그대로 토큰으로 — 채팅 길에서 따로 붙이지 않는다(vLLM · transformers 와 같다).
- **템플릿이 없는 파일**: llama.cpp 처럼 기본 ChatML 템플릿(common/chat.cpp 의 `CHATML_TEMPLATE_SRC` 와 같은 글 — 메시지마다
  `<|im_start|>role\ncontent<|im_end|>\n`, 끝에 `<|im_start|>assistant\n`). 서버는 올릴 때 그 말을 남긴다.
- **풀리지 않는 템플릿**: 서버는 올릴 때 까닭을 남기고 채팅은 400(글 완성 `/v1/completions` 는 된다). 앱은 그런 파일을 받지 않는다(모델
  확인이 같은 해석기로 풀어 본다 — [앱/모델보기.gl](../앱/모델보기.gl)).
- **도구 호출의 출력 꼴**(템플릿의 글로 고른다 — `틀도구꼴`): 1 Qwen 의 `<tool_call>{JSON}</tool_call>`, 2 Llama 3 의 JSON(pre llama-bpe),
  3 Qwen3.5 · Qwen3-Coder 의 `<tool_call>` 안 `<function=이름><parameter=키>값</parameter></function>`, 4 MiniCPM 의
  `<function name="이름"><param name="키">값</param></function>`(제어 토큰). XML 꼴의 값은 요청의 tools 의 JSON 스키마 형으로 바꾼다(vLLM 의
  qwen3coder 파서와 같은 규칙 — 글 · 정수 · 수 · boolean · object · array · null). 템플릿이 tools 를 그리지 않거나 이 넷이 아니면 tools 는 400.
- **생각**: 템플릿이 `<think>` 를 쓰면 도구 요청의 생각을 `reasoning_content` 로 뗀다(전에는 Qwen3 만). 그때 생성 머리가 생각을 연 채
  끝나면(`<think>\n` — R1-Distill-Llama · Qwen3.5 의 생각 켬) 생각 칸에서 시작한다.
