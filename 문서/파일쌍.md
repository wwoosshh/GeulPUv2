# 파일 쌍 재현성

*영어판: [docs/file-pair.md](../docs/file-pair.md).*

GeulPU 앱의 벤치마크 항목(0.11.1 부터). 같은 모델을 다르게 양자화한 GGUF 파일들을 **정밀 모드**로 돌려 두 가지를 본다.

1. **실행이 재현되는가**: 문제 32 개의 스텝마다 나오는 로짓 행의 FNV-1a 64 해시를 기준 PC 가 적은 해시와 견준다. 다른 GPU 에서 해시가
   같으면 그 GPU 가 스텝마다 같은 비트를 셈한 것이다.
2. **파일끼리 얼마나 다른가**: 기준 파일 `default` 와 견주는 파일마다 — 그리디 답이 처음 갈리는 스텝, `default` 의 답을 다른 파일로 echo
   점수 매긴 토큰마다의 로그확률 차(`도구/debugger.py compare` 와 같은 셈 · 같은 더하기 차례).

파일은 Wei-Liang Liu · Cheng-Yen Tsai 가 GGUF 양자화 공급망의 검증 공백을 다룬 논문([arXiv:2610.19498](https://arxiv.org/abs/2610.19498), 아티팩트
저장소 [gguf-verifiability-artifact](https://github.com/Rlonglong/gguf-verifiability-artifact))에서 준 것이다. 논문은 *파일*을 검증할 수 있게
한다(양자화가 비트까지 다시 만들어지는가). 이 항목은 *실행*을 검증할 수 있게 한다(파일이 내는 로짓이 어느 GPU 에서나 같은가).

## 파일

| 라벨 | 파일 | 크기 | SHA-256 | 출처 |

| `ffpoff` | Qwen2.5-1.5B-Instruct-Q4_K_M-b10448-ffpoff.gguf | 986,048,512 | `52e47664d0a0001bd58ffdd16beb6e6a0b3609bbfee7a439a462dc6285a23281` | 같음 |
| `imatrix` | Qwen2.5-1.5B-Instruct-Q4_K_M.gguf | 986,048,768 | `1adf0b11065d8ad2e8123ea110d1ec956dab4ab038eab665614adba04b6c3370` | [bartowski/Qwen2.5-1.5B-Instruct-GGUF](https://huggingface.co/bartowski/Qwen2.5-1.5B-Instruct-GGUF) |

| `7b-q8_0` | Qwen2.5-7B-Instruct-Q8_0.gguf | 8,098,525,888 | `9c6a6e61664446321d9c0dd7ee28a0d03914277609e21bc0e1fce4abe780ce1b` | 같음 |

- `default` · `ffpoff` 는 같은 bartowski f16 을 llama.cpp b10448 로 imatrix 없이 양자화했고, `llama-quantize` 의 빌드만 다르다 — arm64 ·
  Apple clang 에서 FP 축약을 켠 것과, 같은 호스트에서 `ggml-quants.c` 를 `-ffp-contract=off` 로 빌드한 것(x86_64 기본 빌드와 바이트까지 같다).
  머리말 · 메타데이터는 같고 텐서 338 개 가운데 197 개가 다르다(모든 바이트의 4.2 × 10⁻⁴). wikitext-2 퍼플렉시티는 10.7437 · 10.7500 —
  퍼플렉시티로는 구별되지 않는, 바이트가 다른 두 파일이다.
- `imatrix` 는 bartowski 의 imatrix 양자화 — 같은 양자화의 셋째 빌드가 아니라 다른 양자화다.
- `7b-q4km` · `7b-q8_0` 은 논문이 바이트까지 다시 만들어 낸 bartowski 의 파일.

## 설정

정밀 모드(활성값 int8 두 자리 · 16비트 KV 캐시 · 빠른 어텐션 없음 — [계약](../계약/계약.md)), 그리디(온도 0), 새 토큰 512 까지, 문맥 1,024.
문제 32 개는 앱의 재현성 검증의 것이다. 프롬프트는 Qwen2.5 의 채팅 틀에 기본 시스템 프롬프트를 쓴 것을 토큰 번호 그대로 `/v1/completions` 로
보낸다 — 판마다 채팅 틀의 코드가 달라도 같은 프롬프트([교차검증/쌍/requests.json](../교차검증/쌍/requests.json), [도구/쌍기준.py](../도구/쌍기준.py)
가 만든다). 기준 해시는 [교차검증/쌍/expected.json](../교차검증/쌍/expected.json).

## 돌리기

1. GeulPU 0.11.1 이상을 설치하고 **벤치마크 → 파일 쌍 재현성**을 연다.
2. 카드에서 파일을 받는다(받은 뒤 SHA-256 을 확인한다). 그래픽 메모리가 파일보다 1 GB 이상 커야 그 파일을 돌린다 — 1.5B 는 약 2 GB,
   `7b-q8_0` 은 약 9 GB.
3. 파일을 고르고 **실행**. 그 GPU 에서 처음이면 커널 모듈을 만들고 커널 변형을 재느라 몇 분 걸린다(내장 그래픽은 10 분 넘게). 다음부터는
   그대로 쓴다.
4. 결과에서 **zip 내보내기**. 폴더에는 `summary.json`(파일마다 같음 n / 32, 다른 문제의 처음 다른 스텝 · `pairs` — 파일끼리),
   `environment.json`(GeulPU 판 · 커밋, 계약 문서 · CPU 참조의 SHA-256, GPU · 드라이버 · OS), `<라벨>/responses/NN.json`(응답마다 스텝마다
   해시), `<라벨>/run.jsonl`(디버거 꼴의 실행 로그), `pair-default-<B>.json`(토큰마다의 차)이 있다.

AMD GPU 는 Vulkan 으로 돈다. Windows 의 AMD 드라이버(공유 메모리 32 KB)에서 k-양자화 파일은 0.11.1 부터 돈다.

## GPU 없이 확인하기

실행 로그는 계약의 CPU 참조 구현으로 다시 셈할 수 있다(numpy 만 — macOS · Linux 도):

```
python -I 도구/repro_check.py <결과>/default/run.jsonl Qwen2.5-1.5B-Instruct-Q4_K_M-b10448-default-arm64.gguf --requests 0,1
```

고른 요청의 스텝마다 로짓 행을 다시 셈해 FNV-1a 64 해시와 그리디 토큰을 기록과 견준다. 1.5B 의 요청 하나에 데스크톱 CPU 로 10 분 남짓이라
몇 개만 고른다.

## 기준 결과

기준 PC: NVIDIA GeForce RTX 4070 Ti · 드라이버 616.56 · Windows 11 · Intel Core i7-14700K. GeulPU 0.11.1 — 커밋 `bbb6cb3`(릴리스의 코드)으로
꾸린 것, 계약 문서 SHA-256 `faf48d77…` · CPU 참조 SHA-256 `abf2fcd5…`. 기준과 CUDA 로 견준 실행의 파일은
[교차검증/쌍/기준결과/](../교차검증/쌍/기준결과/) — `summary.json` · `environment.json` · 파일마다 실행 로그 · 토큰마다의 차.

| 경로(같은 PC · 정밀 모드) | default | ffpoff | imatrix | 7b-q4km | 7b-q8_0 |
|---|---|---|---|---|---|
| CUDA — 기록한 기준(스텝 수) | 14,720 | 14,673 | 14,783 | 15,083 | 14,658 |
| CUDA — 기준과 견준 두 번째 실행 | 32/32 | 32/32 | 32/32 | 32/32 | 32/32 |
| Vulkan · 공유 메모리 32 KB 흉내(Windows 의 AMD 드라이버가 타는 길) | 32/32 | 32/32 | 32/32 | 32/32 | 32/32 |
| GeulPU main(b944da6)을 앱의 디버거로 — 채팅 API · 문맥 4,096 · 슬롯 2 | 32/32 | 32/32 | 32/32 | 32/32 | 32/32 |

"32/32" = 모든 문제에서 프롬프트 토큰 · 나온 토큰 · 스텝마다 로짓 해시가 같다(경로마다 73,917 스텝). 마지막 줄은 개발 빌드로, 다른 요청 길 ·
문맥 · 배치로 따로 기록한 것인데 같은 비트다.

**파일끼리**(CUDA, A = `default` — 위의 어느 경로에서나 같은 값):

| A ↔ B | 같은 답 | 처음 갈리는 스텝(가운데값 · 최소 ~ 최대) | 토큰당 로그확률 차(B − A) | B 의 1 위가 A 의 토큰과 다른 스텝 |
|---|---|---|---|---|
| default ↔ ffpoff | 19 / 32 | 219 (52 ~ 491) | +0.0000917(14,720 토큰의 합 +1.3505) | 14,720 가운데 17 |
| default ↔ imatrix | 0 / 32 | 29 (1 ~ 169) | −0.0113(합 −166.88) | 14,720 가운데 253 |

- 퍼플렉시티로는 보이지 않는 바이트 차이(`default` ↔ `ffpoff`)가 그리디 생성에서 32 문제 가운데 13 문제의 글을 바꾼다. 토큰마다의 차는
  평균 10⁻⁴ 급이지만, 1 위 · 2 위가 가까운 스텝 하나에서 다른 토큰을 고르면 그 뒤가 달라진다. '같은 답'은 생성한 토큰을 견준 것이고, 수학 답의
  마지막 수를 견준 것이 아니다.
- 스텝은 0 부터 센다(처음 생성한 토큰이 스텝 0).
- CPU 확인: `default` 의 요청 1(프롬프트 47 · 답 217 토큰)을 `default.run.jsonl` 에서 `도구/repro_check.py` 로 다시 셈했다 — 217 스텝 모두 로짓
  해시 · 그리디 토큰이 같다(Intel Core i7-14700K 로 13 분 — `기준결과/cpu_check_default_r1.json`).
