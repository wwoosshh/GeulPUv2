# 프롬프트 행렬곱 — 텐서 코어를 채우기 (#140) — 계획 (2026-10-30)

*상태: P0 끝, P1 닫음(2026-10-30 — 척도 바꾸기는 H100 에서 느려 되돌렸다. 아래 'P1 처방'). 단계마다 판정은 그 단계를 재기 전에 적는다.*

## 0. 왜

- 프롬프트의 행렬곱은 정수 바닥의 4.7 ~ 7.6 배 시간이다(H100 NVL MIG 3g.47gb — [H100.md](H100.md) 3.6). 같은 모듈로 H100 MIG 인스턴스가
  RTX 4070 Ti 보다 1.5 배 느리다. 둘 다 SM 이 60 개이고 인스턴스의 클럭(1,785 MHz)이 낮다 — 텐서 코어 · 메모리가 아니라 SM 이 명령을 내는
  빠르기에 묶인다. 행렬곱은 SM · 클럭당 1,025 연산(H100 MIG) · 956 연산(RTX 4070 Ti)을 한다(H100.md 3.5).
- 에이전트 세션에서 프롬프트 처리는 시간의 38 ~ 43 % 였다(llama.cpp 로 잰 것 — [MoE재기.md](MoE재기.md)). 되풀이는 문맥 저장소가 덜지만 새
  프롬프트는 남는다. 프롬프트가 빨라지면 두 GPU 모두에서 사용자가 바로 느낀다.

## 1. 계약이 정하는 천장 — 빠른 모드 계약을 바꿔야 하나

계약([계약.md](../계약/계약.md) 1 · 1.1 · 1.2)은 선형층의 셈을 32 칸 블록마다 실수 끝셈으로 정한다. 빠른 모드(F1)는 매직 넘버 누산으로
정수→실수 · 눈금 곱을 덜어, 출력 칸 하나 · 블록 하나에 명령이

| 형식 | 끝셈(칸 · 블록마다) | m16n8k32 텐서곱 하나(워프 — 스레드마다 칸 넷)에 |
|---|---|---|
| Q8_0 · IQ4_XS | 마법수 빼기 FADD · 곱해더하기 FFMA — 2 | 8 |
| Q4_K · Q5_K | 위 둘 + 최솟값 항 FFMA — 3 | 12 |
| Q6_K | 16 칸 아래블록마다 2(m16n8k16 텐서곱) | 16(32 칸에) |

Nsight 로 잰 지금 판은 텐서곱 하나에 명령이 Q4_K 23 개(그 가운데 끝셈 12.3) · Q8_0 18 개(끝셈 8)다(RTX 4070 Ti — [2c단계.md](2c단계.md)
2c-0, [0.11.0.md](0.11.0.md) 1-1).

**천장의 셈.** SM 은 클럭마다 워프 명령을 넷(스케줄러 넷) 낸다 — 스레드 칸으로 128. 끝셈이 칸 · 블록마다 c 개면 끝셈만으로 SM · 클럭당
128 / c 칸-블록, 칸-블록 하나는 32 번의 곱해더하기(64 연산)라 천장은 **8,192 / c 연산**이다. c 는 텐서 코어의 종류에 따라 다르다
(2026-10-30 고침): mma.sync 는 C 피연산자가 따로라 마법수 시작값을 레지스터 하나로 거듭 주지만, wgmma 는 누산기가 D 하나라(scale-d)
블록마다 칸마다 시작값을 넣는 명령이 하나 더 든다 — wgmma 의 c 는 하나 크다.

| SM · 클럭당 연산 | RTX 4070 Ti(2.61 GHz) | H100 MIG(1,785 MHz) |
|---|---|---|
| 텐서 코어 최고치 — mma.sync s8 | 2,044 | 4,812 |
| 텐서 코어 최고치 — wgmma s8(sm_90a) | — | 7,403 |
| 끝셈의 천장 — Q8_0(mma.sync c = 2) | 4,096 | 4,096 |
| 끝셈의 천장 — Q4_K · Q5_K(mma.sync c = 3) | 2,731 | 2,731 |
| 끝셈의 천장 — wgmma(Q8_0 c = 3 · Q4_K c = 4) | — | 2,731 · 2,048 |
| 지금 — Q8_0 빠름 | 956(Qwen2.5-7B, 프롬프트 2,048 — 2c-0) | 1,025(Qwen3-8B, 2,048 — 3.5) · 1,014(Qwen3-32B, 8,192 — 3.6) |
| 지금 — Q4_K 빠름 | 약 700(2c-0 — 텐서 바닥 대비 34 ~ 37 %) | 659(Llama-3.1-8B, 8,192 — 3.6) |

- **RTX 4070 Ti** 는 텐서 코어(2,044)가 끝셈의 천장보다 낮다 — 지금 계약으로 텐서에 묶일 수 있다. 남은 몫(956 → 2,044, 2.1 배까지)은 끝셈
  밖의 명령(읽기 · 주소 · 정수 · 반복 조절 — Q4_K 텐서곱당 약 11)과 지연(점유 23 ~ 25 %)이다.
- **H100** 은 지금 계약의 끝셈만으로 Q8_0 4,096(지금의 4.0 배) · Q4_K 2,731(지금 659 의 4.1 배)이 천장이다(mma.sync). 거기까지는 계약을
  바꾸지 않고 간다. wgmma 는 피연산자 읽기 · 주소 셈을 워프의 명령에서 빼지만 시작값 명령이 더해져 끝셈의 천장이 Q8_0 2,731 · Q4_K 2,048
  로 내려간다 — 그래도 지금의 2.7 배 · 3.1 배다.
- **그래서 계약 개정은 먼저가 아니다.** 지금 판은 H100 에서 두 형식 모두 제 천장의 약 25 % 다. 계약이 묶는 곳은 H100 의 k-양자화가
  2,731 에 닿은 뒤다. Q8_0 은 파일 형식(32 칸마다 반실수 척도)이 끝셈 둘을 정해, 가중치를 다시 양자화하지 않는 한 어떤 계약도 4,096 을
  넘기지 못한다.

**읽기.**
1. 끝셈 밖의 명령이 Q8_0 에 9 개 남짓 · Q4_K 에 11 개 남짓이다. 어디서 오는지 보인다.
   - 피연산자를 `ldmatrix`(LDSM 0.13)가 아니라 거의 낱개 LDS(1.9)로 읽는다.
   - 척도의 반실수→실수(HADD2.F32 1.0)와 마법수 시작값(MOV 1.0 ~ 1.7)을 텐서곱마다 다시 만든다.
   - k-양자화는 니블 · 6비트 풀기(LOP3 + SHF 2.7 ~ 3.2)가 있다.
   - 주소 셈(IADD3 · SHF · IMAD)이 1.5 ~ 2 다.
2. 점유가 모두 23 ~ 25 % 다(레지스터 152 ~ 168 — 128 스레드 블록이 SM 에 셋). 명령 내기 51 ~ 67 % 라 지연을 다 숨기지 못한다.
3. **Q6_K 가 가장 비싸다.** 계약이 16 칸 아래블록마다 끝셈을 정해(1.1 절) k16 텐서곱 하나에 끝셈만 8 — 32 칸으로 16 이다. 끝셈의 천장이
   8,192 / 4 = 2,048 로, RTX 4070 Ti 에서도 텐서 바쁨이 26 ~ 30 % 다. Q4_K_M 파일은 v 와 down 의 절반이 Q6_K 라 Llama 의 down(Q6_K)이
   gate·up(Q4_K)보다 곱하기 하나에 약 40 % 느리다(1,303.5 µs · 60 G 곱하기 대 1,876.6 µs · 120 G).
4. 프롬프트의 어텐션(정수어텐션묶음)도 텐서곱에 16 ~ 22 명령 · 텐서 바쁨 37 ~ 47 % 다 — 이 계획의 밖(#139 먼저).

## P1 — mma.sync 판의 끝셈 밖 명령 줄이기 (판정 — P0 뒤에, P1 을 재기 전에 정함)

**고칠 것**(비트 그대로 — 계약 1 · 1.1 · 1.2 의 식 · 차례는 그대로).
1. 피연산자 읽기를 `ldmatrix.x4` 로. 지금은 LDS 1.9 다.
2. 척도의 실수 바꾸기와 마법수 시작값을 텐서곱마다가 아니라 (열, 블록)마다 한 번 둔다. 워프 타일의 m 조각들이 함께 쓰고, C 피연산자에
   같은 레지스터를 되풀이해 준다.
3. 워프 타일과 레지스터 · 점유를 다시 잡는다(척도를 나눠 쓰는 넓이와 레지스터 사이).
4. k-양자화의 가중치를 불러올 때 텐서곱 조각의 차례로 다시 놓는다. 바이트의 자리만 옮기고 값은 그대로라, 니블 · 6비트 풀기가 준다.
5. 주소 셈은 달리는 포인터와 32 비트 색인으로 — 2c 에 남긴 처방이다.

**판정**
- **A 비트**: 판 시험(시험/판23.py · 판26.py — 바뀐 판마다), 다섯 길(시험_7B), 시험/구조회귀.py, CPU 참조가 그대로다. 커널을 바꾸면
  시험/모듈해시.txt 와 시험/SASS넘침.txt 를 같은 PR 에서 고친다.
- **B 명령**(이 PC · P0 와 같은 설정 · 빠름): 텐서곱당 명령이 Q8_0 ≤ 13.5(지금 16.7 ~ 17.6) · Q4_K ≤ 17.5(지금 21.9 ~ 22.2) · Q6_K ≤ 14.5
  (k16 — 지금 17.7 ~ 18.0)이다. 층 10 에서 엔진이 고른 판으로 본다.
- **C 속도**(이 PC — 엔진/재기_걸음 의 프롬프트 모드 · 판의 합, 최대길이 8,704):
  - Qwen3-8B Q8_0 · Llama-3.1-8B Q4_K_M 빠름의 행렬곱이 프롬프트 2,048 · 8,192 에서 10 % 넘게 짧다.
  - 정밀 모드 · 512 를 비롯해 어디서도 1 % 넘게 느려지지 않는다.
- **H100**(원격 — 실행마다 승인): P1 뒤에 재 3.6 의 표에 더한다. 판정에는 넣지 않는다.
- 처방마다 재고, 빨라지지 않는 것은 되돌린다(2c 와 같다). B 나 C 에 못 미치면 까닭을 적고 P2 로 간다.

### P1 처방 — 고칠 것 2 의 척도 바꾸기 (RTX 4070 Ti · H100, 2026-10-30 — 되돌림)

**한 것.** 척도의 반실수 → 짧은실수를 스레드가 열 조각마다(텐서곱마다 하나 — 정밀은 반) 하지 않고 (열, 블록)마다 워프에서 한 번 한다.
블록의 동기화 뒤에 워프가 제 열 WC 개를 레인마다 하나 · 둘씩 바꿔 워프의 실수 자리에 두고(워프 동기화), 열 조각마다 둘을 한 번에
(LDS.64) 읽는다. 같은 반실수를 같은 명령으로 바꾸므로 값이 같다. 꼴 다섯을 짜 보았다(세판 SwiGLU 판의 주 반복 — 정적 SASS, 텐서곱당).
