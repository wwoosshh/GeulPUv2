[앱리디자인.md](앱리디자인.md) §5 의 단계 E: [화면설계.md](화면설계.md)의 화면(사용자 검토 2026-11-09 — 모두 시안대로)을 앱에 만든다.
결정 3 대로 옛 화면은 새 화면이 그 일을 다 할 때까지 두고 하나씩 바꾼다. 하위 단계마다 PR 하나이고, 판정은 그 하위 단계를 실행하기

단계 E 의 판정(앱리디자인.md §5) — 화면마다 그 수준의 기능이 모두 GUI 에서 닿고 옛 화면과 같은 결과(같은 API 결과)이며, 명령 창에 입력한
명령과 AI 의 명령이 GUI 에 반영된다 — 은 하위 단계의 판정이 나눠 맡는다.

## 1. E1 — 명령 창

**서버(앱 — 글)**
- **이벤트의 인자:** `start` 이벤트에 `params`(요청 본문 — C2 의 명령 기록과 같은 것)와 `experiment`(요청 헤더 `X-GeulPU-Experiment` 가 실험
  폴더일 때 그 경로)를 더한다. 본문이 JSON 객체가 아니거나 16 KB 를 넘으면 `params` 대신 `params_bytes`(바이트 수)만 적는다 — 앱이 메모리에
  두는 이벤트 1024 개가 16 MB 를 넘지 않게. 명령 기록(`records/commands.jsonl`)은 지금처럼 본문 전체를 적는다.
- **기능 목록 내보내기:** `GET /api/operations` → `data/operations.json` 그대로. 기능 `system.operations`(내부용 — 명령 창이 명령을 해석할 때
  읽는다. CLI 에는 `ops` 가 있다).
- **모듈 파일:** `GET /ui/<이름>.js` → `web\ui\<이름>.js`(이름은 `[a-z0-9-]`, `text/javascript`).
- **출처는 그대로:** 입력 줄은 사용자가 친 CLI 명령이므로 `X-GeulPU-Source: cli`(세션 없음)로 보낸다.

**화면(웹)**
- **배치:** 지금 화면 8 개 모두의 오른쪽에 명령 창. 처음에는 열림(380px — 화면설계.md §10 결정 3), 접으면 폭 40px, 크기 조절 핸들로
  280 ~ 640px, 폭 768px 아래에서는 아래 창(높이 40%). 접힘과 폭은 이 브라우저에 기억한다. 왼쪽과 명령 창은 따로 스크롤한다.
- **줄:** 기능 호출 하나에 한 줄 — 출처(GUI · 사용자 CLI · AI · 세션 이름 · 파이썬 · 알 수 없음) · 명령(이벤트의 `params` 를 CLI 형식으로 다시
  쓴 것 — 긴 값은 줄여 보이고 줄을 누르면 전체) · 상태(실행 중 → HTTP 상태) · 걸린 시간 · 실험. `start` 가 오면 실행 중, `end` 가 오면 결과를
  적는다. 놓친 이벤트(`oldest > after + 1`)는 그 위치에 한 줄로 알리고, 앱이 다시 켜졌으면(`last < after`) 처음부터 받는다. 이벤트는 롱
  폴링(long polling, `GET /api/events?after=&wait=`)으로 받는다.
- **명령 복사:** 줄마다 CLI 에 그대로 입력할 수 있는 명령 — 기능 목록의 `cli.en` 과 인자. 목록에 없는 필드가 본문에 있으면
  `--json '<본문>'`.
- **입력 줄:** CLI 와 같은 문법 — 명령 이름(`cli.en` · `cli.ko` · 기능 id, 앞의 `GeulPU` 는 있어도 되고 없어도 됨), `--인자 값` ·
  `--인자=값`, `--json`, `--experiment`, `--wait`, `--dry-run`. 기능 목록에서 요청을 만들고, 사용법 오류는 CLI 와 같은 까닭과 다음에 할 일을
  보인다. `help <명령>` · `ops` 는 앱을 부르지 않고 명령 창에 보인다. 단축키: `/` 입력 줄로 · `Esc` 나오기 · `]` 접기와 펼치기 · `↑` `↓` 이전에 친
  명령.
- **모듈:** 새 코드는 `앱/web/ui/` 의 ES 모듈 — `ops.js`(기능 목록 클라이언트: 기능 id 와 인자로 요청을 만들어 보낸다), `command.js`(명령
  해석과 명령 쓰기), `console.js`(명령 창). 새 코드는 앱을 이 클라이언트로만 부른다. 옛 화면의 코드는 옮기지 않는다(`app.js` 는 출처
  헤더를 이미 적은 요청을 덮어쓰지 않게 한 줄과 새 문구의 영어 사전만) — 옛 화면의 호출은 이벤트로 명령 창에 나온다.

**E1 의 판정(구현 전에 적음)**
1. **CLI 와 같은 요청:** 명령 예 40 개 이상(영어 · 한국어 이름 · 기능 id, 인자 자료형 다섯, 점(.)이 들어간 인자 이름, `--json`, GET 의 쿼리
   문자열, 사용법 오류 열 가지 이상)에서 입력 줄이 만드는 요청(op · method · path · body)이 CLI 의 `--dry-run` 과 같고, 오류는 같은 경우에
   난다 — 예 파일 하나를 CLI(빌드한 GeulPU.exe)와 명령 해석 모듈(node)이 각각 통과한다. 명령 복사로 만든 명령을 다시 해석하면 같은 요청이
   된다.
2. **네 출처가 명령 창에:** 시험 인스턴스에서 GUI(옛 화면의 동작) · 터미널의 CLI(세션 없음 · 있음) · 파이썬 API · 입력 줄로 부른 POST
   기능이 각각 한 줄로, 이벤트가 난 뒤 1 초 안에 맞는 출처 · 명령 · 상태로 나온다. `--experiment` 로 부른 호출은 줄에 그 실험이 보인다.
3. **이벤트의 인자:** `start` 의 `params` 가 보낸 본문과 같고, 16 KB 를 넘는 본문은 `params_bytes` 만 있다. 기존 API 응답은 바이트까지
   그대로다(main 에서 빌드한 앱과 같은 요청 12 개).
4. **배치:** 실제 브라우저에서 — 처음에 열림 380px, 접기 · 펼치기와 폭 조절, 두 창이 따로 스크롤(실제 휠 이벤트), 375 × 812 에서 아래 창이고
   가로로 넘치지 않음, 지금 화면 8 개가 모두 열리고 브라우저 콘솔에 오류 없음.
5. **점검:** 기능 목록 점검(`system.operations` 내부용) · 화면 문구 점검(새 문구의 영어) · 빠른 점검이 통과하고, CI 가 명령 해석 시험(node)을
   돈다.

판정 2 · 3 · 4 는 GPU 를 쓰지 않는다 — 앱이 켜질 때의 장치 확인만 GPU 줄로.

## 2. E2 — 실험 화면

**서버(앱 — 글)**
- **실험 파일 읽기:** 새 기능 `experiment.read` — `GET /api/experiments/read?path=<실험 폴더|id>&file=<실험 폴더 안의 상대 경로>&root=` →
  `{"path","file","bytes","text"}`. 텍스트 파일(.md · .json · .jsonl · .txt · .csv · .py · .sh · .log · .yaml · .yml)만, 2 MB 까지. 절대 경로 ·
  `..` · 드라이브 문자는 받지 않는다(실험 폴더 밖의 파일을 읽지 못하게). CLI 에서는 `experiment read`.
- **실험 목록의 요약:** `experiment.list` 의 실험마다 `models`(모델 이름) · `runs`(실행 수) · `criteria`(`{"total","pass","fail"}`) ·
  `commands`(명령 기록의 줄 수)를 더한다 — 목록 화면이 실험마다 따로 묻지 않게. 지금의 필드는 그대로다.

**화면(웹)**
- **사이드바의 '실험':** 맨 위에 '실험'을 더하고, 앱을 열면 실험 목록이 첫 화면이다(화면설계.md §10 결정 2). 지금 화면 8 개는 그대로 있다.
- **실험 목록:** 실험 폴더 위치(폴더 선택으로 바꾸고 이 브라우저에 기억), 실험마다 한 줄(제목 · 상태 · id · 모델 · 실행 수 · 판정 통과 수 / 기준
  수 · 명령 수), 새 실험(이름 · 제목 · 연구 질문). 목록 끝에 '대화'(채팅 화면으로 — 채팅을 기본 실험으로 옮기는 것은 E5).
- **실험 화면:** 경로(실험 › id), 헤더(제목 · 연구 질문 · 상태 · 만든 날), 실행 정보 줄(모델 · SHA-256 앞 8 자 · 계산 방식 · GeulPU 버전), 탭 셋:
  - 계획 — 판정 기준(id · 내용 · 판정)과 plan.md,
  - 결과 — 판정 기준마다의 판정과 results.md,
  - 기록 — 명령 기록(records/commands.jsonl — 줄마다 출처 · 명령 · 상태 · 걸린 시간 · 명령 복사), 파일(experiment.json 의 files — 경로 · 크기 ·
    SHA-256 앞 8 자), 재현 명령(reproduce), 점검(experiment.check — 작업, 판정과 문제 목록).
  실행 · 비교 탭은 실행 화면(E3)과 함께 더한다.
- **실험 안의 호출은 실험의 기록에:** 실험 화면에서 부른 기능(점검)은 `X-GeulPU-Experiment` 를 붙여 명령 기록에 남는다. 다른 곳(CLI · AI
  세션)에서 이 실험으로 부른 호출이 끝나면 기록 탭이 바로 다시 읽는다(이벤트).
- **명령 창에서 실험으로:** 실험이 있는 줄의 '실험 …' 을 누르면 그 실험 화면이 열린다.
- **모듈:** `앱/web/ui/experiments.js`. 명령 창(console.js)이 받은 이벤트를 화면에 알린다(`geulpu:event`). app.js 는 사이드바 항목 · 화면 전환
  알림(`geulpu:view`) · 첫 화면 · 영어 사전만 바꾼다.

**E2 의 판정(구현 전에 적음)**
1. **목록과 CLI 가 같다:** 시험 인스턴스에서 실험 셋(CLI 로 둘, 화면의 새 실험으로 하나)이 목록에 모두 있고, 줄의 값(제목 · 상태 · 모델 · 실행
   수 · 판정 · 명령 수)이 `experiment list` 의 답과 같다. 화면에서 만든 실험은 점검 도구(`experiment check`)를 통과한다. 실험 폴더 위치를 바꾸면
   그 위치의 실험이 보인다.
2. **실험 화면이 파일과 같다:** 계획 · 결과 탭의 글이 plan.md · results.md 와 같고, 판정 기준이 experiment.json 과 같으며, 기록 탭의 명령 기록이
   records/commands.jsonl 의 줄과 같다(수 · 순서 · 기능 · 출처 · 상태).
3. **실험 안의 호출이 기록에 남는다:** 실험 화면의 점검이 작업으로 돌고 그 판정이 `experiment check --wait` 와 같으며, 그 호출이 명령 기록에
   `source: gui` 로 한 줄 남는다. 터미널에서 `--experiment` 로 부른 호출이 끝나면 기록 탭에 1 초 안에 나온다. 명령 창의 '실험 …' 을 누르면 그
   실험이 열린다.
4. **파일 읽기의 경계:** `experiment.read` 가 실험 폴더 밖(`..` · 절대 경로 · 드라이브 문자)과 텍스트가 아닌 파일 · 2 MB 를 넘는 파일을 거절하고,
   CLI 의 `experiment read` 가 같은 답을 낸다.
5. **화면과 점검:** 앱을 열면 실험 목록이고, 지금 화면 8 개가 그대로 열리며, 두 창이 따로 스크롤하고(실제 휠 이벤트), 좁은 화면에서 가로로 넘치지
   않고, 브라우저 콘솔에 스크립트 오류가 없고, 영어 화면 문구가 모두 바뀐다. 기능 목록 점검 · 명령줄 점검 · 화면 문구 점검이 통과하고, 실험 기능
   밖의 기존 응답 12 개는 바이트까지 그대로다.

**하지 않는 것(E2):** 실행 · 비교 탭과 실행 결과의 기록(E3), 계획 · 판정 기준 · 결과를 화면에서 쓰기(기록을 쓰는 기능과 함께 E3 에서 정한다),
채팅을 기본 실험으로(E5).
