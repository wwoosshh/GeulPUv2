# 연구 화면 설계 — 앱 리디자인 단계 D (계획과 판정, 2026-11-08)

[앱리디자인.md](앱리디자인.md) 의 단계 D — 정보 구조(information architecture)와 와이어프레임. 좌우 배치(왼쪽 GUI · 오른쪽 명령 창)를 기본으로
연구 과제마다 화면 흐름과 정적 시안을 만들고, 사용자 검토로 확정한다. 화면을 구현하는 것은 단계 E 다.

## 0. 만드는 것

- **이 문서:** 화면의 위계(레일 · 실험 · 실행 · 스텝/층), 연구 여정 열둘([기능지도.md](기능지도.md) §5)의 화면 흐름, 지금 화면의 기능이 옮겨 갈
  자리, 결과 형식마다 보여 줄 화면, 명령 창의 동작(앱리디자인.md §3), 좁은 화면 · 키보드 · 빈 상태 · 오류 상태.
- **정적 시안:** `문서/시안/연구화면.html` — 앱 패키지에 들지 않는 검토용 HTML 한 장. 값은 실제 실험(C3 의 등대 실험 — Qwen3-0.6B Q8_0, 마진이
  가장 작은 스텝 3 · 분기 · 27 층)에서 가져온다.
- **디자인 시스템에 더할 것:** 명령 창 · 토큰 줄 · 층 렌즈 표 · 출처 막대 같은 새 구성 요소의 규칙(앱/DESIGN.md · app.css 헤더 주석에 넣을 안).

## 1. D 의 판정(구현 전에 적음)

1. 이 문서에 위계 넷과 연구 여정 열둘의 화면 흐름(쓰는 기능 id 와 함께)이 있고, 지금 화면(채팅 · 연구 패널 · 모델 · 모델 평가 · 디버거 ·
   벤치마크 · 에이전트 · 장치 · 설정)의 기능이 모두 옮겨 갈 자리를 가진다 — 기능 목록의 `gui` 기준으로 빠짐 0.
2. 기능 목록의 결과 형식 39 개가 모두 새 화면의 자리를 가진다 — 빠짐 0.
3. 시안이 지금의 디자인 시스템을 따르고, 주요 화면 넷(실험 목록 · 실험 · 실행 · 스텝/층)과 명령 창의 세 경우(GUI 로 · 직접 입력 · AI 세션)를
   보여 준다. 두 창은 따로 스크롤되고(실제 휠 이벤트로 확인), 폭 768px 아래에서 명령 창이 아래 창이 된다 — 브라우저로 확인한다.
4. 사용자 검토: 사용자가 정할 것을 질문으로 모아 받고, 답을 반영한 뒤 병합한다(이 PR 은 자동 병합을 켜지 않는다).

## 2. 레이아웃 — 좌우 배치

```
[레일] [왼쪽: 지금 보는 화면                         ] [|] [오른쪽: 명령 창                ]
 실험   경로   실험 › 2026-11-08-c3-lighthouse › 실행 r1     출처 · 명령 · 상태 · 결과 한 줄
 모델   출처 막대  모델 · 해시 · 계산 방식 · GeulPU 버전 · 시드 …(이벤트가 쌓인다)
 재현   ─────────────────────────────────────────         …
 작업   내용 — 따로 스크롤                                  ─────────────────────────────
 설정                                                      입력 줄: GeulPU 명령
```

- **레일:** 왼쪽 끝의 세로 막대(56px) — 실험 · 모델 · 재현 · 작업 · 설정, 위에 로고. 지금 위치는 흰 표시, 진행 중인 작업이 있으면 작업에 강조색 점.
- **왼쪽(GUI):** 맨 위에 경로(누르면 그 화면으로)와 출처 막대(모델 이름 · 파일 해시 앞 8 자 · 계산 방식 · GeulPU 버전 · 시드 — 앱리디자인.md §2 원칙 4),
  그 아래 내용. 내용만 스크롤한다.
- **오른쪽(명령 창):** 기본 폭 380px, 가운데 손잡이로 280 ~ 640px, 접으면 폭 40px(새 줄이 오면 그 수를 표시). 줄 목록만 스크롤하고 입력 줄은 아래에
  붙는다.
- **좁은 화면(폭 768px 아래):** 레일은 위의 가로 막대, 명령 창은 아래 창(높이 40%, 접기 · 펼치기). 두 창은 여전히 따로 스크롤한다.

## 3. 위계 — 무엇이 어디에

| 수준 | 화면 | 담는 것 |
|---|---|---|
| 1. 레일 | 실험 · 모델 · 재현 · 작업 · 설정 | 첫 화면은 실험 목록 |
| 2. 실험 목록 | 실험마다 한 줄 | id · 제목 · 상태 · 모델 · 실행 수 · 판정(통과 수 / 기준 수). 새 실험, 실험의 자리(root) 바꾸기, 기본 실험 "대화"(가벼운 대화가 실행으로 쌓인다 — 앱리디자인.md §6 결정 2) |
| 3. 실험 하나 | 헤더와 탭 다섯 | 헤더: 연구 질문 · 상태 · 모델 · 출처 막대. 탭: 계획(가설 · 판정 기준 — 실행 전에 적고 고정) · 실행(목록 · 새 실행) · 비교(실행 둘 이상) · 결과(기준마다 판정 · 결론) · 기록(파일과 해시 · 명령 기록 · 점검 · 재현 확인) |
| 4. 실행 하나 | 토큰 줄과 개입 | 토큰 줄(스텝마다 고른 토큰의 확률 · 1 위와 2 위의 마진 · 엔트로피 · 로짓 해시), 마진이 가장 작은 스텝 표시, 개입(이 스텝에서 다른 토큰으로 분기 · 같은 난수로 설정만 바꾸기 · 활성값 바꾸기), 다른 실행과 비교(토큰이 처음 다른 스텝부터) |
| 5. 스텝 · 층 | 스텝 하나 | 상위 후보와 로그확률, 층 렌즈 표(층마다 1 위 토큰 · 고른 토큰의 순위 · 끝까지 1 위가 되는 첫 층), Jacobian lens, 점수(주어진 토큰의 로그확률), 활성값(내보내기 — 실험대 단계 6) |
| 레일: 모델 | 모델 파일 | 파일(더하기 · 확인 · 불러오기 · 내리기 · 토크나이저 정보) · 다운로드(Hugging Face) · 평가(작업 공간 · GGUF 만들기 · 변환 검증 · 원래 모델 비교 · 개선) · 성능 |
| 레일: 재현 | 남의 결과 확인 | 실험 폴더 확인(받은 실험의 점검 · 다시 내기) · llama.cpp(기록기 · 영수증 · 재현 검증 · 분기) · 검사(교차검증 · 파일 쌍 · 같은 비트) · 검사 결과 |
| 레일: 작업 | 오래 걸리는 작업 | 지금 · 지난 작업, GPU 큐, 작업 로그, 취소 |
| 레일: 설정 | 앱의 설정 | 앱(계산 방식 · 자리 · 슬롯 …) · 장치(장치 확인 · 진단) · 프롬프트 캐시 |
| 명령 창 | 늘 오른쪽 | 모든 출처의 기능 호출(이벤트), 입력 줄, AI 따라가기, AI 세션(에이전트 띄우기 · 연결 안내) |

- 경로가 위계를 그대로 보인다: 실험 › 실험 id › 실행 id › 스텝 k. 다른 레일(모델 · 재현 · 작업 · 설정)에서 실험의 실행으로 가는 고리는 늘 그 실행의
  경로로 연다 — 숨은 "지금 연 실험"이 없다(앱리디자인.md §3 의 정한 것 4).
- 지금의 화면(채팅 · 연구 패널 · 모델 · 모델 평가 · 디버거 · 벤치마크 · 에이전트 · 장치 · 설정)은 새 화면이 그 일을 다 할 때까지 함께 둔다
  (앱리디자인.md §6 결정 3). 기능마다 옮겨 갈 자리는 §6 의 표.

## 5. 명령 창

앱리디자인.md §3 의 정한 것 1 ~ 6 을 화면으로 옮긴다.

- **줄 하나 = 기능 호출 하나.** 이벤트(`/api/events` — 기능목록.md §7)의 시작에 줄이 생기고 끝에 상태가 붙는다. 한 줄에 담는 것: 출처(GUI · 사용자
  CLI · AI 세션 이름 · 파이썬) · 명령 전체(기능 목록의 이름 — 화면 언어로, 예: `run branch` 또는 `실행 분기`) · 상태(실행 중은 강조색, 끝은 상태
  코드와 걸린 시간, 실패는 빨강과 까닭 · 다음 할 일) · 결과 한 줄(토큰 수 · 해시 · 작업 번호) · 기록 링크(그 실행 · 실험 기록을 연다).
- **보이는 것은 기능 호출만** — 계산하거나 기록을 바꾸는 호출(POST). 탭 열기 · 스크롤 · 토큰을 눌러 보는 것은 줄을 남기지 않는다.
- **입력 줄은 GeulPU 명령만** 받는다(운영체제 셸이 아니다). CLI 와 같은 문법 — 이름 셋, 인자, `--json`. 실험 화면에서 친 명령에는 그 실험이
  `--experiment` 로 붙는다(화면에 보인다).
- **AI 따라가기**(기본 꺼짐): 켜면 AI 세션의 실행이 끝날 때 왼쪽이 그 실행으로 간다. 꺼져 있으면 줄의 고리로만 연다 — 사람이 보던 화면이 갑자기
  바뀌지 않는다.
- **복사:** 줄마다 "명령 복사"(CLI 에 그대로 다시 입력할 수 있는 명령 — `--json @…` 대신 요청 본문을 펼쳐 쓴다).
- **단계 E 에서 할 것:** 명령 전체를 보이려면 이벤트에 요청 본문이 있어야 한다 — B3 의 이벤트는 인자를 넣지 않았다. C2 의 명령 기록과 같은
  형식(`params`)을 이벤트에도 더한다(크기 한도와 함께).

## 8. 좁은 화면 · 키보드 · 빈 상태 · 오류

- **좁은 화면:** §2. 토큰 줄은 줄바꿈하며 이어지고, 층 렌즈 표는 가로로 스크롤한다(표만 — 페이지 전체는 가로로 넘치지 않는다).
- **키보드:** `/` 명령 창 입력으로, `Esc` 입력에서 나오기, 토큰 줄에서 `←` `→` 이전 · 다음 스텝, `Enter` 스텝 화면, `b` 고른 후보로 분기, `[` `]`
  명령 창 접기 · 펼치기. 키보드 포커스는 늘 보인다(강조색 테두리 — 지금의 앱과 같다).
- **빈 상태:** 실험이 없으면 "새 실험"과 기본 실험 "대화". 모델이 없으면 실행 화면 맨 위에 "모델 불러오기"(그 자리에서). 명령 창이 비면 "여기에
  기능 호출이 쌓입니다 — GUI 로 한 일, 이 줄에 친 명령, AI 세션의 명령이 모두"와 `GeulPU guide` 안내.
- **오류:** 무엇이 잘못됐는지와 다음에 할 일 — 앱의 까닭(화면 언어로)과 `next`. 실패한 작업은 작업 화면과 그 줄에서 같은 문구.

## 9. 디자인 시스템에 더할 것(안)

지금의 앱(app.css 헤더 주석 · 앱/DESIGN.md)을 그대로 따르고, 새 구성 요소의 규칙만 더한다.

- **명령 창:** 바탕 `--canvas-raise`, 줄은 고정폭 13px · 출처는 태그(4px 모서리 옅은 채움 — 누를 수 없음). 실행 중인 줄만 강조색, 끝난 줄은
  무채색, 실패만 빨강(경고 아이콘과 함께). 줄 사이는 가는 구분선(hairline).
- **토큰 줄:** 토큰은 텍스트 그대로 이어 쓰고(고정폭 아님), 토큰마다 밑줄 막대의 길이가 그 스텝의 마진이다 — 짧을수록 마진이 작은 스텝. 마진이 가장 작은
  스텝에 표시(채움 없는 흰 테두리 + 마진 값). 고른 스텝은 흰 테두리, 프롬프트 토큰은 흐리게. 색으로 확률을 칠하지 않는다(강조색은 움직이는 것에만).
- **층 렌즈 표:** 층마다 한 줄(0 이 위, 마지막 층이 아래) — 1 위 토큰 · 고른 토큰의 순위 · 로그확률. 끝까지 1 위가 되는 첫 층부터 아래를 흰 선으로
  묶는다. 순위는 숫자로(색 표시 없이).
- **해시 칩:** 로짓 해시 앞 8 자를 고정폭으로. 두 실행이 같으면 "같음"(판정의 초록), 처음 다른 스텝에 빨강 대신 흰 표시 + "처음 다른 스텝".
- **출처 막대:** 헤더 아래 한 줄, 12px 무채색 — 모델 · 해시 · 계산 방식 · 버전 · 시드. 계산 방식이 다른 두 실행을 비교하면 막대에 경고 아이콘.

## 10. 사용자가 정할 것

시안(`문서/시안/연구화면.html`)을 보고 정한다. 각 질문의 첫째 안이 이 문서와 시안이 따른 것이다.

1. **레일 다섯:** 실험 · 모델 · 재현 · 작업 · 설정 — 이대로 / 실행을 레일에 따로 / 모델 평가를 레일에 따로.
2. **첫 화면:** 실험 목록 / 마지막으로 연 실험 / 기본 실험 "대화"(채팅처럼 바로 쓰기).
3. **명령 창의 기본:** 열림(380px) / 접힘(폭 40px) — 좁은 화면에서는 어느 쪽이든 아래 창.
4. **토큰 줄의 밑줄 막대:** 마진(1 위와 2 위의 차) / 고른 토큰의 확률 / 엔트로피 — 하나를 기본으로, 나머지는 바꿔 보기.
5. **시안에서 더하거나 뺄 것:** 화면 · 이름 · 자리.

답은 이 절에 적고(누가 무엇을 정했는지와 함께), 이 PR 에 반영한 뒤 병합한다.
