# GL / Native C / Python 데이터 처리 비교

CPU에서 같은 결과를 만드는 간단한 작업을 비교한다. GL이 더 빠르다는 가정 없이 측정한다. **CPU↔NPU 전송, 드라이버 호출, 모델 추론 성능 시험은 아니다.**

## 구현과 조건

- GL 1.4.0, 저장소 `0899bd753e1626e31c3094f5787d0f46ad4f7cc4`. Python 참조 컴파일러가 만든 네이티브 x86-64 PE 실행 파일을 실행한다. 컴파일러가 Python이라는 것은 실행 파일이 Python으로 동작한다는 뜻이 아니다.
- Native C: MSVC 19.51.36257.0, `/O2 /W4`, 기본 x64 명령 집합. 별도 AVX2 지정·LTO·수동 SIMD 없음. 컴파일러의 자동 벡터화 등 최적화는 허용한다.
- CPython 3.13.18: `array('q')`를 직접 순회하는 Python 루프.
- NumPy 2.5.4: `int64` 배열의 네이티브 라이브러리 연산. Python 자체의 반복문 성능과 구분한다.
- AMD Ryzen AI 7 350 Windows PC. 모든 구현은 같은 일반 실행 환경에서 순차 실행한다. GL 실행 파일이 샌드박스에서 DLL 주소 충돌로 시작되지 않아 일반 환경에서 전체 비교를 수행했다.

입력은 `a[i] = i & 65535`, 길이는 1,048,576, 원소는 부호 있는 64비트 정수다. 입력/출력 배열 각각 8 MiB를 미리 할당하고 초기화한다. 값은 오버플로가 없는 범위다. GL/C는 포인터 기반의 연속 배열이며 Python은 같은 원소 폭의 `array('q')`다.

| 작업 | 의미 |
|---|---|
| copy | `b[i] = a[i]` |
| affine_mask | `b[i] = (a[i] * 3 + 7) & 65535` |
| tile_transpose | 각 32×32 타일 내부 전치, 타일 사이 순서는 유지 |
| sum | 입력 전체의 정수 합 |

GL/C/Python은 대응하는 루프를 작성했다. C 함수에는 `noinline`을 적용했으며 결과를 검증해 연산 제거를 방지한다. GL의 루프 함수도 작은 함수 인라인 대상보다 크다. 복사는 수동 원소 루프여서 GL 표준 라이브러리의 별도 최적화 복사 함수를 측정하는 것은 아니다.

NumPy는 copyto, ufunc, 타일 뷰 전치 후 copyto, sum을 쓴다. 산술 변환은 GL/C/Python에서는 한 번 순회하지만 NumPy에서는 곱셈·덧셈·마스크의 세 번 순회다. 임시 출력 할당은 없지만 메모리 접근 횟수는 다르다. 이 비교는 각 구현 방식의 성능이며 언어 이름만의 순수 비용으로 해석하면 안 된다.

## 측정과 검증

작업별 준비·할당·검증·출력·프로세스 시작·컴파일은 타이머 밖이다. GL/C는 QueryPerformanceCounter 기반 밀리초, Python은 perf_counter_ns를 사용한다. 프로세스별 각 작업을 8번 실행해 첫 1번은 예열로 제외한다. 네 구현의 실행 순서를 매 라운드 회전하며 4라운드 실행한다. 결과는 작업/구현별 28개 표본의 중앙값, 최솟값, 최댓값, 라운드별 중앙값이다.

복사·변환·전치 출력은 매 실행 **전체 원소를 예상값과 비교**한다. 합산은 수학적으로 계산한 합 34359214080과 비교한다. 실행기 또한 출력 수·오류 수·합을 검사한다. 실패하면 집계하지 않는다. 원시 출력은 `빌드/language/<backend>-<round>.txt`, 모든 시간 표본과 소스 해시는 `results.json`에 보관한다.

코어 고정·고정 클록·전력 상태 제어는 하지 않았다. 검증은 타이머 밖이지만 메모리/캐시 상태와 CPU 온도에 영향을 줄 수 있다. 각 작업의 실행 순서는 고정이다. 한 크기의 반복 입력이며 캐시가 데워진 시험이므로 대용량 DRAM 대역폭, 작은 FFI 호출, NPU DMA 성능을 일반화할 수 없다. GC·객체 표현·배열 라이브러리·자동 벡터화 등 구현 차이가 함께 포함된다.

## 재현

프로젝트 루트에서:

```powershell
./재기/language/build.ps1
./빌드/npu/dev/mlir-aie/ironenv/Scripts/python.exe -X utf8 ./재기/language/run.py
```

GL 저장소와 기존 Python/NumPy 개발 환경이 필요하다. 다른 작업이 없는 상태에서 실행하는 것이 좋다. 실행기 자체의 `including validation` 시간은 진단용으로, 벤치마크 결과에 사용하지 않는다.
