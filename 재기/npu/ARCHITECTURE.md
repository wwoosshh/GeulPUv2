# 글 언어와 NPU 실행 경계

검토한 글 저장소는 `https://github.com/wwoosshh/geul-lang`, 커밋 `0899bd753e1626e31c3094f5787d0f46ad4f7cc4`다. 작업 폴더 `geul-lang/`에 별도 Git 저장소로 복제했다.

## 확인한 연결 구조

- 글 언어의 기본 코드 생성기는 x86-64 PE/ELF를 직접 만든다. 컴파일러 빌드의 바이트 재현성과 추론 연산의 수치 계약은 다른 보장이다.
- `geul-lang/docs/03-문법-명세.md` 9절은 앞단을 포함하는 프로그램의 조각 모드·연구 옵션을 정의한다. `반실수`는 저장 타입이고 기본 x86 코드 생성기는 처리하지 않는다.
- GeulPU `백엔드/PTX/PTX.gl`은 `self/하강.gl` 앞단을 포함해 별도 PTX 뒷단을 구현한다.
- `엔진/쿠다선언.gl`은 CUDA 드라이버 DLL을 외부 함수로 호출한다. CUDA의 grid/block/launch 호출 형태를 NPU에 그대로 옮길 필요는 없다.

따라서 이번에는 글 문법이나 x86 코드 생성기를 바꾸지 않고 NPU 실행 백엔드의 구조를 변경했다. **현재 실행 및 벤치마크는 Python 참조 엔진에서 수행한다. 글 IR → AIE 컴파일러, 글 엔진용 네이티브 DLL 연결은 아직 구현하지 않았다.**

## 구현한 경계

```text
선형 호출: 활성값, INT8 가중치, 블록 스케일, bias
  ├─ 준비: 가중치 내용/형상 확인 → 불변 WeightPlan → 용량 제한 LRU 캐시
  ├─ 실행: 자리 분해 → 큰 타일 작업 묶음 → 명시적 H2D 동기화 → NPU
  └─ 완료: D2H 동기화 → 벡터화된 부분합 재배치 → 순서 고정 FP32 후처리
```

`planned_linear.py`가 준비와 실행을 분리한다. 패킹한 가중치는 호스트에서 재사용한다. SHA256과 형상을 키로 사용하므로 원본 배열의 제자리 수정도 새 계획을 만들며, 스케일과 bias는 매 실행의 값을 사용한다. 캐시는 768 MiB 상한이며 LRU로 제거한다. 현재 모델 식별자가 없는 참조 엔진 어댑터에서는 매 호출 내용 해시를 계산하므로 비용이 있다. 정식 엔진은 불변 모델 핸들·버전을 발급해 그 비용을 줄일 수 있다.

타일 크기는 8행 × 32출력 × 깊이32로 유지한다. 작업당 타일 수를 128에서 2048로 늘리고 출력 후처리를 최대 4096채널씩 묶는다. 작업 크기는 커널 컴파일 인자로 명시되어 JIT 특수화 대상이 된다. 중간합 호스트 청크는 입력 행 수에 따라 줄이며, 전체 어휘 크기의 부분합을 한꺼번에 만들지 않는다. 결과 재배치는 타일별 Python 반복 대신 배열 변환으로 처리한다.

가중치 캐시는 **NPU 상주 캐시가 아니다**. 매 실행 입력 전송이 있으며 계산·전송은 아직 직렬이다. 네이티브 행렬 MAC과 다중 코어도 아직 사용하지 않는다. 이 제한을 제거하려면 별도 커널 및 장치 메모리 배치 설계가 필요하다.

## 동기화 수정

작업 크기 확장 시험에서 값 불일치를 발견했다. 설치된 XRT Tensor의 `to('npu')`는 이미 장치가 npu인 경우 동기화를 생략하며, 보관한 NumPy 뷰에 대한 쓰기는 이 상태를 변경하지 않는다. 따라서 `exact_kernel.py`와 `tiled_kernel.py`에 입력을 쓴 뒤 명시적인 `_sync_to_device()`를 추가했다. 이 메서드는 현재 고정한 런타임의 내부 API이므로 SDK 교체 시 호환성을 확인해야 한다.

앞선 작은 입력의 통과 결과를 모든 버퍼 크기에 대한 동기화 보장으로 확대할 수 없다. 수정 전 확장 시험은 실패로 처리했고, 수정 후에 경계값과 전체 모델 시험을 다시 수행한다. 비교 기준도 같은 동기화 수정을 적용한 tiled 경로다.

## 글 엔진 통합 시 유지할 경계 — 아직 설계 단계

외부 DLL 연결을 추가할 때는 CUDA의 커널 launch를 노출하기보다 `모델 준비 → 실행 계획 생성 → 입력 제출 → 완료/오류 확인 → 자원 해제` 수명 주기를 노출하는 편이 맞다. 계약 버전·가중치 형식·입력 형상·배치 범위는 계획 생성 시 확인하고, 원시 장치 주소 대신 소유권이 명확한 핸들을 전달해야 한다. 비동기를 추가하면 버퍼 소유권과 완료 이벤트도 API에 포함해야 한다.

현재 계약에서는 깊이32 블록별 부분합과 스케일 적용/FMA 순서를 바꿀 수 없다. 후처리를 NPU 안으로 옮길 경우에도 현재 CPU 기준과 동일한 반올림·비정규수 처리·FMA 의미를 재현하고 이 회귀 시험을 통과해야 한다.

## 실행

```powershell
./재기/npu/run-exact.ps1 -Mode planned-test
./재기/npu/run-exact.ps1 -Mode model -Backend planned -Tokens '9707,1879,13' -Repeats 2 -Output '빌드/npu/results/planned/planned.jsonl'
./재기/npu/run-exact.ps1 -Mode model -Backend tiled -Tokens '9707,1879,13' -Repeats 2 -Output '빌드/npu/results/planned/tiled.jsonl'
```

`compare_optimization.py`로 같은 입력·모델·반복의 모든 선형 해시와 저장된 로짓을 비교한다. 측정 범위는 고정 입력 순전파의 선형 시간 합이며 지속 KV 캐시·자기회귀 생성 TPS가 아니다.
