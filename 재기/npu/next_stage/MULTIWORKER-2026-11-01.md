# GL NPU 다중 작업자 실험 — 2026-11-01

동일한 geul_tile 오브젝트를 독립 NPU 연산 작업자 1·2·4개에서 실행했다. 호스트 총 버퍼 크기는 입력 A 524,288바이트, 입력 B 2,097,152바이트, 출력 C 1,048,576바이트로 같다. 실행 한 번은 2048프레임이다. 메모리 타일이 작업자별 입력을 나누고 결과를 원래 순서로 합친다. 호스트 Python 스레드 수를 늘리는 방식과 구분되는 장치 내부 병렬화다.

작업자 수에 따라 1·2·4개의 aie.core가 생성됨을 IR에서 확인했고 모든 그래프가 실제 장치 컴파일·실행에 성공했다. GL 정수 내적의 소스와 오브젝트는 그대로 사용했다. 실제 장치 이용률과 전력은 계측하지 않았다.

## 장치 왕복

워밍업 후 작업자 순서 1→2→4 및 4→2→1을 교대하며 각각 8회 측정했다. 아래는 중앙값이다. 전체 왕복은 호스트 복사, 업로드 동기화, 런타임 호출과 결과 읽기를 포함한다. 런타임 호출도 제출·대기 비용을 포함하므로 순수 연산 사이클로 해석하지 않는다.

| 작업자 | 전체 왕복 ms | 런타임 호출 ms | 1작업자 대비 왕복 속도 |
|---:|---:|---:|---:|
| 1 | 11.697 | 11.001 | 1.00배 |
| 2 | 7.065 | 6.372 | 1.66배 |
| 4 | 5.320 | 4.634 | 2.20배 |

## 실제 Qwen FFN 선형층

Qwen3-0.6B-Q8_0 첫 층 FFN up projection의 K=1024, N=3072 가중치를 사용했다. JoinedPrefill의 제출 배치와 순차 네이티브 CPU 후처리는 동일하다. 각 조건 4회 교대 측정 중앙값이다. 독립 CPU 기준과 출력 uint32 배열을 비교했다.

| 입력 행 | 1작업자 ms | 2작업자 ms | 4작업자 ms | 1→4 전체 속도 |
|---:|---:|---:|---:|---:|
| 16 | 142.7 | 130.3 | 118.9 | 1.20배 |
| 64 | 546.1 | 435.4 | 381.2 | 1.43배 |
| 256 | 3101.9 | 2270.9 | 2010.1 | 1.54배 |

정확성 비교는 장치 입력 크기 1·7·128·2047·2048의 세 작업자 구성, 극단 int8 입력, 왕복 측정의 반복 출력, 실제 선형층 워밍업 및 측정 출력을 합쳐 84회 통과했다. 전체 시간의 개선은 후처리 시간의 변동도 포함한다. 256행에서 1→4의 장치 실행·전송 중앙값은 약 1.261→0.531초, CPU 후처리는 1.591→1.288초였다. CPU 후처리는 이번 변경의 대상이 아니며 측정값 변동을 병렬화의 효과로 단정하지 않는다.

## 모델 연결

고정 난수 16토큰 입력에서 CPU/1작업자/4작업자/4작업자/1작업자/CPU 순서로 측정했다. 각 실행 전에 KV를 초기화했다. 가중치 계획과 장치 실행은 워밍업했다. 출력층의 1행 연산과 이어지는 한 토큰 생성은 모든 조건에서 CPU를 사용했다. 타이밍은 모델 로딩을 제외한 호스트 경과 시간이다.

| 경로 | 첫 출력 초 | 다음 출력 초 |
|---|---:|---:|
| cpu | 9.121 | 2.295 |
| 1 | 27.249 | 2.707 |
| 4 | 17.577 | 2.356 |

6회 실행의 첫 출력 및 다음 출력, 총 12개 전체 로짓 SHA-256이 기존 CPU 기준과 일치했다. 각 경로 2표본이므로 p95나 작은 차이의 통계적 유의성을 판단할 수 없다. 이 결과는 Qwen 전체를 NPU에 상주시킨 실행의 성능을 의미하지 않는다.

## 적용 판단

4작업자 구성을 연구용 선택 경로로 추가했다. 동일한 호스트 전송량에서도 실제 장치 왕복 시간이 줄었다. CPU 후처리와 반복 가중치 전송은 남아 있다. 다음 단계는 출력 열별 CPU 후처리의 병렬화·중첩과, 장치 내부 가중치 재사용을 독립적으로 검증하는 것이다. 4작업자 결과로 전체 NPU 활용률이나 가능한 최대 성능을 추정하지 않는다.

재현은 viability.ps1 bench_multi, viability.ps1 bench_multi_model, summarize_multi.py 순서다. 측정 파일은 실행 시 덮어쓰므로 이전 결과를 보관한 뒤 재실행한다.
