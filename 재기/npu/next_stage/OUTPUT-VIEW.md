# 입력 연속 준비 유지·출력 중간 복사만 제거

OutputViewDevice는 RetainedDevice의 실행 핸들 재사용과 연속 입력 패딩·패킹을 그대로 유지한다. 다운로드 후 임시 INT32 배열을 copy하던 한 지점만 뷰로 바꿨다. 그 뷰는 다음 NPU 실행 전에 소유권이 독립적인 출력 청크로 재배치되므로 CPU 후처리와 장치 버퍼 재사용이 충돌하지 않는다. 최종 출력 재배치는 여전히 남아 있으므로 완전한 zero-copy 경로는 아니다.

기존 벤치마크를 재실행하지 않고 새 경로만 워밍업 후 3회 측정했다. Qwen3-0.6B-Q8_0 FFN up M=256 K=1024 N=3072, seed=619, NPU 작업자 4개, 4,096프레임, CPU 후처리 4스레드 중첩이다.

| 경로 | 전체 중앙값 ms | 최소–최대 ms | 입력 패킹 ms | 출력 중간 복사·뷰 ms | 출력 재배치 ms | 호출 준비 잔여 ms |
|---|---:|---:|---:|---:|---:|---:|
| handle (이전) | 500.14 | 473.63–564.82 | 55.86 | 21.33 | 49.40 | 8.92 |
| handle_lean (이전) | 543.30 | 447.00–556.00 | 89.61 | 0.82 | 55.26 | 9.23 |
| 출력 뷰만 적용 (신규) | 403.91 | 402.14–411.50 | 38.95 | 0.57 | 39.26 | 5.79 |

이전 수치는 다른 세션의 기록이다. 따라서 전체 시간 차이를 출력 copy 제거만의 인과적 효과라고 주장하지 않는다. 이번 표본은 3개이며 전력·온도·클록을 통제한 비교가 아니다. 단계별 계측의 중첩과 런타임 실행 대기의 의미는 TRANSFER-DIAGNOSTIC.md와 같다.

## 정확성·버퍼 안전성

CPU 기준 비트 비교 16회와 16토큰 Qwen 모델의 첫·다음 출력 전체 로짓 해시 2개가 일치했다. 홀수 행·열 및 깊이 꼬리에서 최초 결과를 보존한 채 입력 부호를 바꿔 다시 실행하고, 이전 결과가 변하지 않는지 확인했다. 원래 입력으로 재실행한 결과도 비교했다. 명시적 핸들 해제 후 재로딩도 통과했고 성능 측정 구간의 추가 핸들 로딩은 모두 0회였다.

## 판단

이 경로는 입력 연속 준비를 생략했던 handle_lean의 변경을 포함하지 않는다. 입력 패킹을 유지하고 출력 중간 복사만 없애는 후보로 보존한다. 기존 전역 기본값이나 모델 라우팅은 자동 교체하지 않았다. 전체 모델 실행은 정확성 검증이며 모델 전체의 가속률을 계측한 것은 아니다.

후속 적용 후보는 자동 용량 선택기의 용량별 장치로 OutputViewDevice를 사용하는 것이다. 통합할 때는 2,048·4,096·8,192 각 용량의 핸들을 독립적으로 보유하고, 용량 전환과 출력 수명을 검증해야 한다. 이미 완료한 고정 용량 성능 시험은 다시 실행할 필요가 없다.
