# 글 구조 검토 후 NPU 실행 계획 재설계 및 벤치마크

글 저장소 `0899bd753e1626e31c3094f5787d0f46ad4f7cc4`와 GeulPU의 PTX 뒷단·CUDA 외부 선언을 확인했다. 언어 문법/x86 코드 생성기를 변경하는 대신 **NPU 실험 백엔드의 준비·실행·완료 경계를 분리**했다. 글 IR→AIE 변환이나 글 엔진용 네이티브 DLL은 아직 구현하지 않았다. 설계 근거와 연결 계획은 [ARCHITECTURE.md](../ARCHITECTURE.md)에 있다.

## 구현한 변경

1. 불변 `WeightPlan`으로 타일 가중치를 준비하고 호스트 LRU 캐시에 재사용한다. 가중치 내용 해시와 형상으로 식별하므로 원본 제자리 수정에도 이전 패킹을 쓰지 않는다. 상한은 768 MiB, 모델의 실제 캐시 사용량은 595984384바이트(약 568.4 MiB)였다.
2. 작업당 타일 수를 128→2048로 늘리고 후처리 청크를 최대 4096 출력 채널로 확장했다. 입력 행 수에 따라 청크를 줄인다.
3. 타일별 Python 결과 복사 반복을 배열 배치 변환으로 바꿨다.
4. 호스트 입력 버퍼를 쓴 후 **명시적으로 H2D 동기화**한다. 원래 dot/tiled 경로에도 적용했다.

동기화 수정은 정확성 수정이다. 작업 크기 확장 시험에서 불일치를 발견했고, 설치된 런타임은 텐서가 이미 NPU에 있으면 `to('npu')`에서 동기화를 생략한다는 것을 확인했다. NumPy 뷰 쓰기 후 명시적 동기화를 추가한 뒤 실패했던 시험을 통과했다. 앞선 작은 입력 시험의 통과는 모든 버퍼 크기의 동기화 보장이 아니었다. 수정 전 실패 결과로 모델 성능을 보고하지 않았으며, 아래 기준 경로에도 같은 수정을 적용했다.

## 정확도

- 계획 경로: 부분 타일·8행 초과·4096채널 경계, 자리 1/2, 지수 −98/0/100 조합 24건과 가중치 제자리 수정 4건을 실제 NPU에서 기본 정수 계약과 대조해 통과했다. 캐시 상한·LRU 퇴출도 통과했다.
- 기존 tiled 경로도 입력 교체·부분 타일·극값 회귀 시험을 통과했다.
- Qwen3-0.6B Q8_0, 입력 `[9707,1879,13]` (`Hello world.`), 각 경로 2회.
- 경로당 선형 호출 282회 / 출력 2,976,000개가 CPU 참조와 비트 일치했다. 블록 잔차·최종 로짓·반복 결과도 일치했다.
- 두 경로 사이 모든 대응 선형 해시가 같으며 저장된 로짓 배열도 uint32로 직접 대조했다.
- 최종 로짓 SHA256: `7086db93d0958747cb113f2a88c8586b9e408230cffd03746515e41bbbdf0e52`.

## 성능

| 측정 | 동기화 수정 tiled | planned |
|---|---:|---:|
| 첫 실행 선형 시간 합 | 24.04초 | 20.57초 |
| 둘째 실행 선형 시간 합 | 15.02초 | 11.07초 |
| 둘째 실행 CPU 대조 시간 합 | 8.01초 | 11.39초 |
| NPU 호출 수, 모델 2회 합계 | 9094 | 654 |
| 패킹 계획 캐시 적중/미적중 | 없음 | 141 / 141 |

이번 측정의 예열 후 속도 비율은 **1.36배**, 시간 감소는 **26.3%**다. 작업 제출 수는 약 **92.8% 감소**했다. 첫 반복에 141개 계획을 만들고 둘째 반복에 전부 재사용했다. 캐시는 호스트 메모리에 있으며 가중치를 NPU에 상주시킨 것은 아니다.

| 예열 후 구간 | tiled | planned |
|---|---:|---:|
| 패킹·해시·결과 재배치 등 | 1.58초 | 0.94초 |
| NPU 호출·전송·동기화 | 8.44초 | 4.00초 |
| CPU FP32 후처리 | 4.81초 | 5.95초 |

호출 수 감소가 같은 비율의 속도 개선으로 이어지지는 않았다. 더 큰 버퍼의 전송과 계산은 남아 있고, 더 큰 후처리 청크에서 CPU 비용이 증가했다. 세부 합과 전체 합 차이는 검증·bias 등 세부 타이머 밖의 비용이다.

**CPU보다 빨라졌다고 결론내리지 않는다.** 두 실행의 CPU 대조 시간 자체가 약 8.01초와 11.39초로 달랐으며, 실행 순서·메모리 사용·캐시 상태·외부 부하를 통제하지 않았다. 각 경로 둘째 실행 1회의 관측값으로 신뢰구간은 없다. 선형 시간 합계이고 전체 추론 TPS나 전력 측정이 아니다. 긴 문맥·KV 캐시·자기회귀 생성은 미검증이다.

현재 핵심 병목은 CPU의 계약 후처리다. 이를 장치 안으로 옮기려면 GeulPU의 FP32 반올림·비정규수 처리·블록 순서 FMA를 정확하게 구현해야 한다. 네이티브 행렬 MAC·다중 코어·비동기 중첩은 아직 남은 작업이다.
